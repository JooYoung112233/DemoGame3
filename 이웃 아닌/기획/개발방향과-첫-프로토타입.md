# demo5 개발 방향 — 2026-09-21 확정

> **최신 정정 — 아래 쿼터뷰 관련 항목보다 우선.** 사용자는 쿼터뷰라는 표현을 정정했으며, 기존 승인 시안 이미지를 그대로 사용할 것을 요청했다. 시각 기준은 `아트/승인시안/폐상가-보드게임-원본.png` 하나다. 정면에서 약간 내려다보는 원근 구도, 단순한 실루엣 종이 말과 거친 보드게임 표현을 유지한다. 마름모 바닥·사실적인 정비소와 인물은 미채택. 현재 쿼터뷰 코드는 중간 구현이며 교체 대상이다. 최소 모션 및 모험가 2명 → 정착지 선택 흐름은 유지한다. 실행 파일 빌드는 사용자 요청으로 생략한다.

탐험과 파밍 중심의 스쿼드 생존 게임. 밤에 장소를 탐색하며 보급품을 회수하고, 감염자와 마주치면 말을 움직이는 작은 턴제 보드 전투를 진행한다. 보드·디오라마 표현을 사용하며, 복잡한 캐릭터 이동·전투 스프라이트 대신 토큰 이동과 간결한 피드백을 사용한다. LIVE49 자산은 공유하지 않는다.

장기 흐름: 거점 → 대원과 장비 선택 → 야간 탐색 → 파밍·조우·철수 판단 → 귀환 정산 → 거점 보강. 전투 목적은 회수·탈출·버티기로 다양화한다. 호텔 100층 하강 구조는 사용하지 않는다.

## 최신 확정 — 시작 흐름·쿼터뷰·최소 모션

2026-09-21 사용자 지시. 아래 기준을 앞선 표현과 후속 작업 우선순위보다 우선한다.

- 새 게임은 모험가 2명 선택 → 정착지 선택 → 선택한 정착지에서 시작한다. 현재 전투 시제품의 고정 대원 두 명은 임시 구성이며 최종 시작 흐름이 아니다.
- 정착지 생활과 외부 탐색을 오가는 생존 흐름을 중심으로 한다. 사용자가 제시한 This War of Mine은 이 생활·원정 흐름의 참고이며, 화면은 승인된 시안처럼 쿼터뷰 보드/디오라마 느낌으로 구성한다.
- 정착지와 탐색 장소 모두 사선 위에서 내려다보는 구도를 기준으로 한다. 현재 정면 4×4 UI 보드는 규칙 확인용이며 최종 화면 방향으로 확정한 것이 아니다. 논리적인 칸 좌표와 화면상의 쿼터뷰 배치를 분리한다.
- 걷기·달리기·무기 휘두르기 등 캐릭터 프레임 애니메이션은 제작하지 않는다. 대원은 고정된 그림/말을 사용한다. 이동은 위치 변경을 기본으로 하고 필요할 때만 짧은 보간으로 출발·도착을 읽게 한다.
- 공격은 공격자/대상 표시 → 짧은 타격 효과와 효과음 → 명중/빗나감·피해 표시로 전달한다. 큰 공격 동작과 과도한 카메라 흔들림은 사용하지 않는다. 효과음은 아직 미구현이다.
- 전투의 긴장감은 위치 선택, 행동력, 명중 확률, 소음, 보급품, 철수 판단에서 만든다. 애니메이션 제작을 선행 조건으로 두지 않는다.
- 엄폐는 드럼통·박스 등 일부 사물 옆에서 사격에 덜 맞는 단순 효과로 유지한다.

다음 구현 단위는 모험가 선택 → 정착지 선택 → 정착지 화면 → 첫 원정 → 귀환 시 보급품 반영의 한 순환이다. 모험가 후보의 수·특성, 정착지 후보의 수·특성, 하루의 시간 구분은 아직 미확정이다. 정착지 시설과 역할 차이는 이 흐름을 연결한 뒤 구체화한다.

## 첫 구현 범위

- 씬: Assets/Scenes/NightExpedition.unity, 기준 화면 1920×1080.
- 폐상가 4×4 보드, 대원 2명, 감염자 2명, 선반 2곳, 출구 2칸.
- 대원별 2 AP. 이동/탐색/근접/미끼/방어/철수 1 AP, 사격 2 AP.
- 근접 피해 2·소음 1, 사격 피해 3·소음 3·탄약 1. 초기 탄약 4.
- 선반 인접 탐색 시 보급품 1·소음 1. 재탐색 불가. 선반은 이동과 사격을 막는다.
- 미끼는 3칸 이내 빈 칸, 소음 1. 마지막 미끼가 한 적 턴 동안 모든 감염자의 목표를 대체한다.
- 적 턴에 인접 대원 공격(피해 2), 아니면 장애물을 우회해 1칸 이동. 방어는 피해를 1 줄인다.
- 빛 100에서 적 턴마다 15 소모. 빛 0이면 적 이동 2칸. 공격과 이동은 같은 턴에 함께 하지 않는다.
- 소음 6 이상이면 북동쪽 입구가 비었을 때 증원, 소음 6 차감. 최대 2회. 입구 점유 시 다음 턴까지 보류.
- 두 보급품과 두 대원 귀환 시 성공. 조기 철수는 부분 귀환. 전원 전투 불능은 실패와 보급품 손실.
- 적 다음 행동, 소음, 빛, 탄약, 체력, AP, 행동 로그 표시.
- 전투 명중 확률 적용(사용자 추가 확정): 근접 85%, 사격 90%에서 1칸을 초과하는 거리마다 -10%p. 드럼통·박스 인접 대상은 사격 명중률 -20%p. 빛 0에서 아군 명중 -15%p. 최종 확률 20~95%. 감염자 근접 명중 80%. 엄폐는 근접 공격에 적용되지 않는다.
- 명중률을 대상 칸과 적 행동 예고에 표시한다. 빗나가도 AP·탄약·소음 소모. 난수는 테스트에서 주입하여 명중/빗나감과 자원 처리를 각각 검증한다.
- 엄폐는 사용자 요청대로 단순한 사물 인접 효과로 확정. 드럼통·박스 옆에서 사격에 덜 맞으며, 방향별 엄폐·엄폐 자세·측면 공격은 범위에서 제외한다. 감염자는 현재 근접만 사용하므로 대원 엄폐의 방어 효과는 향후 원거리 적 추가 시 작동한다. 공포·부상 지속·장비·다중 장소·거점 저장·음악은 후속 작업.

## 실행 / 수정

Unity 6.6에서 NightExpedition 씬을 열고 Play. 대원 선택 → 아래 행동 선택 → 보드 대상 클릭. 방어와 철수는 버튼을 누르면 즉시 실행된다. 적 턴 진행은 대원 AP가 남아도 가능하다.

- Assets/Scripts/NightRun/RunState.cs: Unity에 의존하지 않는 턴·전투 규칙.
- Assets/Scripts/NightRun/NightRunView.cs: uGUI 조작과 화면. 한글은 실행 OS의 맑은 고딕/Apple SD Gothic Neo/Noto Sans CJK KR 사용. 배포 전 재배포 가능한 한글 폰트를 프로젝트에 포함해야 한다.
- Assets/Prefabs/NightRun: Expedition, Panel, ActionButton, BoardTile, SurvivorToken, PropToken. 공통 프리팹을 나누고 화면은 런타임에 조립한다. 현재 배치·색·텍스트는 View 코드가 지정하므로 프리팹만으로 모든 화면을 수정하는 단계는 아니다.
- AgentScripts/BuildPrototype.cs: Unity Editor API로 씬과 프리팹 생성. 재실행 시 해당 프로토타입 자산을 재생성하므로 수동 편집 후에는 주의.
- AgentScripts/VerifyPrototype.cs: 규칙 경계·완주·후퇴·실패, 실제 uGUI Button 이벤트 완주 검사.
