# UI 잔여 수정과 튜토리얼 후속 검수

사용자 요청: 남은 작업을 이어서 진행하되 새 작업 폴더/워크트리를 만들지 않는다. 작업 위치는 통합된 `E:/personalProject/Demo3/demo5`다.

## 이번 수정

- UI-01: 발견물의 가방 포화 안내를 114 높이의 두 줄 영역에 표시한다. 다른 대원을 고르라는 해결 방법이 잘리지 않는다.
- UI-02: 출발 확인의 목적지·인원·편도 시간을 위에, 실제 출발 시간 비용을 고정 하단에 표시한다. 대원별 체력/가방/휴대품만 스크롤한다. 빈 가방은 명시하고, 긴 목록은 어두운 레일과 금색 위/아래 버튼으로 이동한다. 열 때 목록 맨 위로 돌아온다.
- UI-03: 전투 아이템 상세 그림의 검은 tint를 흰색으로 바꾼다. 원화 색을 유지하는 변경이며 전투 규칙/배치는 수정하지 않는다.
- UI-04: 메뉴·저장·설정의 기본 딤을 공통 .97로 맞춘다. 출발 확인 등 하위 확인창의 딤은 별도 유형으로 유지한다.
- UI-05: 시설 초기 안내를 `시설 위에 마우스 · Alt: 모든 시설 강조`로 맞춘다.
- UI-06: 휴식 방법/대원 목록과 선택한 대원의 상세를 인접한 두 열로 묶는다. 소요 시간·회복 결과·시간 진행 안내를 상세 카드에 모은다. 대원 목록은 6명과 마지막 항목 클릭을 고려한 스크롤을 제공한다.
- UI-07: 현장 가방의 동료 전달 영역을 늘려 6명 원정대의 전달 대상 5명이 모두 보인다. 이름 탭과 이름 클릭 즉시 전달 방식은 유지한다. 사용 버튼과 수량 영역을 구분한다.
- 출발 준비 제목이 높이보다 커서 사라지던 문제, 체크리스트의 너무 좁은 줄 간격도 보완한다.
- 귀환 보고/시간표의 숨은 스크롤에 어두운 레일과 금색 위·아래 버튼을 추가한다. 귀환 대원은 3장, 작업 목록은 3행, 귀환 물자는 5행 단위로 표시해 목록 끝에서 이름이 잘린 행이 남지 않도록 한다. 내용이 짧으면 표시를 숨긴다.
- 귀환의 ‘휴대품 모두 보관’은 실제 보관 가능한 물품이 있을 때만 활성화한다. 창고가 가득 찼으면 가방 유지와 ‘가방별 정리’를 안내한다. 보관량/용량 규칙은 유지한다.

## 튜토리얼 예외 처리

- 이미 예약된 휴식을 다시 열면 휴식 중단을 유도하지 않고 돌아가서 시간 진행하도록 안내한다.
- 모든 대원이 배정되어 있으면 새 제작창을 반복해서 열지 않고 기존 작업 완료까지 시간 진행으로 연결한다.
- 가방이 모두 찼으면 돌아가기 → 두고 나가기로 이어진다. 다른 대원이 담을 수 있으면 그 대원 이름을 특정해 안내한다.
- 개인 가방의 물건을 눌렀다고 튜토리얼이 현장에 버리는 버튼을 강조하지 않는다.
- 관리표를 읽은 뒤 돌아가기 안내를 연결한다.
- 창고/개인 가방의 대원 페이지 이동은 선택된 사람 대신 현재 보이는 페이지를 기준으로 한다.
- 완성한 지렛대를 챙길 때 선택 대원의 가방이 찼다면 빈칸 있는 대원을 찾는다. 전원 가방이 찼다면 창고로 물건 전체 수량을 옮겨 한 칸을 비운 뒤 도구를 챙긴다. 선택만 무한 반복하던 문제를 실제 연속 플레이에서 찾아 수정했다.
- 전원 가방 포화 시 일부 수량만 보관해서는 빈칸이 생기지 않는 점을 반영한다. 전체 묶음을 보관할 수 있는 물품/대원을 찾고, 그런 물품도 없으면 사용·제작으로 공간을 확보하도록 안내한다.
- 안내판 폭과 헤더 위치를 조정해 시설 개선 버튼의 종이 영역을 침범하지 않는다.

## 검증 방법과 구분

`VerifyRemainingUI`와 `VerifyTutorialClarity`를 Unity Play 모드에서 실행한다. 버튼은 EventSystem raycast와 pointer click으로 누르며, 편의상 fixture를 불러오는 준비 단계와 실제 사용자 조작 검증을 구분한다. 다인원/가방 포화/저장 실패는 임시 검수 데이터다. 실제 시작 대원이 6명이라는 의미가 아니다.

현재 통과:

- 휴식 예약/취소와 6명 목록의 마지막 대원 선택.
- 출발 확인 2명 빈 가방, 6명 휴대품 목록의 최하단, 고정 이동 비용, 돌아가기.
- 발견물 가방 포화의 두 줄 안내, 대원 변경과 실제 물품 회수.
- 6명 가방 탭, 마지막 동료에게 이름 클릭 전달, 선택 대원의 상태 갱신.
- 메뉴/설정/저장 진입·복귀와 기본 딤.
- 예약된 휴식, 모든 대원 작업 중, 전원 가방 포화, 대체 운반자, 관리표 닫기 안내.
- 1280×720 / 1920×1200 / 2560×1080의 휴식·안내판, 출발 확인, 6명 가방 실제 클릭과 텍스트 높이.
- 손상/미지원 버전 저장의 설명과 불러오기 차단, 확인 도중 변경된 파일 재검사, 잘못된 저장 덮어쓰기 차단, 6명 가방 디스크 복원.
- 새 게임의 시작 2명/숨긴 후보 선택 차단, 도입 중 디스크 저장 복원, 첫 수색과 실제 회수품을 사용한 창고·작업대 복구를 재검수했다.
- 동일한 진행에서 밧줄·못·지렛대까지 제작했다. 도구 휴대 시 가방 포화로 안내가 반복되는 문제를 수정한 뒤, 보존한 진행 상태에서 다시 불러와 10번의 안내 클릭으로 도구 휴대 및 두 번째 원정 준비까지 통과했다. 후속 전략 탐험 자체를 안내만으로 완료했다는 뜻은 아니다.
- 최종 프리팹에서 3개 화면비 검사를 다시 통과했다. 안내판이 개선 버튼을 덮지 않고, 전달 대상에 불필요하게 남던 예전 스크롤 레일도 제거되었다.
- 6명 귀환의 마지막 대원까지 화살표 클릭, 창고 빈자리 2개만 부분 보관, 포화 후 비활성 버튼/안내, 재열기 시 물품 복제 없음, 가방별 정리 이동.
- 14종 휴대품 귀환의 마지막 수량 열, 2명 빈 가방 귀환의 빈 상태와 불필요한 스크롤 숨김.
- 동시 휴식 예약 6개와 완료 기록 목록의 마지막 행, 다음 완료 진행 시 1개만 완료되고 나머지 5개 유지.
- 6명 상태의 정착 기록 탭, 밤 사건 선택/결과, 실제 30분 경과, 해결된 사건 기록에서 재실행 차단.
- 양쪽 가방 포화에서 실제 ‘최대’ 클릭으로 전체 묶음을 보관하고 지렛대 휴대. 창고가 1개만 더 받을 수 있어 묶음을 비우지 못하는 상태에서는 반복 없이 공간 확보 안내.
- 전투의 기존 아이템 창을 열어 원화 tint가 흰색이고 원래 색으로 보이는 것 확인. 전투 HUD 전체 수정 완료를 의미하지 않는다.

검수 파일은 기존 `Temp/UIAuditSlots` 및 `Temp/TutorialClaritySave`만 사용한다. 플레이어 저장 슬롯과 설정은 변경하지 않는다. 캡처는 기존 `Assets/Screenshots/UIAudit`의 61번 이후와 `Assets/Screenshots/TutorialClarity`에 저장한다.

## 유지할 범위

전투 HUD 글자 계층(UI-08), 크리쳐 화풍 재제작, 후속 탐험 전략 학습, 장기 물자 균형과 다양한 사건/인물별 퀘스트는 이번 UI 수정 완료와 구분한다. 동시에 진행되는 탐험 작업의 규칙과 신규 기능을 임의 교체하지 않는다. 새로운 실행 파일 빌드는 만들지 않는다.

프리팹 재적용은 기존 공통 프레임 빌더 이후 `PolishRemainingUI.Run`, 그다음 `BuildDeferredUI.Run`(발견물 3버튼 하단 · 모두 담기, 전투 결과 사용 물품 목록 높이 210)이다. UI 배치는 에디터에서 저장하며 런타임에서 임의로 다시 구성하지 않는다.
