최신 저장 버전은 6이다. 옆방 연결·거주 준비 상태와 남은 공사를 보존한다. [거주 공간 1차](거주공간-해금-1차-구현.md). 아래 버전 표기는 과거 작업 기록이다.

최신 저장 버전은 5다. 기존 침대/작업대 기록을 보존하고 조리대 개선과 공사 예약을 저장한다. [시설 개선 1차](시설개선-1차-구현.md). 아래 버전 기록은 과거 작업 시점이다.

최신 저장 버전은 4다. 방문 날짜·종료 여부·교환으로 바뀐 재고를 추가하고 v1~v3 기록을 이관한다. 아래는 각 작업 당시의 기록이다. 자세한 내용은 [방문자와 물물교환](방문자와-물물교환-구현.md)을 따른다.

# 이웃 아닌 — 공통 메뉴·설정·저장/불러오기

최신 후속: 저장 버전 3에 정수·붕대 물자를 포함했다. 버전 1·2 파일 이관과 실제 재시작을 검증했다. [현재 상태](정수와-붕대치료-구현.md). 아래 버전 2 설명은 이전 단계 기록이다.

2026-09-23 구현 및 Unity Editor 검증. 비전투 완성 작업의 첫 시스템 묶음이다. 조리 생산·정착지 성장·신규 탐험 장소까지 완료한 것은 아니다.

후속 갱신: 같은 날 [실제 조리와 음식 사용](식량-조리와사용-구현.md)을 연결했다. 현재 저장 버전은 2이며 조리 예약을 포함한다. 버전 1은 검증 후 신규 식량 재고 0·빈 조리 예약으로 이관한다. 귀환 전 저장의 빈 기록 직렬화도 처리했다. 아래는 최초 메뉴 구현 기록이다.

## 사용

- 시작 화면 제목과 Unity 제품명을 `이웃 아닌`으로 반영했다. `demo5` 폴더와 기존 씬 이름은 유지한다.
- 정착지 상단 `메뉴` 또는 다른 창이 닫힌 상태에서 Esc → 생활 저장 / 생활 불러오기 / 설정 / 시작 화면으로.
- 저장 슬롯은 3개다. 빈 슬롯은 바로 저장하고, 기존 슬롯은 덮어쓰기 확인을 거친다. 불러오기와 시작 화면 복귀는 저장하지 않은 진행의 소실을 안내하고 확인한다.
- 시작 화면 `계속하기`는 정상적으로 읽을 수 있는 최신 저장을 연다. 저장이 없거나 모두 손상된 경우 비활성이다. 새 게임은 기존 슬롯을 지우지 않는다.
- 설정은 시작 화면과 정착지에서 같은 프리팹과 저장 키를 사용한다. 전체 음량 미리보기, 취소 시 복원, 전체 화면, 적용과 재실행 유지를 지원한다. 음악/효과음 개별 채널, 키 재배치, 그래픽 품질 선택은 아직 없다.

## 저장 범위와 안전한 시점

첫 저장 규격은 **정착지에서만 저장**한다. 진행 중인 휴식·제작이 있어도 저장할 수 있다. 원정·전투·이동 중 저장은 지원하지 않으며, 정착지 메뉴 진입 및 데이터 캡처에서 차단한다. 자동 저장과 원정 중 설정 메뉴는 후속 범위다.

보존하는 내용:

- 대원 콘텐츠 ID, 이름과 능력치, 체력, 개인 가방. 참조 복원에는 표시 이름을 키로 사용하지 않는다.
- 정착지 종류, 날짜와 시간, 공용 보급품·탄약 및 제작 물자.
- 휴식과 제작의 담당자, 남은 시간, 수량, 예약 재료. 침대 수리·작업대 개선 효과.
- 폐상가의 확인한 사물, 복도 방문 여부, 수색 진척과 완료 여부, 도구로 개방한 상태, 이미 결정된 발견물과 현장 잔여 수량.
- 최근 귀환 비교 기록과 활동 기록 최대 100개. 귀환 기록 재열람은 재료를 지급하지 않는다.

귀환한 상태만 저장하므로 당시 원정의 턴·소음·조우 대기 상태는 다음 출발 시 기존 규칙대로 초기화한다. 수색 대상 ID는 현재 폐상가의 상자·탁자·오락기·문에 대응하며, 새 장소를 추가할 때 ID와 저장 규격을 함께 확장해야 한다.

파일은 `Application.persistentDataPath/Saves/slot-1.json`부터 `slot-3.json`까지 사용한다. 임시 파일 작성·디스크 반영 후 기존 파일을 교체하며 이전 파일은 `.bak`으로 보존한다. 백업 복구 UI는 아직 없다. 체크섬은 우발적인 파일 손상 확인용이다.

불러오기 전에 저장 버전, 데이터 구조, 알려진 콘텐츠 ID, 가방 용량, 공용 물자 총량, 중복 담당자, 예약 재료, 수색 완료 상태 등을 검증한다. 손상되거나 지원하지 않는 버전은 이유를 표시하고 불러오지 않는다. 현재 규격은 버전 1이며 이전 게임 저장 규격은 존재하지 않는다.

Unity 6000.6.0f1, 컴파일 오류 없음. 실행 파일 빌드는 하지 않았다.

- `VerifySettlement.Flow`: 새 게임 대원/정착지 선택과 기존 HUD·시설 연결 통과.
- `VerifyTitleMenu.PlayFlow`: 실제 버튼 레이캐스트, 설정 미리보기/취소, 슬롯 선택 전 동작 제한, 종료 확인/취소 통과.
- `VerifySystemMenus.RoundTrip`: UI 저장·덮어쓰기·취소·불러오기·계속하기 통과. 가방·공용 물자·진행 중 휴식/제작·부분/완료 수색·귀환 기록이 저장 전과 동일하게 복원됨을 비교했다. 복원 뒤 작업을 완료해 재료 차감과 생산이 한 번만 발생함을 확인했다. 원정 중 저장, 손상 파일, 지원하지 않는 버전과 잘못된 물자 총량을 거절했다.
- `VerifySystemMenus.Settings`: 설정 적용/취소/재열람/시작 화면 공유, 새 게임 시 상태 초기화와 기존 저장 유지 통과. 검증 뒤 기존 사용자 설정을 복원한다.
- `VerifySystemMenus.Restart`: Play 모드 종료 후 새 실행 세션에서도 디스크 저장과 진행 중 작업·수색·귀환 기록 복원 통과. 전체 Editor 프로세스 재시작이나 배포 빌드 검증은 별도로 수행하지 않았다.
- `VerifySystemMenus.EscapeFlow`: 실제 Input System 키 이벤트로 메뉴·설정·확인창을 한 단계씩 닫는 동작, 다른 작업창을 닫은 Esc가 메뉴를 다시 열지 않는 동작 통과.

테스트는 `Temp/SystemMenuVerification`을 사용한다. 실제 플레이어 슬롯과 분리되어 있으며, `save-slots-corrupt.png`의 기록 2는 손상 안내 검수를 위해 의도적으로 만든 데이터다. 최종 정상/빈 슬롯 캡처 전 이 테스트 파일을 제거하고, 테스트 경로 지정도 검증 종료 후 해제한다.

검수 도중 강제 `Camera.Render()`가 캡처 해상도와 Game View 해상도의 차이로 URP RenderPass 오류를 남기는 문제를 확인했다. 이번 검수에 사용하는 `VerifySettlement`와 `VerifySystemMenus`에서 강제 렌더링을 제거하고, 새 캔버스 활성화 뒤 정상 갱신을 기다리도록 바꿨다. 이후 같은 기능 검증과 새 오류 로그를 재확인했다.
