# 보관실 해금·탐험 1차 — 2026-09-23

복도 철문 → 보관실 → 복도 → 오락실 귀환을 연결했다. 다른 닫힌 문은 기존 상태다. 보관실에는 선반·자재 수색 두 곳이 있고 총 수색 대상은7곳이다.

## 플레이 규칙

- 최초 진입: 살아 있는 동행 대원 중 간이 지렛대를 가방에 가진 사람이 필요하다. 거점 창고의 도구는 인정하지 않는다.
- 잠금 해제1턴 + 이동1턴 =20분, 소음+2. 도구 비소모. 확인창에 담당자·시간·소음을 표시한다. 이 값들은 Inspector의 임시 설정이다.
- 취소/도구 부족은 시간·해금 상태를 바꾸지 않는다. 확정 직전에도 도구를 다시 확인한다. 중복 확정은 한 번만 처리한다.
- 개방 이후 이동은1턴/10분이며 도구가 필요 없다. 문 개방·방 방문·수색 상태는 귀환·저장·재방문에도 유지한다.
- 보관실에서의 후퇴는 복도로, 복도에서의 후퇴는 오락실로 연결한다. 거점 귀환은 오락실 출구에서만 가능하다.
- 선반 기본 후보: 통조림2/85%, 물2/80%. 자재 기본 후보: 판자3/90%, 밧줄2/80%, 못2/75%. 확률·수량은 임시 데이터이며 기존 수색 방식/협력 보정을 더한다.

## 저장·편집

저장 버전8은 `StorageUnlocked`와 `StorageVisited`를 추가한다. v7 이하에서는 잠김/미방문으로 초기화하고 기존 대원·작업·수색 기록은 보존한다. 보관실 기록과 해금 상태가 모순된 저장은 거부한다. 기존 사이트 ID는 그대로 두고 `mall.storage.shelf`, `mall.storage.materials`를 추가했다.

`ExpeditionStorageRoom.cs`는 해금 조건과 상태 표시, `ExpeditionRoomNavigation.cs`는 방 이동을 처리한다. `ConnectStorageRoom.Run` 다음 `ConnectSearchStatus.Run`으로 프리팹을 재연결한다. 2026-09-24부터 관리실 선반이 있으면 ConnectStorageRoom은 실행을 거부하고, 보상표는 `BuildBalance1.Run`이 맡는다. 복도부터 다시 생성한다면 `ConnectCorridorSearch` → `ConnectSearchStatus` → `ConnectStorageRoom` → `ConnectSearchStatus` 순서를 따른다.

## 검증·화면

`VerifyStorageRoom.Flow`와 `Persistence`, `Legacy`에서 실제 레이캐스트 클릭으로 도구 없음/확정 전 도구 제거/취소/중복 확정, 첫 개방 비용, 도구 비소모, 왕복·도구 없는 재입장, 방별 버튼, 수색 중단/회수/고갈, v8 파일 복원·재방문·보관실 조우 후퇴를 검증했다. 확장 전 실제 v7 저장을 읽어 기존 복도 진행과 새 문 잠김도 확인했다. 검증 파일은 `Temp/StorageRoomVerification`으로 격리했다.

실제 Unity 1920×1080 캡처: `Assets/Screenshots/SearchStatus/storage-room.png`. 외곽 HUD와 기존 대원 배치는 유지하고 새 선반/자재 위치에 수색 UI를 연결했다. 새 원화의 네이티브 해상도와 PSD 분리 범위는 [원화 기록](../아트/보관실-v1/README.md)에 명시했다. 실행 파일 빌드는 생략했다.
