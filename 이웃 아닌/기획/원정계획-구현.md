# 원정 계획 — UI02 / D00·D01

정착지 출입구 → 목적지 지도와 대원 선택 → 짐 꾸리기 → 선택한 원정대의 기존 가방 화면 → 원정 계획 복귀를 연결했다. 준비 중에는 날짜·시각·보급품·탄약을 소비하지 않는다. 실제 출발/이동/탐험 씬 전환은 이번 범위가 아니다.

## 시각 기준과 최신 사용자 규칙

승인 시안 `아트/UI전체시안-v1/02-원정계획.png`의 지도 좌측 / 장소 설명 우측 / 생존자 목록 하단 배치를 따른다. 화면 1920×1080, 왼쪽 80px·오른쪽 끝 1840px, 하단 y=952·높이78을 공통 기준으로 쓴다. 돌아가기는 최신 지시에 맞춰 좌측 하단, 짐 꾸리기는 우측 하단에 두며 양쪽 버튼은410×78이다. 선택 요약은 그 사이에 둔다. 폰트는 기존 Gaegu Bold다.

시안의 6명/시간18:00/예시 체력·피로는 고정하지 않는다. 현재 실제 두 대원·실제 체력·현재 시각을 표시한다. 피로 수치 모델이 아직 없어 피로 막대를 꾸며 넣지 않고 특성 이름을 표시한다. 대원 목록은 수평 ScrollRect이고, 많은 인원은 휠/드래그/스크롤바로 이동한다. 선택 상한은 Inspector의 MaximumParty(초기6)이며 시작 인원2와 무관하다.

## 목적지 데이터

- 거점: 현재 정착지 이름과 그 정착지 썸네일을 사용. 현재 거점이므로 출발 대상 선택 불가.
- 폐상가: 편도20분/위험 보통/물·부품. 승인 시안의 건물 사진 사용.
- 편의점: 편도10분/위험 낮음/식량·생활용품. 별도 건물 외관은 미제작이므로 상점 아이콘과 외관 미확인 문구 사용.
- 창고: 경로 미확인, 선택해 정보를 볼 수 있지만 짐 꾸리기 불가.

거리·위험·상한·자원은 화면 검증용 데이터이며 실제 이동/탐험 밸런스 확정이 아니다. 미확인 장소의 상세 물자 수량이나 적을 노출하지 않는다.

## 참가 조건과 가방 연결

체력0 이하 또는 휴식/제작에 예약된 대원은 참여 불가. 선택한 뒤 상태가 달라져도 새로 검사하며, 짐 꾸리기 직전에 다시 검사한다. 선택 해제, 상한 도달 차단, 목적지 변경에 대응한다. 대원이 없거나 경로가 막힌 곳에서는 짐 꾸리기가 비활성이다.

이번 짐 꾸리기는 기존 UI01 인벤토리를 재사용한다. 선택한 원정대만 표시하고, 원래 Adventurer 객체를 키로 써서 가방 소유가 바뀌지 않는다. 실제 한 사람만 선택해도 그 사람의 이름·초상이 정확히 나온다. 돌아가면 목적지/선택 초안을 유지하고, 이미 옮긴 물자는 각 가방에 남는다. 이후 일반 가방을 열면 원정 복귀 콜백과 인원 제한이 남지 않는다.

**UI03 전용 짐 꾸리기 배치·출발 최종 확인·현장 이동·저장/씬 간 인벤토리 통합은 후속 단계다.** 지금 짐 꾸리기를 누르는 것만으로 원정이 시작되거나 시간이 차감되지 않는다.

## 편집 파일

- `Assets/Prefabs/Settlement/ExpeditionPlanPanel.prefab`: 화면 조립, 목적지 배열, 상한, 참조.
- `ExpeditionMemberCard.prefab`: 초상/이름/특성/체력/선택 상태.
- `ExpeditionMapMarker.prefab`: 공통 핀 외형/아이콘/이름표와 클릭 영역. 핀 외형은 코드 벡터이고 배경 지도에 합쳐져 있지 않다.
- `Assets/Scripts/FrontEnd/ExpeditionPlanPanel.cs`: 목적지·원정대 초안과 가방 연결.
- `AgentScripts/BuildExpeditionPlan.cs`: 최초 조립 재현용. Inspector 수동 조정 후에는 불필요하게 재실행하지 않는다.
- `아트/원정계획-v1/`: 원본 PNG, 개별 아이콘/사진, 네이티브 지도 PSD, 3840×2160 레이어 배치 PSD, 제작 프롬프트/한계 기록.

지도 바탕은 기본 image_gen으로 승인 시안의 핀·문구를 제거해 재구성했다. 네이티브1902×827을 보존하며, 3840PSD 배치는 새 디테일 복원이 아니다. 그림 내부 도로/건물은 한 지도 레이어다. 시안과 화풍을 맞췄으나 도로가 픽셀 단위로 동일하다는 의미는 아니다. 아이콘/건물 사진은 작은 시안 원본에서 분리한 것으로 후속 고해상도 원본 보완이 필요하다.

## 검증

`VerifyExpeditionPlan.Flow`에서 실제 UI 레이캐스트 클릭으로 출입구 진입, 목적지 정보 변경, 거점·미확인 경로 차단, 선택/해제/상한, 예약·체력 조건 재검사, 한 명만 짐 확인 시 소유·초상, 물자 이동 후 계획 복귀, 일반 가방 복귀, 자원/시간 불변, 텍스트 영역을 확인했다. 기존 인벤토리 소유·예약 재료 판정은 그대로 사용한다. 실행 파일 빌드는 생략했다.
