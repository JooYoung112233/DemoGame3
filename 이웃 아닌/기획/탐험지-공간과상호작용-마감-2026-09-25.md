# 탐험지 공간과 상호작용 마감

> 2026-09-25 적용 기록. 탐험지의 배경·동선·상호작용부터 개선한다는 사용자 승인에 따라 기존 3개 방을 마감했다. 공간·표식·입력·해상도 검증과 첫 원정 튜토리얼의 방별 안내·배치 검증을 Unity Editor에서 통과했다.

## 범위

- 기존 폐상가 원본 배경을 유지한다. 대상은 오락실·복도·보관실의 현재 3개 방이다. 관리실 선반은 기존 복도 문 상호작용을 유지한다.
- 신규 지역, 방 추가, NPC 등장 및 신규 이벤트 연결은 이번 마감과 별도다. 준비된 NPC 프리팹이 탐험 이벤트에 출현하도록 연결되었다고 보지 않는다.
- 전투 규칙·밸런스·실제 이동/잠금 비용·저장 v13 데이터 형식은 변경하지 않는다.

## 수색 정보와 이동 안내

- 최초 방문 전에는 수색 대상 수를 공개하지 않고 `아직 수색 기록이 없습니다`를 표시한다. 방문한 방의 사물만 합산하며, 보관실 문을 열었어도 아직 입장하지 않았다면 그 방의 대상 수는 공개하지 않는다.
- 관리실 선반은 복도 방문만으로 합계에 넣지 않는다. 실제 확인·수색 기록이 생긴 뒤 포함한다. 상태 확인으로 보상을 추첨하거나 새 수색 기록을 만들지 않는다.
- 현장 HUD는 현재 방의 `미수색 / 진행 / 물품 남음 / 비어 있음`을 두 줄로 표시한다. 다른 방 수색이 현재 방 집계를 늘리지 않으며 수색 완료·마지막 물품 회수 뒤에도 갱신한다. 위험·발소리 등 기존 상황 경고가 우선 표시된다.
- 보관실 방문 뒤 오락실로 돌아와도 확인한 경로를 유지한다. 보관실의 돌아가기 문은 `복도로 돌아갈까요?`로 안내한다.
- 일반 문과 열린 보관실 이동은 동일하게 `1턴 · 10분`, `소음 없음`을 안내한다. 실제 분 수는 기존 `MinutesPerTurn`을 사용한다. 잠긴 문은 해제 턴+이동 턴의 합계, 추가 소음, 도구 미소모를 보여준다. 확인창을 열거나 취소하는 행동은 시간을 쓰지 않는다.
- 새 저장 항목 없이 기존 방문 여부·확인한 사물·수색 상태를 이용하므로 이전 저장의 수색 진행과 고갈 상태를 유지한다.

## 공간과 상호작용

- 기존 오락실·복도·보관실 PNG를 유지하면서 방별 조명과 말 아래 접지 그림자를 맞췄다. 새 배경 원화나 고해상도 원본을 제작한 작업은 아니다.
- 사물의 상시 표식은 40px로 정리했다. 미수색 대상에는 `?`를 표시하며 실제 사물 영역을 눌러 상호작용한다. 포인터를 올리거나 키보드 초점을 주면 이름·상태를 펼치고, `Alt`로 전체 표식을 확인할 수 있다.
- 이동 문은 항상 표시한다. 발소리·위험 예고는 사물의 이름/수색 표식과 별도로 유지한다. 팝업이 열려 있는 동안 뒤쪽 현장 입력은 차단한다.
- 이동 방향에 따라 출발 문과 도착 문을 사용하고, 1~6명 원정대가 입구 주변의 바닥에 배치되도록 동선을 맞췄다. 특히 보관실에서 복도로 돌아올 때 중앙 철문 쪽에 도착한다.
- 현장 크리쳐 `Resident`는 대원 이동 대상에서 제외한다. 방 전환 중에는 크리쳐 말과 머리표를 숨기고 도착 뒤 해당 방의 위치에 다시 표시한다. 이는 표시와 이동 대상의 수정이며 크리쳐의 턴·조우 규칙은 유지한다.

## 첫 원정 튜토리얼 후속 수정

- 첫 수색 전에 다른 방으로 이동해도 자유 이동을 막지 않는다. 보관실에서는 복도로 돌아가는 문, 복도에서는 오락실로 돌아가는 문을 차례로 안내한다. 첫 수색 완료 뒤 귀환 안내도 같은 경로를 사용한다. 현재 활성화되어 있고 입력 가능한 대상만 강조한다.
- 현장 기본 안내는 상단 물자 HUD를 가리지 않도록 기존 좌하단 현황판 자리(화면 좌상단 기준 `(80, 776)`), `480×148`에 표시한다. 제목은 26px/높이 40, 본문은 22px/높이 78, 좌우 여백은 24다. 수색·발견물 등 다른 팝업과 정착지에서는 기존 배치·폰트 설정을 복원한다. 안내가 끝나면 원래 현황판이 드러난다.
- 귀환 안내는 실제 버튼 이름인 `거점으로 귀환`을 사용한다. 튜토리얼 진행 조건과 저장 상태는 변경하지 않는다.
- 문을 안내할 때 프레임·밝은 영역·화살표는 작은 문 표식과 이름 주변에 표시한다. 문 전체 높이에 맞춘 강조가 날짜·탐험 턴을 가리던 문제를 실제 화면에서 확인하고 수정했다. 문 자체의 넓은 클릭 영역은 유지한다.

## 검증 기록

- **PASS — [VerifyExplorationKnowledge.Run](../AgentScripts/VerifyExplorationKnowledge.cs):** 미방문·관리실 정보 비공개, 현재 방 집계, 수색 완료·회수 갱신, 방문 경로와 v13 복원, 무작위 상태 불변, 문별 비용 문구, 열기/취소의 시간·소음·도구 무소모.
- **PASS — [VerifyExplorationRoomPresentation.Run](../AgentScripts/VerifyExplorationRoomPresentation.cs):** 방향별 문과 전체 동선, 1~6명 바닥/HUD 간격, 중앙 철문 복귀, 방별 조명·그림자 일치, 실제 이동 코루틴에서 `Resident` 제외.
- **PASS — [VerifyResidentTransitPresentation.Run](../AgentScripts/VerifyResidentTransitPresentation.cs):** 전환 중 크리쳐·머리표 숨김, 도착 위치에서 동일 인스턴스 복원, 표시 필터가 턴·조우·상태를 바꾸지 않음.
- **PASS — [ReviewExplorationPolish.Interaction / AltAndKeyboard / Rooms / Resolutions](../AgentScripts/ReviewExplorationPolish.cs):** 실제 사물 입력·팝업 차단·포인터 안내, `Alt`와 키보드 초점, 세 방의 12개 사물/문 클릭 판정 및 왕복 이동, `1920×1080`·`1280×1024`·`2560×1080`에서 배경과 입력 위치 일치. 마지막 튜토리얼 수정 뒤 Rooms/Resolutions를 다시 실행하고 화면을 갱신했다. 16:9 원화 구도를 유지하며 다른 비율은 여백으로 대응한다.
- **PASS — [VerifyTutorialRoomReturn.Run](../AgentScripts/VerifyTutorialRoomReturn.cs):** 첫 수색 전/완료 후 3개 방의 타깃과 문구, 비활성 대상 숨김, 실제 폰트 높이, 좌하단 안내 및 팝업 배치 복원, 작은 문 표시를 따르는 프레임/화살표/밝은 영역과 원래 클릭 영역 유지, 진행·턴·소음 불변 검사.
- 기존 [VerifySearchStatus.cs](../AgentScripts/VerifySearchStatus.cs)와 [VerifyCorridorSearch.cs](../AgentScripts/VerifyCorridorSearch.cs)의 전체 방 집계 기대치를 실제 fixture의 방문 범위로 수정했다. 처음에는 대상 수 비공개, 오락실만 방문한 저장은 오락실 3곳, 복도까지 방문한 저장은 관리실 선반을 제외한 5곳을 기대한다. 기존 수색·수령·고갈·재방문 검사는 보존한다. 이번 변경 후 실제 실행 결과는 별도 확인한다.
- 지식/HUD/이동 안내 변경 파일의 `git diff --check`는 오류 없이 통과했다. 전체 프로젝트 변경분의 무오류나 Unity 컴파일 통과를 대신하는 결과는 아니다.
- 마지막 코드 변경 뒤 Unity 재컴파일 성공, 컴파일 오류 없음. 플레이 검수에는 `Temp/ExplorationPolishSlots`를 사용해 실제 저장 슬롯을 덮어쓰지 않았다. 이 기록은 위 기능과 화면에 대한 검수이며 전체 게임의 모든 흐름을 완주한 결과는 아니다.
