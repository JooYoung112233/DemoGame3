# 물물교환 담기 방식

사용자가 생활 물자 적용 뒤 교환 조작이 직관적이지 않다고 지적했다. 종이·잉크 스타일과 공통 하단 버튼 위치를 유지하면서, 양쪽 한 품목의 수량을 맞추던 화면을 복수 품목 교환 목록으로 바꾼다.

## 조작과 화면

- 왼쪽은 우리 창고, 오른쪽은 방문자 물품이다. 그림을 누르면 해당 쪽의 교환 목록에 1개를 담는다.
- 목록에서 그림·이름·수량·가치를 함께 보며 `+ / −`로 수량을 바꾼다. 0개는 목록에서 빠진다.
- 종류를 섞어 담을 수 있다. 물품 페이지 이동은 담은 목록을 바꾸지 않는다. 목록이 길면 휠·스크롤바·상하 화살표로 확인한다.
- 아래에 양쪽 합계와 정확한 부족 가치를 표시한다. 초과 지급은 차액을 돌려받지 못한다고 알린다.
- 확정 창도 양쪽 그림 목록으로 보여 준다. 취소하면 담은 목록을 유지한다. 거래 완료·뒤로가기·닫기·새 방문은 임시 목록을 비운다.
- 교섭 가능한 건강한 대원을 자동으로 고른다. 별도 교섭 대원 선택은 요구하지 않는다.
- 기존 매입/판매 표현을 사용자 관점의 줄 물건·받을 물건·교환 가치로 정리한다.

## 재고·저장

담기만으로 실제 재고를 바꾸지 않는다. 예약 재료·개인 가방은 거래 재고에서 제외하고, 같은 물품을 양쪽에 동시에 담지 못하게 한다. 한 종류는 기존과 같이 최대 99개다.

확정 직전 전체 목록의 재고, 가격, 방문, 캠페인, 예약, 교섭 대원, 창고 용량을 다시 검사한다. 하나라도 달라져 유효하지 않으면 전체 교환을 취소한다. 재확정으로 재료가 중복 소모되지 않는다.

가격·선호품·방문 주기·저장 형식은 유지한다. 담아 둔 미확정 목록은 저장 대상이 아니며 실제 창고와 방문자 재고만 저장한다.

## 구현과 재적용

- `SettlementVisitorPanel.TradeCart.cs`: 교환 목록·합계·확정 검사·결과.
- `TradeCartRow.cs`, `Assets/Prefabs/Settlement/TradeCartRow.prefab`: 수정 가능한 공통 목록 행.
- `BuildTradeCartUI.Run`: 기존 VisitorPanel과 SettlementScreen의 방문자 UI만 수정하는 Unity 프리팹 빌더.
- 구형 빌더를 실행할 때는 `BuildEverydayGoods.Run` → `BuildEverydayRecipes.Run` → `BuildEverydayTradeUI.Run` → **`BuildTradeCartUI.Run`** 순서로 적용한다.
- `VerifyEverydayTrade`는 이전 단일 품목 UI의 과거 검수다. 현재 조작 검수는 `VerifyTradeCart.Run`을 사용한다.

## 검수

최종 결과: **PASS**. 실제 Unity 화면의 두 크기를 직접 검수했다. 첫 검수에서 발견한 물품 이름 높이 부족(필요 33px, 배정 30px)은 이름 영역 36px와 그림 영역 조정으로 수정한 뒤 전체 검수를 통과했다.

`VerifyTradeCart.Run`은 사용자 저장을 사용하지 않는 새 캠페인과 `Temp/TradeCartVerification` 슬롯에서 실행한다. 혼합 교환·페이지·수량·취소·확정은 실제 UI Raycast와 버튼 입력으로 검사한다. 재고·가격·예약·용량 변경은 별도로 만든 검수 조건이다.

1920×1080·1280×800에서 그림, 이름, 목록 경계와 스크롤, 확인창을 확인한다. 실제 결과는 `아트/리소스검토/trade-cart-runtime.json` 및 `trade-cart-*.png`에 기록한다. 장기 수급 밸런스나 새 가격 조정은 이번 변경 범위가 아니다.
