# 방문자와 물물교환 — 1차 구현

2026-09-23. 비전투 콘텐츠의 다음 제작 단위. 세계관·방문자 정체·생존 게이지를 확정하는 작업은 아니다.

## 사용 흐름

정착지 상단 **방문자** → 대화 → 가지고 온 물품 → 양쪽 물품/수량과 교섭 담당자 선택 → 교환 제안 확인 → 확정. 돌아가기는 제안을 버리며, 대화에서 돌아가기만 눌러서는 방문이 끝나지 않는다. 방문 마무리는 별도 확인 후 다음 방문까지 종료한다. Esc는 확인창 → 거래 → 대화 → 정착지 순서로 한 단계만 닫는다.

공용 창고에서만 교환한다. 제작·조리 예약분은 제외하고 개인 가방은 사용하지 않는다. 건강하고 작업이 없는 대원이 담당한다. 확정 직전에 방문 날짜/시간, 담당자, 양쪽 재고와 보관 상한을 다시 확인한 뒤 한 번만 맞바꾼다. 같은 물품끼리 거래할 수 없다. 교환 자체는 시간이 들지 않는다.

## 임시 콘텐츠 값

- 첫 방문 DAY 1, 이후 2일 간격, 12:00 이상~18:00 미만. 시간이 건너뛰면 최근 방문만 생성하며 지난 방문의 재고를 누적하지 않는다.
- 방문마다 한정 재고. 닫기·저장·불러오기에는 재충전하지 않고 새 방문에서만 다시 채운다.
- 한 거래에서 내놓기/받기 각각 한 종류, 수량 1~99. 내놓는 가치 합계가 받는 가치 이상이면 수락한다. 초과 가치는 반환하지 않으며 확인창에 양쪽 값을 표시한다.
- 나무/천/물/미정수 물/고철/못 가치 1, 식재료/밧줄/조리한 식사 2, 통조림/붕대/도시락 3, 지렛대/손전등 6.
- 기본 재고: 나무6, 천6, 식재료6, 물4, 미정수 물4, 통조림2, 고철4, 밧줄2, 못2, 붕대2. 식사·도시락·도구는 0에서 시작하지만 플레이어가 내놓으면 방문자 재고에 들어간다.
- 외화/화폐·흥정 확률·특성 보정·영입·이상현상 사건은 이번 범위가 아니다. 방문자는 이름 미공개 `?`다. 익명 대사는 임시 기능 문구다.

## 저장과 편집

- `Assets/Prefabs/Settlement/VisitorPanel.prefab`: 방문 시간, 주기, 물품 가치/기본 재고, 대화/거래/확인 화면. 기존 `InventorySlot.prefab`의 연결된 인스턴스를 사용한다. UI 배치는 Inspector에서 수정하며 런타임에 덮어쓰지 않는다.
- `SettlementScreen.prefab`: 상단 진입 버튼과 연결.
- `SettlementVisitorPanel.cs`: 방문 진행·거래 검증·UI 동작. `CampaignSaveData.cs`: v4 방문 날짜·종료 여부·재고 저장 및 v1~v3 이관. 이전 저장에는 빈 방문 기록을 만들고 해당 게임 시간으로 방문 상태를 계산한다. 플레이어 재료를 지급하지 않는다.
- `AgentScripts/BuildVisitor.cs`: Editor API를 통한 재현용 조립 스크립트. 프리팹을 수동 수정한 경우 이 빌더를 무심코 재실행하지 않는다.

## Unity 검증

`VerifySettlement.Flow`, `VerifyVisitor.Flow`, `Restart`, `Edges` 통과. 컴파일 오류 없음.

실제 버튼 raycast 클릭, HUD 숨김/복원, 글자 높이, 방문 전/후와 다음 방문, 교환 취소/확정/중복 호출, 가치 부족·같은 물품 차단, 예약 재료·개인 가방 제외, 바쁜/행동 불가 담당자, 확인 뒤 바뀐 플레이어/방문자 재고, 최대 보관 수량, 만료된 거래와 오래된 방문 종료 확인, 탐험 중 진입 차단을 확인했다. 키보드 Esc도 실제 Input System 입력으로 검사했다.

별도 `Temp/VisitorRestartVerification` 기록으로 파일 쓰기/읽기, 씬 재진입, Play 종료/재시작 → 시작 화면 계속하기를 검증했다. 재고 변경과 진행 중 제작이 유지되며 방문 재고가 되살아나지 않는다. v1/v2/v3 이관과 잘못된 방문 재고 거절도 확인했다. 사용자 저장 슬롯에는 쓰지 않았다. 실행 파일 빌드는 하지 않았다.

다음 단위는 정착지 성장·시설 개선이다. 다양한 방문 사건, 물자 공급/소비의 장기 균형, 전용 방문자/물품 원화 및 전체 비전투 연속 플레이 검수는 미완료다.

## 재고 표시 수정 — 사용자 피드백

양쪽 목록은 재고가 1개 이상인 물품만 표시한다. 우리 창고는 제작/조리 예약분을 제외한 사용 가능 수량 기준이다. 남은 항목은 빈칸 없이 기존 슬롯 순서에 표시하고, 선택 물품이 품절되면 첫 남은 항목으로 선택과 수량을 초기화한다. 빈 재고에서는 안내를 표시하고 수량 조절/교환을 막는다. `VerifyVisitor.StockVisibility`에서 실제 교환 후 품절 제거·올바른 클릭 매핑·빈 목록·저장 복원을 확인했다. 최신 화면: `Assets/Screenshots/Visitor/trade-in-stock.png`.
