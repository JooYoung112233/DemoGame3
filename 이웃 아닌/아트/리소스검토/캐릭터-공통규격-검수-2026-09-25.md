## 실제 게임 연결에서 확인된 차이

1. `Assets/Data/BattleCreatures.asset`의 **12개 Body 모두 `Assets/Art/Creatures/V1` PNG를 참조**한다. v2 시안을 만들었다고 실제 게임이 v2로 바뀐 상태가 아니다.
2. `ExpeditionArrivalPanel.prefab`의 Scout/Medic는 정착지의 두 전신을 참조한다. `ExpeditionArrivalPanel.cs`는 medic 이외의 인물을 Scout 그림으로 표시한다. `SettlementController.cs` 역시 같은 방식이다. 이름·초상 6종과 전신 6종이 모두 갖춰진 상태가 아니다.
3. 전투는 원정대의 현재 Body를 가져오며 적은 creature.Body를 사용한다. 초기 감염자 PNG는 EnemyBody/EnemyPortrait 대체 연결로 남아 있다.
4. `FieldPawn.prefab`에는 이미 공통 Base·BaseBevel·BaseNeck 구성이 있다. 전투도 이 말을 재사용한다. **이미지마다 새로운 받침대를 그려 붙일 필요가 없다.** v2에 구워 넣은 붉은 받침대는 이 구조와 중복된다.
5. 기존 README의 “연결하지 않음”은 최초 제작 시점 기록이며 현재 연결 상태와 다르다. 폴더 버전 번호나 제작 완료 문구만으로 사용 상태를 판정하지 않는다.

## 같은 규격으로 고정할 요소

- **몸체:** 기존 대원처럼 검정 중심의 납작한 실루엣. 얼굴·의복의 밝은 면·주름·금속 반사를 새로 넣지 않는다. 개성은 머리, 자세, 체형, 외곽 소품으로 구분한다.
- **종이 가장자리:** 기존 대원의 색과 화면 표시 두께를 기준으로 한 공통 편집 요소. 캐릭터마다 색·두께·광륜을 생성 모델에 맡기지 않는다. 큰 크리쳐라고 테두리까지 두껍게 키우지 않는다. 정확한 수치는 실제 표시 크기 비교 후 공통 값 하나로 확정하며 이번 검수에서 임의 수치를 승인 값으로 지정하지 않는다.
- **받침대:** 기존 공통 말 구조 재사용. 상면·옆면·목·그림자의 시점은 같게 유지하고, 게임이 이미 사용하는 구분 색을 따른다. 몸체 PNG 안에 받침대나 접지 그림자를 합치지 않는다.
- **정렬:** 바닥 접점과 중심축을 따로 보관한다. 원본 캔버스 크기로 인물 크기를 맞추지 않고 실제 몸체 경계를 기준으로 한다. 부유형은 공통 받침대 위 몸체 높이만 다르게 한다.
- **인물 일치:** 초상과 전신의 머리 모양·모자·배낭 등 핵심 형태를 동일 ID에 묶는다. 정착지·탐험·전투에서 같은 인물에 서로 다른 원화를 배정하지 않는다.
- **분리 납품:** 몸체 실루엣 / 종이 외곽 / 공통 받침대 / 접지 그림자를 독립 요소로 관리한다. PNG 원본, 실제 알파, 레이어 PSD를 검수한다. 체크무늬·광륜·배경 잔여 픽셀이 있는 합성본은 제외한다.
- **검수 크기:** 승인 그림과 현재 대원 옆에 실제 인게임 크기로 나란히 놓고 비교한다. 확대 단독 원화만 보고 일치 판정을 하지 않는다.

## 이번 작업의 완료/남은 범위

완료: 이전 리소스 비교, 실제 파일 알파/치수 검사, 전투 참조 12개 확인, 공통 규칙 기록.

미완료: 공통 몸체·테두리 마스터 제작, 새 NPC와 크리쳐 수정 납품, 전신 부족 대원 보완, 레이어 PSD, 실제 인게임 나란히 검수와 교체. 게임 원화·프리팹·전투 수치는 이번 검수에서 변경하지 않았다.

앞서 요청된 숨은 NPC 배치와 이벤트 심화도 계속 남아 있다. 자산 일관성 검수를 먼저 통과시킨 뒤 장갑·사진·거울 단서와 발견 후 인물을 방별로 배치한다. 미채택 NPC 그림으로 콘텐츠 제작 완료를 보고하지 않는다.
