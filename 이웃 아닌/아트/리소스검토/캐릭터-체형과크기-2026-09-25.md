# 캐릭터 체형과 크기 · 2026-09-25

## 제작 기준

최신 화면 피드백은 “너무 큰데? 처음 애들이랑 사이즈가 너무다른데? 바닥이랑 맞지도 않고”, “비율도 안맞잖아”다. 아래 최초 확대 설정은 채택하지 않고 기존 두 대원의 표시 높이와 받침대 비율로 되돌린다. 같은 크기에서 머리·몸통·다리의 실제 형태를 비교하며 전신은 보존한다.

이전 지시 중 “자르지마”, “너무 날씬하게 만들지마 우리 기존 캐릭터 처럼”은 유지한다. 표시 크기는 위의 최신 지적을 우선하며, A4 맞춤·신체 잘라내기는 사용하지 않는다.

기존 scout/medic의 머리와 몸통 비율, 두툼한 팔·다리·신발을 기준으로 신규 대원 4명과 NPC 3명의 전신을 다시 제작한다. 검정 몸체, 공통 종이 테두리와 독립 받침대는 유지한다. 기존 두 대원의 PNG는 변경하지 않는다.

## 적용 구조

- 대원 전신: mechanic/cook은 `Assets/Art/Tokens/party-{id}-body-v3.png`, researcher/guard는 `party-{id}-body-v2.png`.
- NPC 전신: doyun/jun은 `Assets/Art/Tokens/npc-{id}-body-v3.png`, giho는 `npc-giho-body-v2.png`.
- 원본: 이 폴더의 같은 이름 `*-source.png`. 생성 결과를 바이트 그대로 보존한다. 이전 버전·미채택 시안도 보존한다.
- v3는 키를 맞춘 뒤에도 남아 있던 v2의 부풀린 허벅지·무릎·큰 부츠·과한 발 간격을 다시 그렸다. 기존 두 인물의 단순한 바지·작은 신발과 자연스러운 옆 자세를 기준으로 삼는다. 머리·의상·직업 소품은 해당 인물 것을 유지한다.
- 연구자·경비·기호는 옆 자세까지 바꾼 v3 1차에서 몸통이 너무 가늘어져 채택하지 않았다. 신발 부분만 수정한 후속도 인물 특징까지 바뀌어 미채택했다. 이 세 명은 v2의 도톰한 체형과 정체성을 유지하고 표시 배율만 기존 대원 기준으로 맞춘다. `rejected-slim`과 `shoes-only-attempt`는 검토 이력이며 사용 자산이 아니다. 세 명의 부츠 형태까지 모두 수정했다고 보고하지 않는다.
- 신규 대원 배율: 모두 1. 기존 scout/medic도 1. 최초 mechanic 1.16 / cook 1.10 / researcher 1.08 / guard 1.18 설정은 사용자 피드백으로 폐기했다.
- NPC 몸체 높이: 모두 기존 기준 1.72. 발 기준은 받침대 위 0.035. 최초 2.03 / 1.93 / 2.10 설정은 폐기했다. 뒤쪽 도윤이 앞쪽 대원보다 커지는 문제를 제거한다.
- `PartyRoster.ApplyBody`가 이전 인물 배율을 제거한 뒤 다음 배율을 적용한다. 교체·반전·새로고침 때 누적 확대나 발 위치 이동을 방지한다.
- 전투의 아군 몸체와 머리 위 표시 기준도 같은 인물별 배율을 사용한다. 전투 규칙은 변경하지 않는다.
- Unity 스프라이트 사각형은 전신 알파를 보존하며 비어 있는 캔버스 여백만 제외한다. PNG 자체를 자르거나 늘리지 않는다.

## 재적용 순서

Unity가 멈춘 상태에서 `ImportStandeeSprite.RevisedPeople` → `WirePartyStandeeBodies.RevisedPeople` → `WireNpcAndInfectedArt.RevisedPeople` → `BuildNpcStory.Run`.

원본 재생성 도구는 built-in `image_gen__imagegen`이다. 현재 프롬프트와 채택 여부는 `*-body-v3-generation.json`과 `party-body-v3-prompts-2026-09-25.json`을 따른다. v2 생성 기록은 이력으로 보존한다. 체크무늬가 실제 픽셀로 들어간 RGB 출력은 게임 자산으로 사용하지 않는다. 형태가 맞는 RGB 후보는 built-in 도구에 배경만 투명화하도록 후속 요청하며 코드로 원본 픽셀을 수정하지 않는다.

## 검증·납품 상태

Unity 6000.6.0f1에서 적용·검증했다. 기존 scout/medic 원본과 표시 배율은 유지한다.

| 사용 몸체 | 원본 PNG | 가시 몸체 높이(alpha≥32) |
| --- | --- | --- |
| mechanic v3 | 967×1627 | 1521px |
| cook v3 | 992×1585 | 1515px |
| researcher v2 | 992×1586 | 1469px |
| guard v2 | 1024×1536 | 1452px |
| doyun v3 | 1024×1536 | 1426px |
| jun v3 | 1024×1536 | 1385px |
| giho v2 | 930×1692 | 1541px |

기호를 제외한 현재 원본의 가시 몸체 높이는 제작 목표 1536px보다 작다. 생성 도구가 반환한 native 결과를 그대로 보관했으며 업스케일·디테일 복원은 하지 않았다. 원본 PNG 픽셀을 자르거나 변형하지 않는다. 임포트 사각형 밖의 alpha1~31 경계 잔여는 각각 보고서에 명시했으며 alpha≥32 몸체는 모두 안쪽이다.

- `VerifyRevisedPeople.Run`: 선택한 7개 몸체의 단일 스프라이트·무축소·알파 경계·대원 배율1·NPC 높이1.72/발/중심·공통 재질·전투 및 도윤 참조 PASS. `standee-proportions-v3-verification.json`에 상세 수치와 검증 전후 PNG16개 해시 보존을 기록했다.
- `VerifyPartyStandeeBodies.Run`: 반복 교체·좌우 반전·중심과 발 위치·누적 확대 방지·정착지 및 전투 참조 PASS.
- `VerifyNpcStoryRuntime.PeopleV3`: 대원6명+공개된 도윤을 테스트 상태로 구성했다. 1920×1080 / 1280×1024 / 2560×1080 탐험 화면, 대화 배치, 실제 전투의 6명 몸체·머리 위 기준을 검증하고 캡처했다. 새로운 영입/퀘스트를 구현했다는 의미는 아니다. 도윤 외 NPC2명은 원화/프리팹 준비 상태를 유지한다.
- 실제 화면: `standee-proportions-v3-field-1920x1080.png`, `standee-proportions-v3-dialogue.png`, `standee-proportions-v3-battle.png`. 원화 비교판: `standee-proportions-v3-review.png`.
- `RenderStandeeReview.ExportRevisedLayers`와 `PackageStandeeLayers.cjs`로 7개의 `standee-{id}-final-native-layers.psd`를 저장했다. Body Ink / Paper Rim / Shared Base의 실제 독립 레이어3개와 합성RGBA를 원본 내보내기PNG와 채널별로 검증했다. `standee-proportions-v3-layer-exports.json`, `standee-proportions-v3-psd-validation.json`에 경로·해시가 있다. 이는 게임 재질 렌더의 구성요소이며 원화 내부의 의상/얼굴 개별 레이어 복원은 아니다.

제작 프롬프트는 built-in image_gen 기록에 보존하며 별도 API/CLI 생성은 사용하지 않았다. 완료 후 Play를 멈추고 검수 전용 저장 경로를 해제한다. 기존 플레이 저장은 수정하지 않는다.
