# 이스트 트레인 — 기획 1차

작성일: 2026-10-03

이 문서는 사용자가 제시한 신규 데모 방향을 보존하고, 구현 제안을 구분한다. 2026-10-03 첫 플레이 프로토타입을 `Assets/Scenes/EastTrain.unity`에 구현했다. 실제 구현 범위와 조작은 [프로젝트 안내](../README.md)를 따른다. 아래 후속 콘텐츠와 미정 사항까지 모두 구현된 것은 아니다.

## 1. 사용자 확정 방향

온 세계가 얼어붙었다. 동쪽에 따뜻한 곳이 있다는 무전을 듣고, 망가진 열차를 어떻게든 수리하며 동쪽으로 향한다. 여정 중에도 계속 동쪽으로 오라는 무전이 들린다.

- 제목: 이스트 트레인
- 형식: 횡스크롤
- 최종 방향은 UI 없음. 단, 2026-10-03 최신 사용자 지시로 **프로토타입에서는 상태·조작·첫 출발 안내 UI를 상시 표시**한다.
- 내부는 **FAR: Changing Tides를 참고한 횡단면 구조**로 구현한다. (2026-10-03 사용자 추가 지시)
- 내부 이동 중에는 확대하고 운전 중에는 배경까지 보인다. 조종 중임을 명확히 표시하며, 설비 가동·정지의 시각 피드백을 강화한다. 이동 속도도 빠르게 조정한다. (2026-10-03 플레이 피드백)
- 배경: 아무것도 없는 설원
- 분위기: 외로움
- 프롤로그: 폐역에서 출발하여 차량기지까지 간다.
- 열차는 망가진 차를 수리한 것이라 외형이 엉망이며 자동운전이 되지 않는다. 플레이어가 직접 운전한다.

### 열차와 생존

- 실시간으로 연료가 줄어들므로 틈틈이 연료를 주워야 한다.
- 연료가 없으면 열차가 멈춘다. 잡템 등을 태우면 조금씩 이동할 수 있다.
- 엔진이 과열되면 불이 나므로 상태를 조절해야 한다.
- 눈이 쌓여 전진하지 못하면 제설 작업을 한다.
- 난방이 되지 않으면 움직임이 느려진다.
- 간간이 덧댄 철판이 떨어진다. 수리하지 않으면 연료 효율이 낮아지고 최고속도에 도달하지 못한다.
- 수리에는 데드 바이 데이라이트(데바데)의 발전기 수리를 참고한 **타이밍 입력 미니게임**이 들어간다. 타이밍에 맞춰 버튼을 누르는 방식이다. (2026-10-03 사용자 확정)

### 탐색과 진행

- 거대한 나무가 철로에 쓰러져 있거나 철로가 끊긴 것과 같은 메인 이벤트가 있다.
- 장애를 처리하기 위해 주변을 탐색한다.
- 메인 이벤트 후 변화가 생긴다. 진행에 필요한 새 기능이 생길 때 객차가 추가되는 구조다.

핵심 반복:

**운전 → 기관실 확인 → 연료 보충 → 다시 운전 → 이상 발생 → 수리 → 다시 운전**

### 미정

- NPC를 넣을지 여부
- 식량 등의 추가 생존 자원을 넣을지 여부

## 2. 첨부 이미지의 역할

사용자 참고 이미지는 로컬 참고 자료이며 Git에 올리지 않는다. 생성한 이미지·시안은 사용자 요청으로 삭제했다. **최종 이미지와 화풍은 미정**이다. 원래 1인 직접 조작 방향을 유지하며 다인 작업 지시안은 보류한다.

설원의 차가운 청색과 열차 안의 따뜻한 빛, 덧댄 철판·천막·배관이 있는 낡은 열차, 옆에서 보는 긴 실루엣을 참고한다. 최종 게임 자산이나 분리 가능한 원화로 간주하지 않는다.

이미지 속 여러 사람, 많은 객차, 폐허 건물과 고가 구조물은 게임 확정 사항이 아니다. NPC 미정, 기능에 따른 객차 확장, 비어 있는 설원이라는 사용자 설명을 우선한다. 원본 파일을 그대로 보관하며 확대·분리·재생성하지 않았다.

## 3. 플레이 경험 제안 — 검토용

핵심은 열차를 타고 이동하는 동안에도 직접 손을 써서 열차를 계속 살려 놓는 경험이다. 외부의 넓고 조용한 설원과 내부의 좁고 따뜻하지만 불안정한 공간이 대비되도록 한다.

### UI 없음의 구현 해석 제안

화면에 고정된 게이지·아이콘·퀘스트 목록을 두지 않고, 필요한 정보와 조작을 열차 내부 사물로 전달한다. 열차에 붙은 실제 계기까지 제외할지는 구현 전에 정한다.

| 정보 | 게임 세계 안에서 전달하는 방법 제안 |
| --- | --- |
| 운전 상태 | 운전석 레버·브레이크 위치, 바퀴와 배경의 움직임, 엔진 소리 |
| 연료 부족 | 연료함에 남은 양, 화실의 불빛과 엔진 소리 약화 |
| 과열 | 기관실 온도계, 증기 증가, 금속 떨림, 발화 전 이상음 |
| 난방 부족 | 실내 빛의 변화, 입김·몸을 떠는 동작, 움직임 저하 |
| 철판 손상 | 실제 빈틈, 흔들리는 판, 들어오는 눈과 바람 소리 |
| 제설 필요 | 열차 앞에 쌓인 눈과 헛도는 바퀴 |
| 무전 | 실제 무전기의 점등·잡음·음성 |

필수 상태는 소리만으로 알리지 않고 시각 변화도 함께 둔다. 이상 발생 전에 작은 신호를 주고, 조치 후에는 소리와 움직임이 정상으로 돌아와 결과를 알 수 있게 한다. 무전 자막·초기 조작 안내를 허용할지는 미정으로 둔다.

### 운전과 내부 작업의 관계

조작 대상은 열차 안팎을 오가는 인물이다. 운전석에 서면 레버를 조작하고, 자리를 떠나면 기관실이나 연료함으로 이동한다. 사용자 추가 지시에 따라 FAR: Changing Tides를 참고한 옆면 단면을 적용한다. 첫 프로토타입은 아래층에 연료 선반·화실·기관·냉각 밸브·수리 작업대를 두고, 사다리로 위층 운전석·무전기에 접근한다. 연료는 손에 들고 옮기며 바닥에 내려놓을 수 있다.

참고 자료: [Okomotive 공식 소개](https://www.okomotive.ch/presskit/sheet.php?p=far_changing_tides), [개발진의 설비 조작 설명](https://news.xbox.com/en-us/2022/03/01/designing-the-sails-in-far-changing-tides/). 차량 내부 이동과 직접 설비를 다루는 경험을 참고하며 구체적인 열차 배치·형태는 이 프로젝트용으로 구성한다.

자동운전은 없되, 운전석을 떠났다고 즉시 정지시키지는 않는 방식을 제안한다. 마지막 출력·브레이크 설정에 따라 잠시 주행을 유지하고, 연료·열·손상에 따라 상태가 달라진다. 그래야 감속한 뒤 기관실을 보고 돌아오는 반복이 성립한다. 이 방식과 제동 거리는 첫 시험에서 검증한다.

초반부터 연료·과열·추위·철판·눈을 동시에 고장 내지 않는다. 평온하게 달리는 시간을 충분히 두고, 첫 이상은 하나씩 경험하도록 제안한다. 무전도 계속 말하기보다 긴 정적 사이에 반복해서 들어오는 방식이 외로움과 어울린다.

## 4. 프롤로그 구성 제안 — 폐역에서 차량기지까지

길이와 소요 시간은 아직 정하지 않는다. 첫 데모는 한 구간 안에서 핵심 반복이 재미있는지 확인하는 범위로 제안한다.

1. **폐역:** 정차한 낡은 열차와 설원. 무전기에서 동쪽으로 오라는 첫 연락을 듣는다.
2. **시동 준비:** 가까운 곳에서 연료를 가져와 화실에 넣는다. 작은 고장 하나를 수리하며 상호작용을 익힌다.
3. **첫 주행:** 운전석에서 직접 출발한다. 넓은 설원과 열차 소리를 느낄 수 있는 조용한 구간을 둔다.
4. **기관실 확인:** 과열 전조를 경험한다. 출력을 낮추고 확인한 뒤 다시 운전석으로 돌아간다.
5. **첫 정차·탐색:** 눈에 막힌 구간에서 내려 제설하고 주변의 연료를 회수한다. 큰 나무와 단절된 철로는 이후 메인 이벤트 후보로 남긴다.
6. **차량기지 도착:** 프롤로그 종료. 첫 확장 기능과 추가 객차의 종류는 별도로 정한다.

### 첫 구현 범위 제안

- 작은 기관차 한 대와 조작 가능한 인물
- 운전석·기관실·연료함 사이 이동
- 수동 출력·제동, 연료 소모·보충·고갈 시 정지
- 과열 전조와 출력 조절, 발화 시 대응의 최소 흐름
- 한 종류의 수리 미니게임
- 한 곳의 정차·제설·연료 탐색
- 무전 반복과 차량기지 도착

난방에 따른 움직임 저하, 철판 탈락과 성능 저하, 잡템 연소, 객차 확장은 전체 기획에 유지하되 핵심 반복 확인 후 붙이는 순서로 제안한다. NPC와 식량은 결정 전까지 첫 구현 범위에 포함하지 않는다.

## 5. 수리 미니게임 — 타이밍 입력

**사용자 확정:** 데바데 발전기 수리처럼 타이밍에 맞춰 버튼을 누르는 방식이다. 기존의 철판을 직접 맞추고 볼트를 조이는 조작 제안을 대체한다. 철판 고정이나 볼트 조이기는 수리 동작의 시각 표현으로 사용할 수 있지만, 핵심 입력은 타이밍 판정이다.

기본 흐름 제안: **수리 시작 → 타이밍 신호 → 적절한 순간에 버튼 입력 → 성공·실패 반응 → 수리 계속 또는 완료**.

성공하면 수리가 진행되고, 실패하면 작업이 잠시 끊기거나 진행도가 일부 줄어드는 방식을 검토한다. 입력 키, 판정 구간, 신호 발생 간격, 필요한 성공 횟수, 실패 비용은 아직 확정하지 않는다.

‘UI 없음’ 방향은 유지한다. 첫 프로토타입은 작업대에 부착한 기계식 계기의 바늘과 초록 구간으로 타이밍을 표현한다. SPACE로 입력하며 성공하면 실제 볼트 색이 바뀐다. 화면에 고정된 수리 팝업은 없다. 이 표현과 판정 폭은 플레이 후 조정한다.
