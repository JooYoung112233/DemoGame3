# 이미지 제거 체크포인트 검증

- 생성 PNG·PSD·시안·캡처와 Unity ArtSet 자산 삭제. 이미지 경로는 `.gitignore`로 커밋 제외.
- 기본 도형 화면과 원래 1인 직접 조작을 사용. 다인 작업 지시 실험은 비활성.
- Unity 컴파일: 오류 없음, up_to_date.
- `VerifyEastTrain.Rules`: 20개 통과.
- `VerifyEastTrain.Interactions`: 15개 통과.
- 자동 키 주입 검증은 이번 실행에서 통과하지 못했다. `VerifyEastTrainInput.Run`은 E 입력 단계가 실행별로 다르게 실패했고, `VerifyEastTrainPresentation.Run`은 Tab 표시 단계에서 실패했다. 포커스 설정 변경으로 해결되지 않아 해당 변경은 되돌렸다. 입력 자동화와 실제 플레이 입력의 추가 구분 확인이 필요하다. 이 두 검증을 통과했다고 간주하지 않는다.

이미지와 최종 화풍은 미정이다. 이 커밋은 프로토타입 체크포인트이며 최종 아트나 완성판 배포가 아니다.

## 후속 변경 · 빠른 커서 줌과 프로토타입 UI

- 프로토타입 HUD를 상시 표시하고 첫 출발 4단계 안내·다음 설비 화살표·F5 빠른 출발을 추가했다.
- 휠 입력 1칸에 크기 2 변화. 정규화된 1단위와 Windows 120단위 입력을 모두 처리한다. 커서 아래 월드 지점을 유지하며 수동 줌 후에는 캐릭터 이동으로 시점이 당겨지지 않는다. 휠 클릭으로 추적을 복원한다.
- `VerifyPrototypeHud.Run` 17개 통과: 160ms 줌 수렴, 커서 지점 오차, 수동 줌 유지, 전체 열차와 자동 주행 전방 시야, 상시 HUD 수치, 단계 전환과 빠른 출발 실제 상태 진행.
- 1920×1080 게임 화면에서 HUD·첫 출발 안내·F5 안내와 화살표 배치를 확인했다. 검수 캡처는 삭제하고 이미지 파일은 커밋에서 계속 제외한다.
- 이전 자동 키 주입 실패 기록은 그대로 유지한다. 이번 검증은 줌·입력 처리 함수와 상태 진행을 직접 검사한 것이며 자동 키 입력 검증 전체가 통과했다는 뜻은 아니다.

## 추가 수정 · 캐릭터 이동 시 추적 복귀

- 최신 사용자 지시로 정지 중에는 커서 중심 줌을 유지하되, 실제 보행·사다리 이동이 발생하면 카메라가 캐릭터 추적에 복귀한다. 선택한 확대 배율은 유지한다.
- 크게 축소한 수동 시점에서도 이동 후 추적한다. 이동하지 못하는 방향키 입력만으로는 커서 중심을 해제하지 않는다.
- 새 Play 상태에서 `VerifyPrototypeHud.Run` 21개 통과. 정지 시 커서 지점 유지, 보행 후 수평 추적, 배율 유지, 사다리 수직 추적, 넓은 수동 배율에서 추적을 확인했다. Unity 컴파일 오류 없음.
