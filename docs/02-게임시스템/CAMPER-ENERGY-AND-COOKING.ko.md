# 캠핑카 에너지 운영과 요리 미니게임

2026-09-11 대화 기록. 아래의 **확정 방향**은 사용자 승인 사항이며 **요리 시안**과 수치·이벤트 순서는 후속 검토안이다. Unity 로직·콘티 데이터·자원 경제에 적용 완료한 문서는 아니다. 대사는 사용자가 대사집에서 수정한다.

## 확정 방향 — 자원을 어디에 쓸지 선택

| 대상 | 사용하는 자원 | 역할 |
| --- | --- | --- |
| 차량 이동 | 공용 연료 | 다른 장소로 이동해 물자·단서·이벤트 탐색 |
| 발전기 | 차량과 같은 공용 연료 | 배터리 충전. 가동 소음은 주변 반응 이벤트로 연결 |
| 수동 발전 장치 | 게임 시간 | 연료 없이 최소 전력 확보. 획득·복구를 이벤트로 연결 |
| 전자레인지 | 배터리 전력 + 간편식 | 가열 연출 후 식사. 미니게임 없음 |
| 가스레인지 | 별도 가스 자원 + 식재료 | 요리 미니게임으로 직접 식사 만들기 |

- 차량·발전기는 **동일한 연료 재고**를 차감한다. 사용자가 이동과 충전 사이에서 선택한다. 연료 종류·단위·실제 장치 모델은 미정이며 이 문서는 게임 자원 분류다.
- 가스와 공용 연료는 별개다. 가스 부족으로 직접 요리를 못 하는 상황을 두어 가스 확보 탐색의 동기를 만든다. 가스를 무한으로 사용하거나 부족 설정을 없애지 않는다.
- 전자레인지는 무료 우회 수단이 아니다. 간편식과 충분한 배터리 전력이 필요하다. 수동 발전은 최소 전력을 위한 시간 비용 대안이며, 전자레인지를 무제한 사용하게 하는 수단으로 설계하지 않는다.
- 발전 전 소모 연료·예상 충전량·남을 연료를 제시한다. 목적지가 선택되어 있으면 사용 후 그 목적지까지 이동 가능한지도 알려 준다. 선택되지 않았으면 목적지 선택 안내를 하며 임의로 이동 가능을 확정하지 않는다.
- 이동 여력을 없애는 발전을 무조건 금지하지 않는다. 자원 사용 결과를 알고 사용자가 선택하도록 한다.
- 공용 연료를 모두 썼을 때도 진행이 영구적으로 막히지 않도록 도보로 접근 가능한 비상 연료 확보 경로를 설계한다. 시간·위험 비용을 두되 무한 확률 실패로 탈출이 막히게 하지 않는다. 재고가 고갈되는 장소에서도 이 경로를 검토한다.
- 최초 목표는 전력·가스의 부족과 보급이 탐색 및 생활 이벤트로 이어지는 구조다. 소모량·충전 효율·소음 확률·배터리 용량은 아직 확정하지 않았다.

## 기존 시안 정리

- `design/minigames/fire-v1/`의 화덕·부채질 시안은 조작 실험으로만 보존한다. 캠핑카 요리 설비 또는 챕터 필수 이벤트로 채택하지 않는다.
- 가스레인지를 없애거나 휴대용 버너로 교체하는 방안은 확정하지 않았다. 기존 요리대 복구 흐름을 살리고, 가스 확보와 첫 요리를 연결하는 방향이다.
- 전자레인지에 불 조절 미니게임을 붙이지 않는다.

## 이벤트 연결 후보 — 순서 미확정

1. 기존 전력으로 간편식 데우기: 배터리 소모를 짧게 소개한다.
2. 요리대 복구와 가스 확보: 서로 다른 조건으로 표시하고 모두 충족하면 직접 요리를 해금한다. 이미 가스를 챙겼다면 다시 구하라는 퀘스트를 만들지 않는다.
3. 전력 부족: 발전기 확인 → 공용 연료를 이동/충전에 쓸지 선택한다.
4. 발전기 첫 가동: 배터리 충전과 소음의 대가를 경험한다. 가동 즉시 전투로 고정하지 않는다.
5. 수동 발전 장치 확보 또는 복구: 시간으로 최소 전력을 보충하는 대안을 해금한다.

기존 챕터의 사건·시간·필수 물자 보장과 대조한 뒤 이벤트 ID에 배치한다. 첫 주에 전부 강제 수행시키지 않는다. 라디오 등 서사 필수 진행을 자원 부족으로 봉쇄하지 않는 연결을 함께 검토한다.

## MG-02 요리 시안 — 냄비 한 끼: 끓이고 뜸 들이기

**후속: 사용자 시안 제작 요청으로 독립 브라우저 프로토타입을 제작했다. 최종 규칙 승인은 아직 아니다.** [구현 범위와 검증 기록](COOKING-MINIGAME-PROTOTYPE.ko.md)을 참조한다. 아래는 원래 구상이다.

### 진입과 비용

요리대 복구 완료 → 레시피·사용 식재료 선택 → 필요한 가스·게임 시간·예상 식사 확인 → 조리 시작. 부족한 자원은 시작 전에 표시한다. 가스/식재료 비용은 레시피별 고정량을 한 번 차감하는 초안이며, 미니게임 실패나 강불 선택으로 추가 차감하지 않는다. 가스 최적화와 입력 실수를 동시에 벌주는 부담을 피한다. 레시피별 수치와 기본 게임 시간은 미정이다.

### 조작

- 약불·중불·강불의 세 선택. 불은 선택 즉시 바뀌지만 냄비의 온도와 끓음은 서서히 따라온다.
- 조작 목표 약 15~20초. 플레이 시간과 게임 세계의 조리 시간은 별개다.
- 처음에는 데우기 단계. 중불이나 강불로 온도를 올리고, 작은 기포가 생기며 다음 단계가 가까워졌음을 알린다.
- 끓기 시작하면 자동으로 다음 단계로 넘어가고, 유지할 온도 구간이 낮아진다. 끓는 소리·기포·뚜껑 움직임과 짧은 문구로 전환을 함께 알린다. 강불을 계속 두면 끓어넘침 위험이 쌓인다.
- 다음은 익히기 단계. 약불·중불을 조절해 잔잔한 끓음을 유지한다. 열이 남으므로 끓어넘치기 직전까지 기다리기보다 미리 낮추는 판단이 핵심이다.
- 완료는 익힘 단계 종료 시 자동으로 불을 끄는 연출로 처리한다. 마지막에 추가 타이밍 판정을 붙이지 않는다.
- 적정 열기에서 보낸 비율로 작은 품질 보너스를 판정한다. 넘침은 보너스를 낮추지만 재료 전부 소멸이나 식사 전체 상실로 연결하지 않는 초안이다. 항상 약불로 방치하거나 계속 강불만 선택하면 최고 품질이 나오지 않아야 한다.
- 무작위로 목표 구간을 흔들지 않는다. 첫 레시피는 예측 가능한 두 단계로 배우고, 재미 확인 후 다른 요리의 가열 패턴을 검토한다.

### 결과와 연출

일반 완성 / 잘 만든 따뜻한 식사 두 결과부터 검토한다. 두 결과 모두 기본 식사량을 유지하고 성공 보너스는 한 종류의 작은 효과로 제한한다. 효과 종류·수치는 아직 미정이다. 미니게임 성공으로 감염 치료나 결말 분기를 직접 바꾸지 않는다.

가스 점화 → 작은 기포 → 끓음이 커짐 → 불을 낮추면 천천히 잦아듦 → 불 끄기 → 그릇에 담기. 조작 중에는 대사를 넘기는 입력을 요구하지 않고 식사 완성 후 사용자 대사집의 장면으로 연결한다. 조리 행동과 소품 조작은 수혁이 수행하며 현재 시점 소이의 객관적 물체 조작을 추가하지 않는다.

첫 시안은 냄비·불꽃·기포·세 단계 조절만으로 검증하고 새 원화는 조작 승인 후 제작한다. 기존 화덕의 부채질 조작과 화면은 재사용하지 않는다. 접근성은 색 외 상태 문구와 소리, 여유로운 온도 구간을 검토한다. 반복 레시피의 자동 조리는 별도 후속 결정이며 지금 확정하지 않는다.

### 검증 질문

- 끓기 시작했을 때 미리 불을 낮추는 판단이 재미있는가?
- 온도 반응이 느린 이유가 화면·소리로 이해되는가?
- 비용을 이미 지불한 뒤의 조작이 지나치게 부담스럽지는 않은가?
- 한 끼마다 반복해도 괜찮은 길이인가? 반복 생략이 필요한가?
