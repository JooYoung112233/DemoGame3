# 탑다운 제작·검수 절대 품질 규칙

2026-10-06 사용자 지시. 적용 범위는 demo6 원본 프로젝트의 모든 새 리소스, 기존 리소스 수정·교체·적용, 캐릭터·무기 모션, 이펙트, 환경, 월드 표시 UI다. 이 규칙은 프로젝트 품질 기준이며 상위 안전·권한 정책을 우선하지 않는다. 기존 작업 범위·승인·원본 보존 규칙을 유지한다.

## 매번 제작 전에 정할 것

1. 원본 해상도, Aseprite 분리 레이어, 실제 표시 크기, 피벗, 지면 접점, 기존 충돌·광원 보존 범위를 확인한다.
2. 지면 좌표와 시각적 높이를 구분한다. 정수리 투영에서 보일 면과 가려질 면을 정하고, 앞/뒤/좌/우 및 대각 방향에서 검토한다. 화면 Y만 움직여 높이처럼 보이게 한 경우도 발·그림자·그립과의 관계를 확인한다.
3. 각 부품의 sorting layer, order, 부모 SortingGroup, YSort, 재질/render queue 및 어둠/시야 처리 경로를 확인한다. 숫자 하나의 대소만으로 서로 다른 layer/group의 최종 가림을 판정하지 않는다. 카메라나 광원을 바꿔 오류를 숨기지 않는다.

## 대상별 필수 판정

| 대상 | 통과 조건 | 실패 예 |
|---|---|---|
| 바닥 Telegraph·범위·선택 마커 | 지면에 놓이고 겹친 발·몸·머리의 불투명 부분에 가려짐. 원/반원/띠의 채움·테두리·진행선 모두 확인 | 어둠보다 위에 표시하려고 높은 order로 올려 캐릭터 정수리 위에 원이 보임 |
| 지면 예고와 시야/어둠 | 밝은 곳·어두운 곳·시야 경계에서 동일한 높이 관계, 필요한 범위 판독 유지 | 본체 가림을 없애서 가독성을 확보하거나 예고가 바닥 아래로 사라짐 |
| 무기·손 | blade face(넓은 면)/edge(날)의 각도와 높이가 정수리 투영에 맞고 손이 그립에 붙음. 몸/머리 관통 없이 앞뒤 전환 | 칼의 면이 카메라를 향한 채 고정, 손에서 분리, 회전 도중 몸통을 뚫음 |
| 등 장식·장비 | 등의 부착점·정수리 투영·높이에 따라 몸/머리/무기와 일관되게 가림 | 옆모습 장식을 그대로 붙이거나 모든 방향에서 최상단 표시 |
| 그림자 | 지면 접점 기준, 점프·높이·회전과 일관됨 | 머리/장비에 붙어 떠다님 |
| 환경·캐릭터 | 같은 정수리 시점, 높이와 접점 기준의 앞뒤 중첩 | 기둥/문/상자는 옆모습인데 캐릭터만 정수리 시점 |
| 월드 UI | 지면 표시/머리 위 표식 등 의도한 높이·가림 정책을 명시하고 겹침 확인 | 월드 표시를 화면 고정 HUD처럼 무조건 최상단에 올림 |

화면 고정 HUD 자체에 지면 sorting을 강제하지 않는다. 월드 좌표를 따라다니는 게이지·표식·이름과 HUD를 구분하고 각각의 의도한 가림을 기록한다. 새로운 UI 배치나 반응형 개선을 이 규칙만으로 승인하지 않는다.

## 모든 새 작업의 완료 조건

- 원본 프로젝트의 고정 게임 카메라, 실제 Game View 출력 해상도/배율, 씬, 조명/시야 조건을 기록한다. 확대 보드는 보조 자료다.
- 캐릭터와 해당 오브젝트를 실제로 중첩시켜 발·몸·머리의 중앙과 경계에서 확인한다. 둘 이상의 캐릭터, 환경 앞/뒤, 방향 변화(상하좌우·대각)를 확인한다.
- 모션은 대기→준비→타격→회복 및 전환 구간을 정상 속도로 확인한다. 바닥 예고는 시작·진행·완료와 원/반원/띠, 어둠 경로를 확인한다. 해당 없는 항목은 이유를 기록한다.
- 자동 결과와 시각 결과를 구분하여 변경 파일, 검수자, 시각 증거 경로, 통과/실패/미검수, 남은 오류를 남긴다. 가려져야 할 면을 확인하지 못했거나 위험이 미해결이면 완료 처리하지 않는다.
- 최종 GIF가 필요하면 대표 동작의 연속 10프레임만 제공한다. 정상 속도 전체 구간 검수와 납품 GIF 길이는 별개다.
- Unity는 지정 소유 세션 하나가 다룬다. 미저장 씬·입력·Play 상태를 보존하며 합성 입력을 실제 사용자 조작 성공으로 보고하지 않는다.

## 자동 검사와 로컬 변경 훅

프로젝트 루트에서 Node.js로 실행한다. 추가 패키지·Unity 호출·네트워크·보안 설정 변경이 없다.

```powershell
node AgentScripts/topdown-quality/check.cjs
node AgentScripts/topdown-quality/check.cjs --watch
node AgentScripts/topdown-quality/selftest.cjs
```

첫 명령은 저장된 소스의 알려진 Telegraph sorting 위험을 검사한다. `--watch`는 Node의 실제 `fs.watch`에 Assets, ProjectSettings, 아트 디렉터리를 연결하고 변경 뒤 검사기를 재실행한다. `.cs/.shader/.asset/.unity/.prefab/.meta/.png/.aseprite/.json` 등 제작 파일 변경을 감지한다. 초기 검사 뒤 `watch-ready`가 출력되어야 연결된 상태다. 터미널을 유지해야 하며 Ctrl+C로 종료한다. 재부팅·터미널 종료 후에는 자동 실행되지 않는다. Git/앱/Unity의 상시 훅으로 설치한 것은 아니다. 파일 감시는 OS 이벤트 누락 가능성이 있으므로 완료 직전 첫 명령을 반드시 다시 실행한다.

자동 범위는 **저장된 Telegraph.cs의 NewChild 마지막 인자(정수 상수, +/-, 조건 분기)와 YSort 기본 order의 보수적 비교**, 규칙 링크 존재, 입력 해시다. 기본 actor order 이상인 지면 예고 경로는 `risk`로 보고한다. 현재 알려진 `AboveDarkOrder=14500` 회귀를 찾기 위한 제한된 정적 검사이며 전체 C# 해석기나 렌더러가 아니다. layer/group 변경·동적 식·새로운 구현 패턴은 `unknown`으로 남긴다. 낮은 order라도 실제 actor 위치·부품 offset·환경·재질 때문에 잘못 가릴 수 있다.

종료 코드: 0=검사 범위 내 위험 미검출(시각 통과 아님), 1=알려진 위험, 2=검사 입력 누락/해석 불가/예상 구조 변경. 감시 중에는 종료하지 않고 각 검사 결과에 코드를 기록한다. 모든 결과에 `visualReview: required`가 붙는다. 새로운 렌더 경로가 생기면 담당자가 검사 범위를 갱신하고 시각 검수한다.

정수리 그림의 투영 정확성, blade face/edge, 파지·몸 관통, 실제 SortingGroup/재질·YSort 적용 결과, 시야, 플레이 중 동적 상태, 최종 픽셀 가림은 자동 판정하지 않는다. 위 완료 조건에 따라 수동 시각 검수해야 한다.

## 연결 및 검증 증거

- 조사 시 demo6의 `.agents/.codex` 훅 설정은 없었고, 상위 `.agents/skills/unity-pipeline/SKILL.md`에 명시된 연결은 Unity CLI의 `run_script`/`run_tests`였다. 상위 `.claude/settings.local.json`에는 훅이 없었다. Git 훅은 LFS용이며 그대로 보존했다.
- Unity 재컴파일을 유발하는 Assets/Editor 코드는 추가하지 않는다. 이 검사기는 Assets 밖에 있으며 씬·입력·Play를 건드리지 않는다.
- `selftest.cjs`는 원본 Unity 프로젝트를 복제하지 않고 작은 텍스트 fixture로 높은 order 검출, 낮은 order 미검출, 해석 불가 분리, 실제 감시 이벤트→재검사 연결을 검증한다. fixture는 검증 폴더에 남겨 증거로 보존한다.
- 실제 실행 결과는 [검증 기록](../검증/topdown-quality/verification.json)에 기록한다. fixture 결과와 원본 소스 검사 결과를 구분하며 시각 검수 증거로 쓰지 않는다.
