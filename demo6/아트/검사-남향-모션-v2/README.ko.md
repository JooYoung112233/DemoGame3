# 검사 남향 모션 v2

> **2026-10-02 사용자 미채택:** “탑다운이 아닌데?”, “너무 어색한데 아무리 봐도” 피드백. 카메라가 정면에 가깝고 프레임별 비례·형태 일관성이 부족하다. 이 묶음은 실패 시안 이력이며 후속 제작의 승인 기준으로 사용하지 않는다. 기술 검사 통과를 시각적 완성으로 판단한 것은 잘못이었다.

2026-10-02. 전달받은 보행 참고의 정면 행을 기준으로 다시 만든 **모션 시안**. 대기·걷기·달리기·아래 방향 베기와 시작/정지 연결을 포함한다. 사용자 미술 승인이 완료되었다는 의미는 아니다.

## 확인 파일

- `four-motions.gif`: 네 동작 동시 재생. 위쪽 대기/걷기, 아래쪽 달리기/공격.
- `transitions.gif`: 대기 → 걷기 → 달리기 → 걷기 → 정지 → 공격 → 대기, 13초.
- `preview.html`: 버튼 또는 숫자 1~4로 동작 전환. 같은 폴더를 로컬 서버로 열면 된다.
- `review/`: 동작별 GIF와 프레임 나열 이미지.

## 실제 구성

| 동작 | 재생 프레임 | 서로 다른 원화 | 주기 |
| --- | ---: | ---: | ---: |
| 대기 | 8 | 5 | 1.40초 |
| 걷기 | 8 | 8 | 1.00초 |
| 달리기 | 8 | 8 | 0.52초 |
| 아래 베기 | 8 | 7 | 0.80초 |

중립 원화는 대기/공격에서 공유한다. 시작용 2장을 정지에서도 역순으로 사용하여 **개별 PNG 원본 총 29장**이다. 원본은 `sources/`, 재생 순서는 `clips.json`, 정렬 정보는 `anchors.json`과 `anchor-overrides.json`에 있다. `frames/`에는 투명 1536×1536 출력, `sheets/`에는 4열 투명 시트를 보관한다.

내장 **image_gen**으로 포즈를 개별 재작화했다. 사용한 프롬프트와 참조 프레임은 `prompts.json`에 기록했다. 코드에서는 전신 그림의 위치와 동일 비율 크기만 정렬하며, 팔·다리를 늘이거나 두 포즈를 투명하게 겹쳐 움직임을 만들지 않는다. 선택하지 않은 오류 원화는 `rejected/`에 별도 보관했다.

## 참고와 검수

- 사용자 제공 인체 보행 시트: `reference/user-walk-directions.png`, 두 번째 정면 행.
- [전달받은 Reddit 가이드](https://www.reddit.com/r/PixelArt/comments/1jo3bvq/8_direction_top_down_character_guide/)
- [원작자 SLYNYRD 설명](https://www.slynyrd.com/blog/2025/3/24/pixelblog-55-top-down-character-animation)
- 정면과 윗면이 보이는 시점, 좌우 착지/통과 포즈, 무릎 굽힘, 발바닥 방향을 확인했다. 최종 공격은 화면 오른쪽의 보호대 없는 어깨에서 이어진 팔이 계속 검을 쥔다.
- `verification.json`: PNG 크기·알파·해시, 출력 경계와 GIF 프레임/시간.
- `continuity-checks.json`: 72개 상태/프레임 전환 검사, 공격 후 대기 복귀. 걷기↔달리기는 같은 다리의 통과 포즈에서 전환한다.

## 현재 한계

- 원본은 1024×1536. 실제 인물 높이는 포즈마다 다르며 행동 원화 목표 1536~2048px에 미달한다. 1536 정사각 출력은 배치 캔버스이며 새로운 디테일을 복원한 고해상도 원본이 아니다.
- 프레임마다 머리/옷의 세부 모양과 붓질이 조금 달라 보인다. 포즈와 방향을 검토하는 시안이며 게임 최종 애니메이션 품질 확정본은 아니다.
- 몸·검·방어구가 한 프레임에 합쳐진 원화다. 프레임별 PNG는 독립적으로 교체할 수 있지만 장비 교체 레이어나 실제 분리 PSD는 아직 없다.
- Unity에는 아직 적용하지 않았다. 시안의 정지/공격 요청은 보행 주기를 마친 뒤 연결되어 최대 약 1초 기다릴 수 있다. 전투 입력 반응 속도를 정한 구현은 아니다.
- 기술 검사 통과는 자연스러운 움직임에 대한 사용자 승인을 대신하지 않는다.

## 재생성

번들 Node에서 `build.mjs`, 번들 Python(Pillow)에서 `package.py`, Node에서 `verify.mjs` 순으로 실행한다. `build.mjs --partial`, `package.py --partial`은 완성된 동작만 출력한다. 원본 그림은 덮어쓰지 않는다.
