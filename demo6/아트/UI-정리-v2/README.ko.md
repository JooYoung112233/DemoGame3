## 적용한 구성

- 20칸, 5×4 격자. 빈 칸을 항상 보이고 1아이템=1칸을 유지했다. 기존 G 바로 장착으로 생기는 용량 초과분은 스크롤로 보존한다.
- 현재 구현된 장착 부위는 무기 1곳이다. 장검·대검·쌍검만 장착 규칙에 연결했다. 방어구·악세서리 부위나 규칙, 가방 용량을 추가하지 않았다.
- 무광 철제 프레임, 가죽 안감, 오목한 슬롯, 절제한 모서리 장식, 인물 안내 그림을 연결했다. 프레임은 9분할로 그려 모서리 크기를 유지한다.
- 등급은 기존 색상과 이름을 유지한다. 내부 색은 일반 9%, 선택 14%, 상세 10% 투명도로 깔았다. 아이템 원본 색은 바꾸지 않는다. 선택은 뼈색 모서리 표식, 등급은 1~5개 점도 함께 표시한다.
- 선택 상세의 아이템명은 고딕 굵은 글씨와 줄바꿈을 사용한다. 능력치 값은 오른쪽으로 정렬한다. 내용이 길어지면 상세 영역을 스크롤한다.
- 장착 요약/HUD의 좁은 한 줄은 말줄임한다. 가방 장착명은 전체 이름을 툴팁에 보존하고, 툴팁 높이도 문자열에 맞춰 계산한다. 획득 카드에서 여러 줄 이름 아래에 공격 비교를 배치한다.
- 추후 악세서리가 늘어날 때도 `DungeonUi.Slot`, `UiSkinArt`, `ItemIconArt`와 현재 아이템 슬롯 그리기를 재사용할 수 있다. 새 부위를 미리 표시하는 변경은 하지 않았다.

## 폰트 — 추천과 실제 적용

현재 Windows 환경에서 실제 사용할 수 있는 **제목: 바탕(Batang), 본문·아이템명·능력치: 맑은 고딕(Malgun Gothic)** 조합을 선택했다. 분위기는 제목에 집중하고 조작/수치 정보는 고딕으로 읽히게 했다.

900 기준 좌표에서 제목 25, 상세 아이템명 23 Bold, 본문 18, 보조 글 16이다. 720p/1080p에서는 화면 높이에 따라 같은 비율로 표시한다. 닫기 기호 ×는 가운데 정렬한다.

`C:/Windows/Fonts/batang.ttc`, `malgun.ttf`, `malgunbd.ttf`를 읽어 가족명, 스타일, Microsoft 제공 폰트 라이선스 문구 및 OS/2 메타데이터를 확인했다. [폰트 증거](검수/font-evidence.json), [Unity 사용 후보/크기](검수/font-runtime.json).

폰트 파일은 다운로드·설치·프로젝트 복사하지 않았다. 현재 방식은 설치된 OS 폰트를 동적으로 사용한다. `Assets` 전체의 TTF/TTC/OTF/FNT/fontsettings 및 폰트 이름 자산을 검색했으며 프로젝트에 포함된 한글 폰트가 없었다. 설치된 바탕이 없으면 기존 명조 후보, 맑은 고딕이 없으면 기존 고딕 후보를 사용하지만 이 후보도 OS 설치 폰트다. **따라서 한글 폰트가 없는 다른 PC/게임 빌드의 한글 표시를 보장한 상태는 아니다.** 현재 확인은 로컬 Windows 환경이며, 재배포 가능한 한글 폰트 포함은 남은 배포 작업이다.

## 공통 닫기

`DungeonUi.CloseButton`으로 우측 위 짙은 빨간 사각형 ×를 통일했다. 각 창의 기존 닫기 메서드를 호출하여 일시정지와 공격 차단 해제를 유지한다.

| 창 | 연결 |
|---|---|
| 장비와 가방 | `Inventory` → `DungeonUi.Close("bag")` |
| 지도 | `BigMap` → 지도 닫기 |
| 스킬 | `SkillPanel` → 스킬 닫기 |
| 쪽지 | `StoryItem.CloseModal` |
| 도시락 사건 | `LunchboxEvent.CloseModal` — 선택 확정 없이 닫기 |
| 말뚝 메뉴 | `Stake.CloseMenu` |
| 개발 탐험 기록 | `ExplorationLog.PanelVisible=false` |
| 층 기록 | `ExplorationLog` 요약 창 닫기 |
| 귀환 결과 | `NightCard`의 기존 결과 확인 경로 — 밤 진행으로 연결 |

기존 Esc/F1/M/K/I 동작은 유지했다. 귀환 결과의 ×는 기존 ‘밤을 보낸다’와 같은 진행 동작이므로 툴팁도 그렇게 표시한다. 필수 승강장 선택, 밤 전환 연출, HUD에는 취소/닫기 규칙을 새로 만들지 않았다.

독립 PNG 원본 **11종, 각각 1254×1254**를 만들었다. 작은 시트나 검수 화면을 확대한 원본이 아니다.

| `wpn_longsword`, `wpn_greatsword`, `wpn_twinblades` | 장착 칸·가방·상세·바닥 획득 카드 |

- 패널/슬롯은 가죽과 철테를 분리했다. 무기 3종은 칼날 영역과 손잡이·가드 영역을 마스크로 분리했다. 다시 합친 픽셀은 원본과 차이 0이다.
- 나머지 보조 아이템/인물은 ‘painted original’ 평면 그림과 빈 보정 레이어다. 재질별로 분해된 그림이라고 보고하지 않는다. 무기 레이어도 영역 마스크 분리이며 가려진 내부를 새로 그린 것은 아니다.
- [합성 검증](원본/source-validation.txt). PSD는 이번 납품에 포함하지 않았다.
- 게임 PNG: `Assets/Resources/UI/Items` 512×512, `UI/Skin/panel.png` 1024×1024, `slot.png` 512×512, `button.png` 128×128. 버튼은 프레임 원본 재사용이다.
- UI 전용 텍스처로 Bilinear, 무압축, mipmap 없음, Clamp 설정이다. 월드 스프라이트 PPU 규격을 UI에 적용하지 않는다.

확인 완료:

- I/Esc 재열기, K/M/F1, 창의 시간 정지·공격 차단과 닫힌 뒤 해제 확인. 개발 패널 위 공격 차단, 게임 중앙 공격 입력 구분 확인.
- 실제 `Inventory.Equip` 콜백에서 가방 수 15 유지 및 이전 장비 보존 확인.
- 원본 PNG/Aseprite 합성 픽셀 차이 0. 씬 저장 없이 검수용 Play 데이터 폐기. 추가한 GameView 크기 항목 제거, 원래 크기 인덱스 6과 입력 설정 복원.
- `git diff --check` 오류 없음. 커밋 없음.

**남은 확인: 실제 포인터 클릭으로 선택→장착→각 × 닫기→재열기를 한 번에 수행하는 검증.** 자동 포인터/IMGUI 마우스 이벤트를 보냈지만 GUI가 클릭을 소비한 결과를 얻지 못했다. 이 부분을 통과했다고 보고하지 않는다. 콜백, 키보드 닫기, 화면 표시 검증과 분리하여 기록한다. 해당 자동 입력 실험은 `검수/imgui-mouse-events.jsonl`에 남아 있다.

구현 코드는 일반 `GUI.Button`과 각 창의 기존 닫기 경로를 연결한다. 사용자 포인터 환경에서 실제 클릭 검수는 아직 필요하다. 귀환 결과 ×에 의한 밤 전환 흐름도 이 포인터 검수에 포함한다.

### 후속 검수 — 실제 입력 도구와 재실행

- 실행 가능한 도구 목록에는 Windows 데스크톱 포인터 클릭 도구가 없다. Unity Pipeline 전체 명령을 추가 조사해 `simulate_pointer`/`simulate_key`를 발견했고 실제로 호출했다. 이 명령은 Input System 상태 이벤트를 주입하는 도구다.
- 임시 InputSettings 복제본에서 키보드·마우스를 활성화하고 백그라운드 입력을 허용했다. 3840×2160 화면에서 × 중심 `(3072, 1910.4)`에 `move → down → up`을 순서대로 보냈다. 좌표 원점은 왼쪽 아래다.
- 명령의 `Success=true`와 마우스 위치 갱신은 확인했지만 **클릭 전후 모두 `Modal="bag"`여서 닫히지 않았다.** `simulate_key`의 I/Esc도 이 명령 경로에서는 창 상태를 바꾸지 못했다. 현재 OnGUI/IMGUI까지 입력이 연결됐다고 볼 수 없어 실제 포인터 검수 통과로 기록하지 않는다.
- 닫기 검사 준비를 위해 가방을 코드로 열었고, 끝난 후 코드로 정리했다. 이 준비/정리 호출은 클릭이나 재열기 통과 증거가 아니다. 선택·장착·실제 포인터 입력 관통(레이캐스트) 검증도 미확인이다.
- [지원 입력 명령 원문](검수/supported-pointer-commands.json), [전후 상태](검수/supported-pointer-states.jsonl), [도구 조사](검수/desktop-input-capability.json).
- **Play 재실행에서 적용 유지 확인:** 검수용 장비를 추가하지 않은 새 실행(가방 0개, 시작 일반 장검)에서 20칸, 새 프레임/아이콘, 텍스트, 빨간 ×가 그대로 표시된다. [720p 재실행 가방](검수/720-restarted-bag.png), [1080p 재실행 가방](검수/1080-restarted-bag.png).
- 사건 창 하단 안내 높이는 27.265625 기준 픽셀로 28 높이 칸에 들어가며, 해당 칸 하단은 창 끝에서 24만큼 떨어져 있다. 720p/1080p 실제 화면으로 확인했다.
- 가방 개수·장착 장비·씬 변경 여부는 검수 전후 동일했다. 임시 해상도 항목을 제거하고 3840×2160(원래 인덱스 6), 일시정지·입력 차단·입력 설정을 복원했다. [화면 검수와 복원 기록](검수/final-followup-visual.json).
- 이 확인은 Play 재실행까지다. 별도 Player 빌드나 다른 PC의 폰트 표시는 검증하지 않았고 새 폰트를 설치·재배포하지 않았다.

검수 중 동시 작업의 `FloorGeneratorTests.cs`에 미완성 도우미 함수로 인한 일시적 컴파일 오류가 있었으나, 해당 작업의 함수가 추가된 뒤 마지막 재컴파일이 오류 없이 완료됐다. 이 테스트 파일은 UI 작업에서 수정하지 않았다.
