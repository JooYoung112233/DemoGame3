# 검사 남향 모션 시안 v1

> **미채택 · 2026-10-02:** 사용자가 동작이 이상하다고 피드백했다. 다리의 길이 변형과 팔·검 위주의 회전 때문에 보행·공격의 체중 이동이 표현되지 않았다. 아래 자동 검사는 파일과 전환 규칙의 검사이며, 자연스러운 움직임이나 사용자 승인을 뜻하지 않는다. SLYNYRD의 3/4 탑다운 캐릭터 가이드를 바탕으로 `../검사-남향-모션-v2/`에서 재제작한다.

2026-10-02. 탑다운 남향 검사에 대기, 걷기, 달리기, 아래로 베기 1종을 제작했다. 동일한 분리 원화와 관절을 공유하는 2D 컷아웃/메시 애니메이션이다. 손으로 각 프레임을 새로 그린 셀 애니메이션은 아니다. 미술·동작의 최종 사용자 승인 전 1차 시안이다.

## 바로 확인

- `four-motions.gif`: 네 모션을 나란히 실제 속도로 재생한다.
- `transitions.gif`: 대기 → 걷기 → 달리기 → 걷기 → 대기 → 공격 → 대기를 이어 재생한다.
- `preview.html`: 로컬 브라우저에서 1 대기 / 2 걷기 / 3 달리기 / 4 공격으로 임의 전환한다. 현재 로컬 미리보기 주소는 http://127.0.0.1:8126/preview.html 이다. 서버가 종료돼도 HTML 파일과 PNG 원본은 남는다.

| 동작 | PNG 프레임 | 한 주기 | 특징 |
| --- | --- | --- | --- |
| idle | 8 | 1.6초 | 발을 고정하고 상체와 팔의 작은 호흡 |
| walk | 12 | 1.0초 | 번갈아 내딛는 발과 반대편 팔 움직임 |
| run | 12 | 0.6초 | 큰 보폭, 빠른 주기, 팔 흔들림과 상체 움직임 |
| attack | 12 | 0.8초 | 검을 들어 준비 → 화면 아래로 베기 → 원래 자세로 회수 |

공격 첫 프레임과 마지막 프레임은 회수를 위해 동일하다. 12장 중 서로 다른 그림은 11장이다. 루프 프레임은 마지막에 첫 장을 중복 삽입하지 않았다. GIF는 동일한 연속 프레임을 하나로 합치고 표시 시간을 보존하므로 GIF의 내부 프레임 수와 원본 PNG 수는 다르다.

## 동작 연결

- 공통 캔버스·관절·인물 크기를 사용한다. PNG마다 개별 자동 크롭이나 재중앙 정렬을 하지 않았다.
- 대기 → 이동은 0.18초 동안 현재 관절 자세에서 다음 자세로 연결한다.
- 걷기 ↔ 달리기는 진행 중인 발 주기를 유지한다. 전환 때 첫 프레임으로 리셋하지 않는다.
- 이동 → 대기는 0.22초 동안 보폭과 팔 자세를 회수한다.
- 공격 진입은 0.12초 연결한다. 끝나면 자동으로 대기로 복귀한다.
- 이미지를 겹쳐 흐리게 만드는 크로스페이드 대신 관절 값을 보간한다. 연결 중간 프레임은 런타임에 만들어지며 44장의 루프/공격 PNG와 별도다.
- 이동은 제자리 동작이다. 게임 좌표 이동과 발 속도 동기화, 판정·피격·효과음·Unity Animator 연결은 이번 모션 제작에 포함하지 않았다.

## 원본과 편집

- `sources/`: 내장 **image_gen**으로 만든 분리 원화 5개. 머리 1247×1261, 나머지는 1024×1536 RGBA 원본이다. 확대 보간하지 않았다.
- `prompts.json`: 실제 프롬프트 5개와 참조 파일 경로.
- `regions.json`: 머리, 몸통, 좌우 팔, 좌우 다리, 검의 원본 영역 7개. 팔과 다리 원본은 각각 좌우 2개 부위를 포함하고 있으며 재생 시 독립 관절로 취급한다.
- `rig.js`: 자세, 관절 변형, 검의 손 부착, 모션 전환을 수정하는 원본 코드.
- `frames/`: 1536×1536 투명 PNG 44장. 프레임당 실제 인물 높이는 대략 1020~1100px이며 빈 여백을 포함한 캔버스가 1536px이다. 확대용 최종 고해상도 인물 원화 목표에 도달했다고 주장하지 않는다. 큰 분리 원화를 별도로 보관했다.
- `sheets/`: 원본 프레임을 축소 없이 4열로 묶은 시트. idle 6144×3072, 나머지 6144×4608. 수정 원본은 작은 시트에서 자른 그림이 아니라 위 분리 원화와 리그다.
- `animation-manifest.json`: 프레임 순서, 주기, 고정 기준점, 연결 시간.
- 실제 레이어 PSD는 미제작이다. PNG의 알파와 7개 독립 파츠는 원본·영역·리그 코드에서 편집할 수 있다.

## 검수와 한계

- 출력 44장의 크기, 투명 모서리, 실루엣의 프레임 밖 잘림 여부를 검사했다. 네 동작 모두 잘림 없음.
- 공격 시작/종료 자세 일치, 대기·걷기·달리기 루프 이음새, 걷기/달리기 발 주기 유지, 여덟 전환 경로와 공격 자동 복귀를 검사했다.
- 공격·걷기 시트를 육안 검수했고 브라우저에서 대기·걷기·달리기·공격 및 자동 복귀를 확인했다. 검수 파일은 `verification.json`, `continuity-checks.json`, `transition-trace.json`이다.
- 원화의 동일성을 유지하는 컷아웃 방식이므로 큰 동작에서 팔꿈치와 옷의 종이 인형 같은 변형은 남아 있다. 큰 관절 회전마다 옆면/뒷면을 새로 그리는 방식은 아니다. 접지와 동작 전환은 확인했지만 미술적 자연스러움의 최종 승인은 사용자 검토 사항이다.
- 원래 탑다운 단일 원화와 Unity 프로젝트 씬은 보존했다.

## 재현

1. Node와 `playwright`, `sharp` 사용. `build.mjs`의 `CODEX_NODE_MODULES` 환경 변수로 패키지 경로를 바꿀 수 있다. 로컬 Edge 헤드리스 렌더러를 사용한다.
2. `node build.mjs export`로 원본 프레임·시트 전 단계의 검수 렌더·HTML·manifest를 출력한다.
3. Pillow가 있는 Python에서 `python package.py`로 렌더된 프레임을 GIF와 시트로 포장하고 알파/잘림을 검사한다. 이 단계에서는 원화 내용을 새로 그리거나 수정하지 않는다.
4. `node verify.mjs`로 루프·전환 불변 조건을 확인한다.
