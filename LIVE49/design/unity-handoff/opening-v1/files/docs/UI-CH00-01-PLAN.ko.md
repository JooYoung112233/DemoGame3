# 챕터 0~1 · 상황별 UI 제작 계획

개발 연결: [이미지가 포함된 장면별 콘티·실제 원화 경로](CH00-01-STORYBOARD-ASSET-MAP.ko.md), [시작 흐름 인계](UNITY-OPENING-HANDOFF.ko.md). 앞으로 각 화면을 만들 때 장면 ID·원본·PSD·런타임 PNG·좌표·입력 조건·다음 장면을 함께 갱신한다.

2026-09-10 사용자 요청. 상황별 합성 화면을 보고 UI를 선택한다. UI 원본은 인게임 조합을 위한 투명 PNG와 실제 분리 레이어 PSD로 제작한다. 시작 화면은 **A(활자·얇은 선)를 사용자 채택**했으며 후속 UI의 공통 기준으로 삼는다. 기존 대화 시안의 따뜻한 갈색·크림색과 간결한 구성도 유지한다. 개별 화면의 배치와 정보량은 해당 장면에서 선택한다.

## 제작·선택 방식

- 사용자 확정 기본 게임 해상도: **1920×1080(16:9)**. 아래 3840×2160은 편집용 원본 크기다. 사용자에게 보여줄 게임 화면은 1920×1080, 레이아웃·텍스트·클릭 좌표도 1920×1080 기준으로 기록한다.

- 사용자 후속 명확화: **챕터 0부터 실제로 이어지는 장면 안에서 UI의 위치·구성을 파악하고 하나씩 제작한다.** 기능별 전체 화면 묶음이나 캠핑카 HUD부터 시작하는 순서는 채택하지 않는다.
- 첫 시작 화면에서 UI 화풍을 비교한다. 같은 배경·로고·메뉴로 A(활자·얇은 선)와 B(붓 질감·거친 선)를 비교하고, 선택한 느낌을 이후 화면에 이어 적용한다. 아래 기능 목록은 누락 방지용이며 제작 순서가 아니다.
- 배경 합성본은 검토용, UI PNG·PSD는 배경과 분리한다. 문자는 독립 검수 레이어와 문자열 데이터로 두며, 인게임용 패널 PNG에 이름·수치·대사를 굽지 않는다.
- 좌우 대화 인물의 표정·행동 원화는 대사집 이후 제작한다. 이번 UI 작업으로 인물 세트를 새로 생성하지 않는다.
- 미니게임 상세·시간 비용·게이지 최대치·회수 확률은 아직 미정이다. 배치 시안의 예시값을 게임 규칙으로 확정하지 않는다.
- UI 그래픽은 1920×1080 논리 좌표를 기준으로 2배인 3840×2160에서 직접 그린다. 기존 배경의 확대 합성은 화면 검토용이며 배경의 디테일이 복원된 원본이 아니다.
- 텍스트는 PSD에서 별도 래스터 레이어로 이동·숨김 가능하게 제공하고, 문장 수정은 문자열 데이터로 재출력하거나 Unity 텍스트에서 처리한다. Photoshop 라이브 텍스트·벡터 도형 레이어라고 표시하지 않는다.

## 납품 구조

`design/ui/ch00-01/` 아래 `psd/`(레이어 원본), `sprites/`(문자 없는 UI PNG), `layers/`(배치 레이어), `review/`(배경 합성), `manifest.json`(좌표·원본 크기·상태·용도), `strings.ko.json`(검수 문구)을 보관한다.

버튼은 기본/포커스/눌림/비활성 상태를 같은 캔버스와 여백으로 준비한다. 늘려 쓰는 패널은 9-slice 경계값을 기록한다. 마스크·게이지 채움·테두리를 분리한다. Unity에서 입력·키보드 이동·반응형·실제 상태 연결을 검증한 것으로 보고하지 않는다.
