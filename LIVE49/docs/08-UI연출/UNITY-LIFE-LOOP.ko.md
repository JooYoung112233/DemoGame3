# Unity 생활 UI와 진행 연결 · 2026-09-12

지도 후속 구현: [첫 지역 10곳과 분기 해금](REGION01-EXPLORATION.ko.md).

최신 사용자 지시: 별도 중단 요청 전까지 단계별 승인을 기다리지 않고 남은 순서대로 구현한다. 기존의 1단계씩 화면을 확인하던 진행 방식보다 이 지시를 우선한다. 이번 범위는 요리, 첫 지도 이동, 하루 마무리, 기록·목표, 저장·불러오기다.

## 실제 연결

- `00_Title`, `01_Game` 두 게임 씬을 유지한다. 캠핑카·편의점·생활 창을 새 씬으로 나누지 않았다.
- 기존 챕터 0 콘티 38개 노드를 런타임 데이터로 옮겼다. 첫 응답·스케치북 뒤 라디오 → 출발 준비 → 물·담요 → 정전 → 스위치·전원부 확인 → 복구 → 사진 고정 → 책 보관 → 첫 기록 → 자발적 취침 → 1일 차 아침으로 이어진다.
- 물·담요 및 스위치·전원부는 순서가 자유이며 완료한 행동을 다시 요구하지 않는다. 선택 관찰은 필수 합류를 막지 않는다.
- 장면 이미지는 기존 승인 원화 13개를 복사하여 Unity에 등록했다. 기존 원본을 편집하거나 새 원화를 생성하지 않았다. 사진의 얼굴 가림과 소품의 기존 구도를 유지한다. 아직 방송·생활 효과음·아침 전용 조명 연출을 제작한 것은 아니다.
- 빈 방송·사진 바람 대사는 이번 구현용 짧은 초안이다. 기존 대사는 유지했다. 원문 콘티 파일을 덮어쓰지 않고 `Assets/_Project/Resources/Live49/continuation.json`에 구현 초안을 표시했다. 정식 대사집 퇴고·음성 제작이 남아 있다.

## 요리

HUD 요리와 주방 행동에서 `ActivityPanel`의 가스레인지 화면을 연다. 가스·식재료 보유량, 비용, 결과 식사량, 시간, 시작 가능 여부를 표시한다. 차량 연료와 조리 가스를 구분한다.

`CookingSession`은 기존 `design/minigames/cooking-v1/core.mjs`의 데우기·익히기, 열기의 지연 반응, 세 불 조절, 품질 보너스 판정을 옮겼다. 시작 시 비용을 한 번만 차감한다. 완료 시 항상 식사 1개를 지급하고 불을 끈다. 불 조절로 추가 비용을 부과하지 않는다. 창 닫기와 포커스 이탈은 조리를 멈추며, 다시 열었을 때 명시적으로 이어서 조리한다. 조리 중 저장·지도 이동·하루 마무리를 막아 조리 재진입으로 차감이나 지급을 반복하지 못하게 한다.

가스 1·식재료 1·25분은 기존 시안의 임시 게임 단위를 유지한 값이며 최종 생존 밸런스가 아니다. 첫날의 요리대는 기존 콘티대로 고장 상태다. 실제 플레이에서는 수리 조건 안내가 나오고, 수리 해금과 가스 획득 사건의 상세 연결은 후속 기획이다. 검수는 분리된 임시 상태에서 해금·재료를 공급하여 조리까지 확인하며, 이를 실제 시작 재고로 남기지 않는다. 전자레인지·발전기·수동 발전은 이번에 구현하지 않았다.

## 이동·회수·하루 마무리

- 첫날 지도에서 작은 편의점을 선택하고 출발을 재확인하면 실제 장소·차량 위치·시간·연료 상태를 변경한다. 짧은 암전 후 편의점 화면을 보여준다. 이미 가게 앞에 주차한 경우 재이동·재차감을 막는다.
- 초기 공용 연료 3, 첫 이동 연료 1은 진행 검수용 잠정값이다. 20분 이동, 5분 간단 탐색, 생수 2·포장 식량 2 확보는 기존 첫날 시안 값을 따른다. 수치를 최종 확정한 것으로 해석하지 않는다. 후속 연료 공급·발전 경제 및 비상 연료 경로는 아직 없다. 현재 연결된 차량 이동은 첫 편의점 노선뿐이다.
- 편의점의 냉장고·식품 선반은 눈에 보이는 보장 물품만 한 번 회수한다. 확인 전 취소는 비용이 없고, 중복 클릭·재방문으로 물품을 복제하지 않는다. 추가 확률 탐색·미니게임·문구대·NPC 사건은 이 범위에 없다.
- 물품을 찾기 전에도 바로 앞 캠핑카로 돌아올 수 있다. 캠핑카와 편의점 출입은 차량을 다시 운전하는 것으로 처리하지 않는다.
- 챕터 0은 준비·복구·기록을 마친 취침 지점에서 하루 마치기를 허용한다. 이후는 캠핑카에서 확보 조건을 확인하고 취침 확정 → 암전 → 다음 날짜 → 자동 저장을 처리한다. 가방과 완료 기록을 유지한다. 49일 차 이후의 날짜 증가는 막는다.
- 다음 날짜의 이야기·소모·회복을 모두 만든 것은 아니다. 현재 첫날 이후 날짜 증가는 UI·상태 전이 기반이며 전체 49일 게임 완성으로 보고하지 않는다.

## 기록·저장

기록 화면은 선택한 첫 문장과 현재 목표, 완료한 준비·복구·확보 상태를 보여준다. HUD의 목표와 같은 상태를 읽는다. 첫 기록의 문장 선택에 정답·점수·엔딩 조건을 추가하지 않았다.

Esc 메뉴에 저장·불러오기 페이지를 추가했다. 탐색·행동 선택 대기 지점에서 한 슬롯에 수동 저장한다. 대화 도중과 미완료 조리 중은 저장하지 않는다. 저장에는 첫 응답·책 확인, 콘티 노드와 확인한 문장 위치, 준비·조사·선택 효과, 첫 기록, 날짜·분·차량 위치·출입 상태, 가방·공용 연료·요리대 해금을 포함한다. 게이지의 미정 초기값은 새로 만들지 않았다.

다음 날 전환은 같은 슬롯에 자동 저장한다. 임시 파일을 먼저 기록·검증하고 기존 파일을 교체하며 직전 파일을 `.bak`으로 보관한다. 버전·체크섬·데이터 범위·노드/문장 위치를 검사한다. 손상된 파일은 지우지 않고 읽기를 거절한다. 백업 자동 복구·다중 슬롯·클라우드 동기화는 아직 없다.

불러오기는 미저장 진행을 되돌린다는 확인 뒤 실행한다. 기존 HUD와 조리 세션을 정리하고 실제 게임 씬에 저장 상태를 복원한다. 타이틀의 이어하기도 같은 경로를 사용하며, 저장이 없거나 읽을 수 없으면 이어하기를 숨긴다. 새 게임은 기존 저장 파일 자체를 지우지 않는다.

실제 저장 경로는 `Application.persistentDataPath/Live49/journey-v1.json`이다. 검수 스크립트는 Editor 전용 경로 재지정으로 `Screenshots/JourneyReview/` 아래에 저장하여 사용자 슬롯을 덮어쓰지 않는다.

## 검수 기록

`AgentScripts/VerifyJourney.cs`가 시작 화면부터 첫날까지의 콘티, 지도 출발 확인·중복 차감, 출입·회수, 저장·로드·타이틀 이어하기, 조리 중단·재개·지급, 하루 전환을 실제 UI와 진행 입력으로 검수한다. `Screenshots/JourneyReview/report.txt`와 화면 캡처에 실행 결과를 기록한다. 전체 검수 완료 여부는 이 보고서의 마지막 결과를 따른다.

최종 결과: 전체 진행 검수 `PASS ALL`. 손상 파일 예외 처리와 새 배경 효과의 초기화 순서 오류를 수정한 뒤 통과했다. `ReviewJourneyScreens`는 저장한 2일 차 상태에서 장소명 크기, 실제 행동 버튼의 포인터 입력, 가게 출입·복귀, 기록 완료 문구, 저장·주방 텍스트 넘침 없음과 수리 전 조리 차단을 추가 확인했다. 완료 표시의 미지원 체크 글리프를 한글 문구로 교체하고 행동 버튼의 어두운 바탕을 보강했다. `visual-report.txt`도 PASS이며 최종 게임은 검수용 재고를 제거한 기록 화면에 열어 두었다.

`06-cooking.png`, `07-cooking-result.png`는 일시적으로 수리 해금·가스·식재료를 공급한 검수 화면이다. 실제 플레이 시작 재고로 채택한 화면이 아니다. 편의점은 기존 배경으로 연결했으며 회수 전후 개별 물품 원화·추가 탐색 동작의 세부 연출은 후속이다. 이번 검수는 Unity Editor 플레이이며 독립 플레이어 빌드 검수는 별도다.
