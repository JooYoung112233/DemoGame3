# demo5 인게임 UI 전체 시안 v1

[전체 시안 열기](index.html) · [제작 목록](제작목록.md) · [설계 기준](설계기준.md) · [화면 연결과 상태](화면흐름과상태.md)

## 범위
승인된 종이 질감을 기준으로 **20종 검토본**을 제작했다. 01~17은 상황별 화면, 18~20은 여러 상태를 묶은 보드다.
각자 가방과 공용 창고, 출발 준비, 오브젝트 작업 배정, 탐색, 전투, 귀환, 생활 관리, 공통 메뉴까지 연결한다.
이번 신규 화면은 사용자 개별 검토 전이다. 기본 질감 승인과 화면별 승인 여부를 구분한다.

## 보는 방법
index.html을 브라우저에서 열면 설치 없이 볼 수 있다. 구간 필터·검색·확대·이전/다음 방향키를 지원한다.
manifest.json이 최종 파일 목록이다. v2가 있으면 갤러리는 v2를 보여주며 v1도 비교용으로 보존했다.
생성 프롬프트와 수정 프롬프트를 각각 저장했다.

## 검수 및 수정
- 03: 실제 16칸 가방과 용량 문구를 맞췄다.
- 05: 휴식으로 피로가 감소하도록 전후 표시를 수정했다.
- 06: 확정하지 않은 최대 2명 제한 문구를 제거했다.
- 07: 손전등 보유와 미보유가 동시에 뜨던 상태를 정리하고 수색도를 추가했다.
- 11: 전투 아이템 화면의 보드를 각 진영 3×3으로 맞췄다.

## 개발 시 적용 기준과 한계
- PNG는 모두 생성 원본을 그대로 보관한다. 원본 해상도는 manifest에 기록하며 기본 게임 해상도 1920×1080보다 작다. 단순 확대로 디테일을 복원했다고 간주하지 않는다.
- **평면 검토 이미지이며 실제 투명 레이어·PSD·Unity 프리팹이 아니다.** 글씨·수치·아이콘이 합쳐져 있다. 승인 후 UI용 개별 요소를 제작해야 한다.
- 초기 2명, 시안의 후보 6명, 작업 패널의 눈에 보이는 카드 수를 전체 대원 상한으로 사용하지 않는다.
- 가방 칸 수는 화면별 예시다. 대원별 용량 데이터를 사용할 때 모든 화면이 동일한 값을 참조해야 한다.
- 야간 배정 화면의 침대 경고와 합계, 하루 결과, 날짜, 수치 및 문구는 예시다. 실제 배정 인원과 시설 슬롯을 계산하여 표시한다.
- 시안 속 새 초상·적·지역 배경은 UI 문맥을 위한 임시 그림이다. 기존 승인 캐릭터·배경 자산을 대체한 것이 아니다.
- 배경에 합쳐진 명암을 최종 조명으로 쓰지 않는다. 제작용 배경·UI·캐릭터를 분리하고 URP 2D 조명을 적용한다.
- 캐릭터와 시설은 데이터 목록으로 확장한다. 조작 흐름·소유권·시간 처리·취소/오류 상태는 설계 문서가 기준이다.
- 게임 코드·씬·실행 빌드는 이번 리소스 검토 작업에서 변경하지 않았다.
- 이미지 20종을 읽어 해상도와 파일 경로를 검사했다. 앱 브라우저 보안 정책이 로컬 HTML 접근을 막아 갤러리의 실제 브라우저 동작 검증은 미완료다.
