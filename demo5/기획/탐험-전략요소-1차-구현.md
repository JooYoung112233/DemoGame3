# 탐험 전략 요소 1차 구현: 굴이 비는 틈

> 상태: 2026-09-24 1차 구현. 수치와 이름('그것', 위험도, 오래 머묾, 숨죽이기)은 모두 임시입니다.
> 설계는 [탐험 전략 요소 설계안](탐험-전략요소-설계안.md)을 따릅니다. 이번에는 그중 **장소 판의 뼈대**만 넣었습니다.
> **밸런스 1차(2026-09-24)에서 바뀐 규칙**은 [밸런스 1차](밸런스-1차.md)가 기준입니다. 이 문서의 해당 줄에도 표시했습니다.
> 실제 Unity 화면은 [탐험전략-검수](탐험전략-검수/)에 있습니다. [한눈에 보기](탐험전략-검수/한눈에-보기.png)에서 전체 장면을 볼 수 있습니다.

## 1. 한 줄 요약

폐상가 관리실에 사는 **'그것'**이 소리를 듣고 방 사이를 움직입니다. 다음 걸음은 **한 턴 전에 문 위에 표시**됩니다. 큰 소리로 그것을 꾀어내면 **굴(관리실)이 빈 틈**에만 관리실 선반을 뒤질 수 있습니다.

## 2. 플레이 방법

| 화면 | 뜻 |
|---|---|
| 좌측 위 `남은 N턴` | 장소 시계. 방문마다 24턴(밸런스 1차: 방문마다 0에서 시작). 8턴, 16턴을 지날 때마다 '오래 머묾'으로 위험도 최저값 +1. 다 쓰면 위험도 3 고정 |
| 우측 위 `위험도 ●●○` | 0~3. 현장에서는 내려가지 않음 |
| 그 아래 `소음 ■■□□` | 소음 게이지 4칸. 가득 차면 위험도 +1 |
| 문 위 `발소리` | 옆방에서 그것이 움직였음 |
| 문 위 빨간 `다음 턴 들어옴` | 다음 턴에 이 방으로 들어옴(항상 한 턴 전에 표시) |
| 복도 관리실 문 `숨소리` / `조용함 · 선반` / `곧 돌아옴` / `조용함 · 빈 선반` | 굴에 있음 / 굴이 비어 선반을 뒤질 수 있음 / 이번 턴에 돌아와 선반이 닫힘 / 선반을 비움 (뒤의 둘은 밸런스 1차) |
| 같은 방의 말과 머리표 | `다음: 복도로` · `멈춰 듣는 중` · `머무는 중` |
| 우측 아래 `모두 숨죽이기`(이번 턴만) · `턴 진행` | 숨죽이기: 한 턴을 소리 없이 보냄. 소음 게이지 -1. 위험도 2 이하일 때 그것이 들어와도 지나침. 턴 진행과 대원별 배정은 [대원별 행동 배정 1차](탐험-대원별행동배정-1차-구현.md) |

그것의 움직임은 다음과 같습니다.

- **위험도 0~1:** 굴에 머뭅니다. 위험도 1부터는 한 턴에 소음 3 이상(큰 소리)을 낸 방을 기억합니다.
- **위험도 2:** 기억한 방이 있으면 그 방으로 향합니다. 한 칸 움직일 때마다 한 턴 멈춰 듣습니다. 도착하면 2턴 머물고 굴로 돌아갑니다. 기억한 방이 없으면 굴을 비우지 않습니다.
- **위험도 3:** 원정대가 있는 방으로 매 턴 옵니다. 숨죽이기가 통하지 않습니다.

마주치는 경우는 세 가지입니다. 모두 확률이 아니라 **위치**로 정해집니다.

| 경우 | 시작 |
|---|---|
| 그것이 우리 방으로 들어옴 | 예고된 조우 |
| 우리가 그것이 있는 방으로 들어감 | 기습 |
| 같은 문을 서로 반대로 지나감 | 예고된 조우 |

조우 창은 기존 조우 창(싸운다 · 숨는다 · 물러난다)을 그대로 씁니다. 싸우면 그 종(귀기울임) 1마리와 전투합니다.

- **숨기:** 밸런스 1차부터 주사위가 아니라 숨죽이기 1턴입니다. 위험도 2 이하면 지나가고, 3이면 실패합니다. 그것은 굴로 순간 이동하지 않고 제자리에 있습니다.
- **이기면:** 그것이 4턴(밸런스 1차, 이전 3턴) 동안 판에서 사라지고 굴이 빕니다. 돌아오는 턴에는 선반을 뒤질 수 없습니다.
- **오락실에서 물러나기:** '출구로 빠져나가기'로 바로 거점에 귀환합니다(밸런스 1차).

**첫 방문은 도입부입니다.** 그것은 잠들어 있고, 기존 소음 확률 조우와 `탐험 N턴` · `위험 · 미확인` 표시가 그대로 나옵니다. 숨죽이기도 보이지 않습니다. 관리실 문에서만 '잠든 숨소리'가 들립니다. 두 번째 방문부터 장소 판이 켜집니다. 위험도, 소음, 기억한 방은 다음 방문으로 이어집니다. 밸런스 1차부터 장소 시계는 이어지지 않고, 첫 방문도 위험도(최대 1)와 게이지를 넘깁니다. 두 번째 방문에서 처음 한 번 장소 판 안내 창이 뜹니다.

규칙 코드와 화면 코드는 다음과 같습니다.

- **규칙(화면과 분리):** `Assets/Scripts/FrontEnd/FieldSiteState.cs`
- **화면 연결:** `ExpeditionSiteThreat.cs`, `FieldThreatMarker.cs`
- **기존 파일에 넣은 최소 연결:**
  - `ExpeditionArrivalPanel.cs`: 시작과 귀환
  - `ExpeditionRoomNavigation.cs`: 턴 소비, 이동, 관리실 문
  - `ExpeditionEncounterPanel.cs`: 위치 조우 열기, 숨기·승리 결과
  - `ExpeditionLootPanel.cs`: 굴이 찼을 때 선반 잠금
  - `ExpeditionSearchPanel.cs`: 수색 확인창에 소음 미리보기 한 줄
  - `CampaignSaveData.cs`: 저장 ID

프리팹 구성은 `AgentScripts/BuildFieldStrategy.cs`로 다시 만들 수 있습니다. 이미 있는 부분은 건드리지 않습니다.

## 4. 검증

| 검사 | 결과 |
|---|---|
| `VerifyFieldStrategy.Rules` | 통과. 잠든 상태, 게이지·기억·출발·멈춤·예고·지나침, 머묾·귀가, 조우·숨기·쫓아냄, 기습·엇갈림, 추적, 장소 시계, 미리보기 = 실제 결과(1800턴) |
| `VerifyFieldStrategy.Showcase` | 통과. 실제 출발 경로로 8장면을 캡처 |
| `VerifyFieldBattle.BeginPreview` + `ItemFlow` | 통과(첫 방문 기존 조우 → 전투) |
| `VerifyCreatureBattle.Flow` | 통과 |
| `VerifyCorridorSearch.Flow` | 통과 |
| `VerifyEncounter.Flow` | 실패. 이번 변경 전부터 있던 문제로 봅니다 |
| `VerifyExpeditionArrival.Flow` | 실패. 이번 변경 전부터 있던 문제로 봅니다 |

실패한 두 검사의 원인은 다음과 같습니다.

- **`VerifyEncounter.Flow`:** 도구 없이 지렛대가 필요한 오락실 대상(2번)을 수색하려다 멈춥니다. 장소 판을 꺼도 같은 곳에서 실패합니다.
- **`VerifyExpeditionArrival.Flow`:** 폐허 시작의 창고에 보급품이 없어 짐 싸기 단계에서 멈춥니다.

Showcase는 두 번째 방문을 재현하려고 검수용 `ReviewWake(위험도 1, 소음 2, 시계 6)`를 씁니다. 나머지는 실제 버튼 입력입니다.
