# 모험가 2명 선택 — 2026-09-22

이번 범위는 시작 화면 다음의 모험가 선택이다. 정착지 화면은 기존 프로토타입으로 연결했으며, 승인 시안으로 교체하는 작업은 다음 단계다.

최신 연결 갱신: 이제 다음 버튼은 새 `HomeSelection` 씬으로 연결된다. [정착지 선택 구현](정착지선택-구현.md)을 참고한다. 아래 NightExpedition 직접 연결 내용은 이전 구현 기록이며, 현재는 정착지를 확정한 뒤 NightExpedition의 생활 화면에 도착한다.

## 최신 수정: 상단 선택 + 하단 캐릭터 정보

사용자 요청으로 `02` 종이를 제거하고 안내·후보 카드 영역을 210px 위로 올렸다. 하단에는 `CandidateDetails.prefab`을 추가했다. 마우스를 올리거나 키보드로 카드에 초점을 주면 이름·가방·체력·특성·특징이 갱신된다. 클릭은 기존대로 선택/해제이며, 두 명을 이미 골랐어도 다른 후보의 상세 정보는 살펴볼 수 있다. 처음에는 첫 후보 정보를 표시하고 선택은 0명으로 시작한다.

`PartyRoster.asset`의 `TraitTitle`, `TraitDescription`, `Characteristics`에서 문구를 수정한다. 현재 특성과 성격 설명은 역할별 초안이며 실제 능력 효과를 구현했다는 의미는 아니다. UI 좌표는 프리팹에서만 관리한다. `RevisePartySelection.Apply`는 이번 수정 재현용이며, 이전 전체 빌더를 다시 실행한 경우에만 이어 적용한다. 이후 수동 편집에는 재실행하지 않는다.

실제 캡처: `Assets/Screenshots/PartySelection/party-v3-details.png`. 기존 종이와 실루엣을 재사용하며, PSD 배치 문서도 상단 이동과 하단 패널에 맞춰 갱신했다. `candidate-details.psd`에는 종이와 6개 인물 대체 레이어가 있고 글자는 Unity에서 편집한다.

추가 검증: 6명 전원의 마우스 미리보기, 키보드 초점 미리보기, 선택 인원 유지, 특성 데이터 일치, 패널 텍스트 높이, 세 번째 후보 미리보기와 선택 제한, 선택됨 표시를 통과했다.

### 가독성 보정 및 두 명 선택 확인

후속 요청으로 모험가 선택 화면 전체를 실제 Gaegu Bold 폰트로 통일했다. 상세 본문은 30px/줄 간격 1.12, 카드 설명은 22px/줄 간격 1.02, 선택 상태는 24px다. 카드 설명 폭을 172px로 조정했다. 위치·종이·실루엣은 유지한다. `PolishPartyTypography.Apply`는 이 수정만 재현하는 도구다. 실제 캡처는 `Assets/Screenshots/PartySelection/party-v4-bold.png`.

6명 전원의 카드 설명과 상세 문구가 영역에 들어가는지 검증했다. 두 명 선택 시 두 카드의 테두리·체크, `2 / 2`, 다음 버튼 활성화, 해제 후 비활성화, 세 번째 선택 제한을 확인했다. 다음 화면에서 선택된 후보의 이름·체력·조준·가방 데이터 일치와 되돌아올 때 선택 유지도 통과했다. 특성 설명의 게임 효과 및 조합 시너지는 아직 구현되지 않았으며 이번 확인은 선택 표시와 데이터 전달 범위다.

## 실행 및 버튼 연결

`Assets/Scenes/StartMenu.unity` → 새 게임 → 페이드 → `PartySelection.unity`.

| 조작 | 동작 |
| --- | --- |
| 후보 카드 클릭 | 선택, 노란 테두리와 체크 표시 |
| 선택된 카드 재클릭 | 해제 |
| 두 명 선택 후 다른 카드 클릭 | 기존 선택 유지, 먼저 해제하라는 안내 |
| 다음 | 정확히 두 명일 때 활성. 후보 ID와 능력값을 기존 NightExpedition의 정착지 선택에 전달 |
| 돌아가기 | 시작 화면 |
| 정착지의 모험가 다시 선택 | 방금 선택한 두 명을 유지하며 이 화면 복귀 |
| 시작 화면에서 새 게임 | 임시 선택 초기화 |
| 좌우 화살표 | 후보가 6명보다 많으면 다음 페이지. 현재 후보 6명이라 비활성 |

## 편집 위치

- 씬: `Assets/Scenes/PartySelection.unity`
- 조립 프리팹: `Assets/Prefabs/PartySelection/PartySelectionScreen.prefab`
- 개별 프리팹: 같은 폴더의 `SelectionHeader`, `CandidateCard`, `NavigationButton`, `ContinueButton`
- 후보 데이터: `Assets/Data/PartyRoster.asset` — ID, 이름, 설명, 가방·체력·조준, 인물 이미지. ID는 후보별 고유하게 유지한다.
- 이미지 원본/PSD: [아트 기록](../아트/모험가선택-v1/README.md)
- 연결 코드: `Assets/Scripts/FrontEnd/PartySelectionController.cs`

글자 크기·색·위치는 프리팹의 Text/RectTransform에서 수정한다. 이름/설명/수치는 Roster 데이터에서 수정한다. 실행 중 코드는 선택 상태와 후보 내용만 갱신한다. Canvas·카메라·EventSystem·TitleViewport는 씬에 있으므로 화면 프리팹만 빈 씬에 놓으면 입력 환경을 별도로 갖춰야 한다.

역할명·체력·가방 수치는 시안 기반 임시 데이터다. 설명에 있는 요리·수리·의료 효과는 아직 구현하지 않았다. 가방 용량은 여정 데이터에 전달되지만 개별 인벤토리 규칙에 연결하는 작업은 후속 범위다. 여정 저장 기능도 아직 없다.

## 검증

Unity 6.6 Editor에서 재컴파일 통과. `VerifyPartySelection.Flow`에서 실제 UI Raycast를 통과한 클릭으로 초기 비활성, 두 명 선택, 세 번째 선택 거절, 해제, 임시 7번째 후보의 페이지 이동·선택 유지, 5/6번째 후보 ID·가방 수치의 정착지 전달, 되돌아오기, 새 게임 초기화를 통과했다. 실행 파일 빌드는 하지 않았다.

1920×1080 실제 캡처를 승인 시안과 비교했다. 카드 설명 넘침, 인물 옆 체크 잔여물, 배경 타일 경계는 보정했다. 시안과 다른 점·원본 해상도 한계는 아트 기록에 별도 명시했다. 시각적 최종 승인은 사용자 검토 대기다.

빌더 `AgentScripts/BuildPartySelection.cs`는 초기 제작용이다. 다시 실행하면 프리팹 배치가 초기화되므로 이후 수동 편집 뒤에는 전체 빌더 대신 해당 요소만 수정한다.
