# 식량 준비 — 실제 조리·창고·음식 사용

2026-09-23. 〈이웃 아닌〉 비전투 제작 단계. 기존 식량 준비 시안의 배치를 유지하면서 실제 물자와 연결했다. 전체 비전투 콘텐츠 완성을 뜻하지 않는다.

## 이용 순서

1. 정착지 **식량 준비**에서 조리법·횟수·담당자를 선택하고 조리 시작.
2. 재료와 담당자를 예약한다. 다른 제작·휴식·원정 배정과 겹치지 않으며 예약 재료는 가방에 넣거나 소비할 수 없다.
3. 시간 진행에서 제작·휴식·조리가 동시에 진행된다. ‘다음 완료까지’에 조리도 포함한다.
4. 완료할 때 예약 재료를 소모하고 결과물을 공용 창고에 넣는다. 중도 취소는 재료와 담당자를 해제하며 이미 흐른 시간은 되돌리지 않는다.
5. 공용 창고에서 음식을 선택하고 먹기. 도시락은 개인 가방에 담아 탐험 중 가방의 먹기 버튼으로 사용할 수 있다.

## 임시 수치

아래는 기능 검증용 초기 밸런스이며 최종 생존 규칙이 아니다. 배고픔·갈증·부패·자동 배급·직업별 조리 보너스는 추가하지 않았다.

| 조리법 | 1회 재료 | 시간 | 결과 |
|---|---|---:|---|
| 따뜻한 한 끼 | 식재료 2, 물 1, 나무 판자 1 | 20분 | 조리한 식사 2 |
| 넉넉한 스튜 | 식재료 2, 물 2, 나무 판자 2 | 30분 | 조리한 식사 3 |
| 원정 도시락 | 조리한 식사 1, 천 조각 1 | 10분 | 원정 도시락 1 |
| 통조림 한 끼 | 통조림 1 | 즉시 | 조리한 식사 1 |

- 횟수만큼 재료·시간·결과 수량이 늘어난다. 통조림도 담당자를 선택하지만 즉시 완료되어 작업에 남지 않는다.
- 새 게임 식재료 6, 물 4, 통조림 2. 완성 음식·도시락은 0. 기존 목재·천 재고를 공유한다.
- 식사/도시락 1개 사용 시 체력 +1. 정착지에서는 10분, 현장 도시락은 탐험 1턴(현재 10분)과 소음 0. 현장에서는 선택한 가방 주인이 먹으며 옮길 수량과 무관하게 1개를 쓴다.
- 만피·행동 불능 대원은 소비하지 않는다. 정착지 작업 중인 대원은 작업 종료 후 먹을 수 있다. 현장에서는 이동·수색·조우 같은 다른 행동 중 사용할 수 없다.
- 오락실 상자에 식재료 2(기본 85%), 물 2(80%), 통조림 1(45%) 드롭을 추가했다. 기존 수색 방식 보정이 적용된다. 기존에 수색을 끝낸 장소는 재추첨하지 않는다.
- 음식 전용 원화 대신 기존 물자 상자/가방 아이콘을 사용한다. 전용 원화 완성으로 취급하지 않는다.

## 저장

버전 2에 조리 담당자 ID, 조리법 ID, 횟수, 남은 시간, 결과 ID/수량, 예약 재료를 저장한다. 제작과 조리의 예약 합계가 재고 이하인지 함께 검증한다. 같은 대원을 여러 작업에 저장할 수 없다.

버전 1은 기존 상태를 검증한 뒤 신규 식량 재고를 0, 조리 예약을 빈 목록으로 이관한다. 불러오기 자체는 원본 파일을 덮어쓰지 않는다. 새 게임 초기 식량을 과거 저장에 반복 지급하지 않는다. 귀환 경험이 없는 저장의 빈 기록 직렬화 문제도 수정했다.

## 편집·재적용

- `Assets/Prefabs/Settlement/CookingPanel.prefab`: 조리법, 시간, 결과, 예약 목록과 취소 확인창.
- `CraftWorkPanel.prefab`: 공용 물자 초기 수량. `InventoryPanel.prefab`: 음식 회복량·사용 시간·사용 동사·현장 사용 여부.
- `ExpeditionLootPanel.prefab`: 수색 드롭. `ExpeditionBagPanel.prefab`: 기존 하단 버튼 사이 먹기 버튼.
- 기능 연결 빌더: `AgentScripts/ConnectCooking.cs`의 `ConnectCooking.Run`. Editor API를 통해 프리팹을 편집한다. 정지 상태에서만 실행하며 저장하지 않은 씬은 보호한다.
- 예전 `BuildCookingUI`는 시안 생성 이력이다. 이를 재실행한 경우 공통 팝업/내부 정렬 보완 뒤 `ConnectCooking.Run`을 다시 적용해야 한다.

## Unity 검증

Unity 6000.6.0f1 Editor에서 컴파일 성공. 실행 파일은 만들지 않았다.

- `VerifyCooking.Flow`: 실제 UI 레이캐스트 클릭으로 예약·취소·담당자 잠금, 제작 병행, 정착지 식사, 도시락 제작·이동·현장 사용, 만피/중복 소비 방지, 귀환 저장 확인.
- 디스크 왕복 시 전체 상태 일치, 손상된 예약/중복 담당자 거부, 완료 시 비용·보상 1회 적용.
- `LegacyAndRestartFixture` / `Restart`: 실제 기존 버전 1 파일 읽기 및 별도 Play 세션의 시작 화면 이어하기 → 조리 복원 → 완료 확인.
- `BatchAndSupply`: 2회 조리/4인분, 중도 취소, 조리 중 원정 불가, 제작과 목재 예약 공유, 시간 진행 UI, 수색 → 발견물 분배 → 가방 → 귀환 → 창고, 저장 복원 후 식재료 재추첨 방지.
- 테스트 파일은 `Temp/CookingVerification-*`, `Temp/CookingRestartVerification` 등 격리 폴더만 사용한다. 플레이어 저장 파일은 수정하지 않았다.
- 현재 통과한 실행에서 새 Unity 오류 없음. 이전 검증 도구의 수동 Camera.Render 오류 기록은 별개이며 삭제하지 않았다.

## 남은 범위

배고픔·갈증 등 생존 규칙, 정수/거래 같은 반복 공급원, 조리 특성 보너스, 음식 전용 그림은 미확정 또는 후속이다. 현재 수색 장소는 유한하며 반복 식량 생산을 보장하는 경제가 완성된 상태는 아니다. 다음 제작 단위는 생활 물자의 공급·소비와 회복 콘텐츠다.
