# 인게임 UI 연결 기준

2026-09-22. UI 시안 20종과 연결된 방·턴제 탐험 방향을 바탕으로 작성한 **개발 전 연결 명세**다. 실제 Unity 버튼 연결이나 런타임 동작을 구현한 상태가 아니다. 문서의 버튼 이름은 구현용 정규화 명칭이며 이미지에 적힌 문구와 완전히 같을 필요는 없다.

## 문서 구성

- `index.html`: 화면 노드를 선택해 앞뒤 연결, 버튼별 목적지, 원본 시안을 함께 보는 오프라인 연결도.
- `버튼연결명세.md`: 전체 화면 목록, 구간별 Mermaid 다이어그램, 모든 버튼/자동 전이 표.
- `navigation.json`: 동일한 연결 명세의 구조화 데이터. 게임 저장 데이터 또는 실행 코드가 아니다.
- `navigation-source.cjs`: 명세 편집 원본. `node generate-docs.cjs`로 위 산출물을 다시 생성한다.

## 우선순위와 확정 범위

UI 종이 질감·개별 가방·오브젝트 중심 작업 배정·다인원 대응·분리 진형 전투는 기존 방향이다. 방 연결과 턴제 탐험은 최신 사용자 방향을 따른다.

빠름/보통/정밀의 1/2/3턴, 잠금 해제 비용, 야간 규칙, 거점 시간 진행, 전투 행동/도주 비용, 현장 효과 아이템의 턴 비용 및 저장 허용 시점은 검토안이다. 이 명세는 화면 연결을 우선 정하며 밸런스 수치를 확정하지 않는다.

## 겹침과 복귀

1. 기본 화면은 시작·거점·탐험·전투 중 하나다. 패널을 열어도 기본 맥락을 유지한다.
2. 모달은 뒤쪽 조작을 막는다. 수량 선택·확인창은 현재 패널 위에 한 단계씩 쌓는다. 한 번의 입력으로 아래 버튼까지 누르지 않는다.
3. 각 팝업 진입 때 `returnRoute`, `phase`, `roomId`, `survivorId`, `containerId`, `selectedItemId`, `scrollPosition`, `draftId`를 필요한 만큼 보관한다. `RETURN`은 고정 거점 화면이 아니다.
4. 예: 발견물 → 현장 가방 → 아이템 상세 → 수량 선택에서 취소하면 아이템 상세로, 가방 닫기는 발견물로 돌아간다. 아이템 이전 성공 시에는 관련 상세를 갱신하거나 닫아 소유자가 바뀐 물품을 다시 조작하지 못하게 한다.
5. `Esc`는 최상위 취소 가능한 창 하나만 닫는다. 열린 패널이 없는 거점/탐험/전투에서는 메뉴를 연다. 아이템 사용 확정 전 취소는 비용을 소모하지 않는다.
6. 조우·처리 중·귀환 정산·전투 결과·전멸에는 임의의 X 닫기를 두지 않는다. 조우에서는 제공된 선택지로 해결하고, 정산은 입고 또는 개인 보관으로 명시적으로 마무리한다. 처리 중에는 메뉴/닫기를 잠근다.
7. 긴급 상황을 제외한 완료 알림은 모달 위에서 강제로 전환시키지 않는다. 현재 선택을 마친 뒤 알림을 선택할 수 있다.
8. 대원을 바꿨다고 같은 아이템·대상 선택을 새 대원에게 조용히 적용하지 않는다. 선택 해제 또는 재확인을 거친다.

## 턴 확정 경계

탐험에서는 **행동 배정과 턴 진행을 분리**한다. 수색 방식·담당자·지원·이동 선택은 초안만 바꾼다. `E00/E04 → E05`에서만 탐험 턴을 차감한다. 07 시안의 ‘수색 시작’은 ‘행동 배정’으로 수정해야 한다.

한 턴 처리 순서 제안:

1. 입력 잠금 → 턴 ID 발급 → 대원/방/도구/작업 충돌 재검증. 실패하면 상태와 비용을 바꾸지 않고 원래 화면에 오류 표시.
2. 원정대 이동과 개별 현장 작업은 같은 턴에 함께 실행하지 않는다. 이동을 고르면 진행 작업 중단 결과를 먼저 확인한다.
3. 비용·작업 진행·수색도·이동 상태·발견물 결과를 한 트랜잭션으로 저장한다. 발견물은 아직 개인 가방에 자동 입고하지 않는다.
4. 원정대 전체에 대한 위험 판정 한 번. 긴급 조우 → 발견물 → 일반 알림 순서로 표시한다. 조우가 먼저 나와도 이미 발생한 발견물을 없애지 않는다.
5. 조우 해결 후 살아남은 원정대가 재개할 수 있으면 대기 발견물 배분을 먼저 보여준다. 보상과 소비를 다시 계산하지 않는다.
6. 잔여 턴이 있는 작업은 다음 턴 계획에 유지하되 중단 가능 여부를 표시한다. 같은 턴 ID는 두 번 처리하지 않는다.

탐험 중 치료·음식 등 유효 효과가 있는 아이템은 공짜 메뉴 조작으로 무한 사용하지 않도록 행동 배정 경로를 사용한다는 검토안이다. 단순 가방 정리와 물품 배분은 0턴이다. 전투 아이템은 B02에서 전투 비용을 사용한다.

## 이동과 귀환

- 방 지도 클릭은 정보 조회다. 인접한 문 → 이동 계획 → 이번 턴 계획 → 턴 진행을 거쳐 실제 이동한다.
- 원정대는 첫 버전에서 함께 이동하는 안이다. 이동 초안과 개별 작업이 겹치면 확인 없이 기존 작업을 버리지 않는다.
- 출구가 아닌 방의 귀환 버튼은 지도에서 경로를 보여준다. 즉시 거점으로 순간 이동시키지 않는다.
- 실제 출구에서 귀환 확인 → 귀로 시간 1회 처리 → 귀환 정산. 안전한 복귀를 위한 시간·비용은 출발 전에 보여준다.
- 목적지까지의 왕복 이동 시간, 현장 탐험 턴, 전투 시간은 각각 한 번만 장부에 반영한다. 몇 분/몇 턴인지는 별도 수치 데이터다.

## 인벤토리와 소유권

- 거점 H01: 공용 창고 ↔ 개인 가방. 현장 E07: 동행 대원 가방만. 전투 B02: 현재 행동 대원의 사용 가능 물품.
- 짐 꾸리기의 이동은 실제 가방 이전이다. 뒤로 가거나 원정을 취소해도 조용히 원상 복구하지 않는다.
- 수량 확인 때 출발지 수량과 도착지 수용량을 다시 검사한다. 전체 옮기기는 가능한 수량만 옮기고 나머지를 명확히 남긴다.
- 거래 수량 편집은 제안 초안이다. 상대 수락과 최종 확인 전에는 소유권을 바꾸지 않는다.
- 장착 슬롯은 별도 복사본이 아니다. 예약된 제작 재료는 가방 이동·사용·거래 대상에서 제외한다.
- 발견물 닫기 때 잔여물 확인은 ‘현장에 남겨두기’다. ‘버리기’와 구분하고 방/컨테이너 상태에 보존한다.
- 입고 완료·거래 완료·아이템 사용·저장 완료는 작업 ID별 한 번만 확정한다.

## 연결 검증 시나리오

1. 시작 → 2명 → 정착지 → 거점. 뒤로 가기는 초안 보존, 새 게임은 기존 저장 무단 삭제 없음.
2. 창고 → 아이템 → 수량 → 취소. 수량·시간·소유권 변화 없음.
3. 출입구 → 목적지 → 대원 → 짐 → 출발 취소. 짐 배분은 유지되고 출발 시간은 미차감.
4. 수색 방식·담당자·지원 배정 후 가방 열기/닫기. 시간은 그대로, 배정 초안 유지.
5. 턴 진행 연타. 턴·비용·위험·보상이 한 번만 반영됨.
6. 방 이동 배정 중 진행 수색 취소 경고에서 취소. 이전 작업 유지, 이동 없음.
7. 발견물 가방 부족 → 다른 대원 가방 → 일부 이전 → 나머지 남김. 소유권 합계 보존.
8. 발견과 조우 동시 발생 → 전투 → 탐험 복귀. 발견물 사라짐·중복 생성 없음.
9. 전투 아이템 대상 변경 후 취소. 아이템·차례 유지. 확정만 소비.
10. 전멸 결과에서 계속 탐험 버튼 없음. 유효 저장 없으면 불러오기도 비활성.
11. 출구 아닌 방에서 귀환 → 연결 지도. 실제 출구에서만 왕복 이동 처리.
12. 귀환 정산 재열람/연타. 입고 한 번, 개인 보관 물품 유지.
13. 일시정지 → 설정 취소. 기존 설정과 원래 화면 복구.
14. 손상된 저장 불러오기 실패. 현재 여정 유지, 오류 설명 제공.
15. 대원이 2명보다 많아져도 담당자·가방 목록이 잘리지 않고 소유자 혼동 없음.

위 시나리오는 향후 Unity 검증 기준이다. 이번 문서 작업으로 런타임 테스트를 통과했다고 간주하지 않는다.
