# 오락실 ↔ 복도 이동 — 2026-09-22

정착지 내부 이동의 세부 연출은 후속으로 남기고 탐험 장소의 연결된 방을 구현했다. 현재 두 방은 동작 검토용이며 복도 원화는 사용자 시각 승인 전이다.

## 실제 흐름

폐상가 출발 → 오락실 도착 → 오른쪽 문 클릭 → 이동 비용 확인 → 일행이 문으로 이동 → 짧은 검은 페이드 → 복도 진입. 복도 왼쪽 문에서 같은 방식으로 오락실로 돌아간다.

- 확정한 단체 이동마다 탐험 1턴. 확인창 취소에는 비용이 없다.
- 이동 중 입력을 막고 연속 클릭으로 턴이 중복 소비되지 않게 한다.
- 미방문 복도 내부는 진입 전 공개하지 않는다. 방문 표시와 오락실 사물 확인 기록은 왕복 시 유지한다.
- 선택한 대원과 개인 가방은 그대로 유지한다. 복도에서는 오락실 출구로 돌아간 뒤 거점으로 귀환한다.
- 복도의 철문과 오른쪽 문은 설명만 제공한다. 잠금 해제나 추가 방 진입은 아직 없다.

## 수정 위치

- `Assets/Scripts/FrontEnd/ExpeditionRoomNavigation.cs`: 방 상태, 확인창, 턴, 말 이동과 페이드.
- `Assets/Scripts/FrontEnd/ExpeditionArrivalPanel.cs`: 도착 화면 연결, 사물 확인, 귀환 제한.
- `Assets/Prefabs/Settlement/CorridorHotspots.prefab`: 복도 문 3개. 기존 개별 시설 버튼 프리팹을 사용한다.
- `Assets/Prefabs/Settlement/ExpeditionArrivalPanel.prefab`: 방 연결 표시와 탐험 턴, 확인창.
- `Assets/Scenes/Settlement.unity`: 탐험 배경 렌더러 연결.
- `AgentScripts/BuildRoomNavigation.cs`: Editor 구성 스크립트.
- `아트/복도-v1/`: 원본 PNG, Unity용 PNG, 배경 PSD 및 요소별 화면 배치 PSD.

## 검증

`VerifySettlement.Flow`와 `VerifyRooms.Flow` 통과. 실제 UI 클릭으로 출발, 사물 확인, 이동 취소, 확정, 연타 방지, 복도 진입, 왕복, 잠긴 문 설명, 가방·대원·확인 기록 유지, 텍스트 영역을 확인했다. Unity 1920×1080 실제 화면은 `Assets/Screenshots/Settlement/corridor-v1.png`다. 실행 파일 빌드는 하지 않았다.

실제 캡처에서 상단 종이 HUD의 기준선, 기존 대원 카드와 흰 받침대, 하단 돌아가기 위치를 확인했다. 복도는 승인된 오락실 배경을 참조한 새 그림이므로 기존 시안의 동일 복제본으로 취급하지 않는다.

## 남은 범위

- 현재 턴은 탐험 전용 카운터다. 한 턴의 게임 내 분 단위 환산은 미정이며 방 이동으로 생활 시계를 진행하지 않는다. 목적지 왕복의 기존 이동 시간은 별도로 적용된다.
- 방문·사물 확인 상태는 이번 원정 동안만 유지한다. 저장 및 다음 원정의 상태 복원은 후속이다.
- 수색 배정, 확률 획득, 소음, 적 조우, 전투 연결은 아직 추가하지 않았다.
- 배경 원본은 1672×941이며 큰 PSD 배치 캔버스가 원화 세부 해상도를 복원하지는 않는다. 배경 PSD는 단일 그림 레이어이고 문·벽·상자는 아직 분리되지 않았다. 별도 화면 배치 PSD의 HUD·버튼 등은 분리되어 있다. 최종 원화 납품에는 고해상도 원본과 독립 소품 레이어 보완이 필요하다.
