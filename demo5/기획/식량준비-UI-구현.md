# 식량 준비 UI — 2026-09-23

물자비축과 창고 기능의 중복을 해소하기 위한 조리 UI 첫 단계다. 정착지 기존 비축 물자 버튼은 식량 준비로 바뀌며 CookingPanel을 연다. 보관함은 기존 공용 창고를 유지한다.

## 현재 조작 가능 범위

- 조리: 따뜻한 한 끼, 넉넉한 스튜.
- 휴대식: 원정 도시락.
- 간편식: 통조림 한 끼.
- 조리법, 준비 횟수, 담당자 선택. 조리법/탭 전환에도 가능한 담당자 선택 유지.
- 필요 재료, 완성 예상 인분, 예상 시간 갱신. 시안 재료 부족 또는 담당자 미선택이면 확인 불가.
- 준비 내용 확인 버튼은 오른쪽 구성 확인 상태만 바꾼다. 실제 조리 예약이나 생산을 수행하지 않는다.

현재 재고와 시간, 인분은 UI 비교를 위한 임시 데이터다. 실제 창고, 개인 가방, 작업 예약, 캠페인 시간에 영향을 주지 않는다. 부족 표시도 시안 재고 기준이며 화면에 명시한다. 담당자의 현재 배정/체력 상태는 실제 게임 상태를 따른다.

## 편집과 자산

- 독립 화면: Assets/Prefabs/Settlement/CookingPanel.prefab.
- 조립: SettlementScreen.prefab → SettlementController.CookingPanel.
- 재사용 행: CraftRecipeRow, CraftWorkerRow, CraftCostRow. 기존 종이 질감, 글꼴, 강한 딤, 좌하단 돌아가기, 동일 하단 기준선을 유지한다.
- 데이터/참조: SettlementCookingPanel의 Meals, Ingredients와 Text/Button/Scroll 참조를 Inspector에서 편집.
- 재생성: AgentScripts/BuildCookingUI.cs → BuildCookingUI.Run (Play 종료 후).
- 이미지 PSD/PNG: 아트/식량준비-v1. 음식 아이콘은 기존 물자 상자 등을 쓴 임시 표기이며 전용 원화는 후속 작업이다.

## 검증과 다음 단계

VerifySettlement.Flow, VerifyCookingUI.Flow 통과: 진입 경로 분리, 탭/음식 변경, 담당자 유지, 횟수와 재료 부족, 구성 확인, 배경 입력 차단과 HUD 복원, 창고 기능 유지, 문구 높이, 하단 크기·정렬, 실제 시간·물자·배정 비변경.
긴 스튜 설명이 3줄로 넘치는 문제를 2줄 문구로 보완했다. 실제 1920×1080 화면을 캡처하고 기존 제작대와 비교했다. 배치와 질감은 유지하고 오른쪽 예약 목록을 준비 내용 요약으로 대체했다.
