# 튜토리얼 — 서사와 실제 행동 연결

2026-09-25 사용자 지적: “개연성 1도 없고 그냥 버튼 안내만 한다.” 최신 정정은 “굳이 2명 체력 둘 다 깎을 이유가 있는 거야?”다.

현재 기준은 **물자를 모아 둘 거점을 확인하고, 실제로 부족한 자재를 찾으러 나가는 도입**이다. 휴식을 가르치기 위해 시작 체력을 깎거나 부상 사건을 만들어내지 않는다. 작업 프로젝트는 `E:/personalProject/Demo3/demo5`이며 새 작업 폴더나 별도 게임을 만들지 않는다.

## 현재 도입의 목적과 순서

두 사람은 수색한 물건을 모아 둘 거점으로 쓸 생각에 선택한 건물에 들어선다. 안에 사람이 있는지와 선반·작업대 상태를 확인하고, 남은 상자에서 무엇을 쓸 수 있는지 살핀다. 목재·고철이 없다는 사실을 확인한 뒤 회수품을 내려놓을 바닥 한쪽을 치운다. 이후 오는 길에 본 폐상가의 포장 자재를 근거로 수색할 곳을 정한다.

| 실제 도입 단계 | 행동과 이유 | 소요 시간·결과 |
|---|---|---|
| 0 → 1 | 거점으로 쓸 건물 안을 확인한다. | 10분. 다음 확인 대상인 남은 상자로 연결 |
| 1 → 2 | 남은 상자에서 쓸 물건과 부족한 재료를 확인한다. | 10분. 천 1·물 1·발견 탄약 지급. 탄약 기본값 2발 |
| 2 → 5 | 돌아와 가져온 짐을 내려놓을 바닥 한쪽을 정리한다. | 20분. 첫 외출 준비 개방 |
| 5 | 부족한 목재·고철을 찾으러 갈 장소·동행·휴대품을 정한다. | 준비 자체는 무료. 실제 출발부터 해당 이동 시간 적용 |

- 새 게임 대원은 원래 최대 체력으로 시작한다. `BeginSettlementIntroduction()`은 기본 물자를 비우지만 체력을 낮추거나 회복시키지 않는다.
- 바닥 정리는 회수품을 내려놓기 위한 행동이다. 침대 복구나 휴식 완료를 뜻하지 않는다.
- 휴식과 빈 보관함 여닫기는 출발 조건이 아니다. 휴식은 실제 회복이 필요할 때 선택한다.
- 도착 대화에 부상 이야기나 두 사람의 체력 설명 패널을 표시하지 않는다. 일반 대원 상태 화면의 체력 표시는 유지한다.
- 대화는 현재 확인한 것과 필요한 일을 연결한다. 확인하지 않은 위험이나 피해를 기능 학습의 이유로 덧붙이지 않는다.

## 새 게임 화면 전환

도착의 **0.45초 암전 + 1.35초 페이드 인**은 유지한다. 방이 드러난 뒤 도착 대화가 열리며, 페이드 동안 HUD·게임 조작·튜토리얼 표식은 숨기고 입력을 막는다. 페이드 종료와 대화 시작 사이에 기본 HUD나 클릭 안내가 먼저 나타나지 않도록 연결한다.

저장 불러오기에서는 도착 페이드를 반복하지 않는다. 읽던 장면과 대사 위치를 복원하며, 이미 읽은 대화를 강제로 다시 열지 않는다.

## 장면 구성

`SettlementTutorialNarrative`는 완료한 행동과 현재 상태를 읽어 하단 대화창을 연다. 내부 장면 번호는 저장용이며 플레이어에게 단계 시험 번호로 표시하지 않는다. 번호 11개와 각 장면의 줄 수를 유지하되 **새 게임은 장면 3을 건너뛴다**.

| 내부 번호 | 장면 | 표시 조건·전달할 이유 | 이어지는 실제 행동 |
|---|---|---|---|
| 0 | 돌아와 짐을 내려놓을 곳 | 정착 도입 0단계. 선택한 건물을 물자를 모아 둘 거점으로 쓰려 한다. | 사람과 시설이 있는지 건물 안 확인 |
| 1 | 고쳐 쓸 수 있는지 | 주변 확인 완료. 선반과 작업대가 흔들리므로 남은 상자에 수리 재료가 있는지 확인한다. | 상자 수색 |
| 2 | 남아 있는 것과 필요한 것 | 물·천·탄약은 발견했지만 목재·고철은 없다. 가져올 짐을 내려놓을 곳부터 만든다. | 바닥 한쪽 정리 |
| 3 | 짐을 둘 자리 | 구형 저장이 이 장면을 읽던 중일 때만 두 줄을 이어 읽는다. 정리된 바닥과 부족한 자재를 이야기한다. | 외출 준비. 휴식 요구 없음 |
| 4 | 자재를 찾으러 | 바닥 정리를 마쳤고 첫 귀환 전. 목재·고철이 필요하며, 오는 길에 본 폐상가를 후보로 삼는다. | 출입구에서 목적지·동행·휴대품 선택 |

| 6 | 작업대 · 도구와 시설 만들기 | 작업대가 복구됐고 관리표를 아직 읽지 않았다. 작업대의 기능과 다음 수색 장소를 알게 되는 근거를 제시한다. | 접힌 관리표 읽기 |
| 7 | 간이 지렛대 · 걸린 문을 벌릴 도구 | 관리표를 읽었고 지렛대가 없으며 보관실 문도 열지 않았다. 도구의 용도를 설명하고 오래된 비축품의 존재는 보장하지 않는다. | 끈·못·간이 지렛대 제작 |
| 8 | 돌아올 길을 생각하며 | 지렛대를 보유했거나 보관실 문이 이미 열렸다. 두 상황에 맞춰 대사를 구분한다. | 필요한 도구 휴대·보관실 확인 |
| 9 | 직접 확인한 장소 | 보관실 방문·비축 선반 수색을 마치고 귀환했다. 특정 식량 획득을 성공 조건으로 삼지 않는다. | 직접 확인한 사실 기록 |

장면 4의 첫 화자는 한해인(`medic`)이다. 최대 체력인 사람을 찾아 화자를 바꾸는 이전 `rested` 선택 방식은 사용하지 않는다. 자유로운 작업 순서나 기존 저장으로 뒤쪽 상태에 도달했다면 지난 장면을 연속 재생하지 않는다. 읽던 장면·대사가 저장돼 있으면 해당 위치를 우선 복원한다.

## 대상의 이름과 용도 안내

사용자 지시 “표시해주는 것도 좋은데 뭐가 뭔지 이야기해주고 표기를 해야지”를 따른다. 대화에서 지금 필요한 대상과 이유를 소개한 뒤 **실제 기능 이름 → 뜻과 효과 → 지금 할 조작** 순서로 안내한다.

- 출입구: 수색할 장소, 함께 갈 사람, 휴대할 물건을 정한다.
- 공용 창고/개인 가방: 제작에는 창고의 사용 가능한 재료를 쓰며, 가방 물건만 원정에 휴대한다. 가방 숫자는 사용 칸 / 전체 칸이다.
- 제작: 담당자는 한 번에 한 가지 일을 맡는다. 재료 수량은 사용 가능 / 필요 수량이다.
- 시간 진행: 맡긴 일이 선택한 시간만큼 함께 진행된다. ‘다음 완료까지’는 시간을 고르는 버튼이며 실제 진행은 별도 확정이다.
- 잠자리: 선택해서 연 경우 체력 수치와 빈 칸, 휴식 배정과 실제 회복 완료를 설명한다. 건강한 두 사람을 도입 필수 행동으로 보내지 않는다.
- 수색: 수색도는 진행한 턴 / 필요한 턴이다. 수색 완료로 드러난 발견물은 가방에 담아야 휴대한다.
- 귀환: 모두 보관은 현재 원정대의 휴대품을 창고로 옮긴다. 넘친 물건은 가방에 남는다.

주변 확인·상자 확인·바닥 정리는 기존 행동 버튼을 사용한다. 이후 안내는 실제 출입구·보관함·작업대·시간 진행 버튼에 연결한다. 대화 중에는 정착지 기본 조작을 막고 안내판·화살표·강조 딤을 숨긴다. 대화를 마치면 현재 상태에 맞는 다음 행동 안내가 돌아온다.

## 대화와 게임 상태의 구분

- 대사 넘기기·본문 클릭·대화 마치기는 시간, 체력, 자원, 시설, 수색 진행을 바꾸지 않는다. 대화 진행 상태와 활동 기록만 남긴다.
- 10분·10분·20분은 실제 도입 행동에서 처리한다. 대화가 이 시간을 대신 진행하지 않는다.
- 상자 보상은 실제 수색 행동에서 한 번만 지급한다. 발견 대화의 아이콘과 수량은 실제 보유 상태를 읽는다.
- 휴식은 선택 사항이며 예약만으로 회복되지 않는다. 선택한 경우 실제 시간 진행으로 작업을 끝내야 회복된다. 첫 출발을 위해 수행할 필요는 없다.
- 제작·보관·출발·수색·귀환은 기존 시스템을 사용한다. 시작 피해와 휴식 필수 조건을 제거한 것 외에 비용·보상표·전투 규칙을 대화에 맞춰 임의 변경하지 않는다.

## 상태에 맞춘 대사

- 빈손 귀환은 확인하지 않은 자재를 봤다고 말하지 않는다. 현재 창고와 가방에 목재·고철이 있는지 확인해 문구를 구분한다.
- 창고가 복구됐다면 다시 만들라고 하지 않고 작업대에 필요한 자재로 목적을 옮긴다.
- 보관실 문이 열렸다면 도구를 새로 완성한 것처럼 말하지 않는다. 열린 길로 다시 들어갈 수 있다는 사실을 이야기한다.
- 체력 0은 현재 게임에서 중상이다. 상태 때문에 해인의 대사를 서진에게 붙이는 식으로 화자의 이름·초상을 바꾸지 않는다.
- 마지막 장면은 침대·조리대가 모두 없을 때, 하나만 있을 때, 모두 있을 때를 구분한다.
- 작업대의 관리표는 보관실 문이 걸려 도구가 필요하다는 근거다. 간이 지렛대는 문틈을 벌리는 용도이며 금속 잠금장치를 부수는 도구로 설명하지 않는다.
- 관리표, 기록 열람, 야간 사건의 경고는 **“문 너머에서 세 번 두드리면, 먼저 대답하지 말 것.”**으로 통일한다.
- 첫 생활 기록은 보관실을 확인했다는 사실을 남긴다. 실제 회수 여부와 관계없이 식량을 확보했다고 단정하지 않는다.

## 저장 v18과 이전 도입 호환

`SavedTutorialNarrative`는 읽은 장면 비트마스크(`SeenMask`), 진행 중 장면(`PendingBeat`), 대사 위치(`LineIndex`)를 저장한다. 이번 수정에서 저장 버전과 장면·줄 수는 바꾸지 않는다.

- 새 도입은 2단계 바닥 정리 뒤 5단계로 이동한다. 장면 3을 새로 재생하지 않는다.
- 기존 저장의 도입 3·4단계는 런타임에서 5단계로 복원한다. 체력을 자동 회복하거나 이미 예약한 휴식을 취소하지 않는다.
- 기존 `PendingBeat=3`은 중립적인 ‘짐을 둘 자리’ 두 줄 중 저장된 위치부터 이어 읽는다. 물건을 다시 지급하거나 수색·휴식 시간을 다시 소비하지 않는다.
- 기존 휴식 예약 때문에 출발할 대원이 없으면 맡긴 일의 완료를 안내한다. 이는 저장한 작업의 처리를 위한 안내이며 새 부상을 만들거나 새 휴식을 강제하는 과정이 아니다.
- v17 → v18 이행은 기존 도입·첫 귀환·시설·관리표·도구·보관실 상태에서 현재 대화 문맥만 계산한다.
- 기존 물품·시간·대원 체력·작업 예약·방문자 재고·수색·NPC·캐릭터 해금·활동 이력을 보존한다.
- 이미 첫 생활을 끝냈거나 도입이 비활성인 저장에는 초기 장면을 강제하지 않는다.
- 잘못된 장면 번호, 읽은 장면과 진행 중 장면의 충돌, 실제 장면에 없는 대사 위치는 저장 검증에서 거부한다.

검수 도구는 `VerifyTutorialNarrativeSave.Run`과 `VerifyTutorialStory.Run`이다. 저장 검수는 `Temp/TutorialNarrativeSlots`, 진행 검수는 `Temp/TutorialStoryVerification`을 사용하며 사용자 슬롯을 테스트하지 않는다. 런타임 보고서 경로는 `아트/리소스검토/tutorial-story-runtime.json`이다. 재실행 시 같은 보고서·스크린샷 경로가 갱신될 수 있으므로 파일 존재만으로 최신 변경의 통과를 판단하지 않는다. 긴 실행은 CLI `--timeout 150`과 스크립트 `--timeout_ms 120000`을 함께 사용한다.

최종 보고서는 `result: PASS`, `failure: null`, 검수 항목 8개다. 저장 이행·대사 검증·실제 디스크 왕복과 `VerifyCharacterBalance.Run`도 PASS했다. 진행 안내와 대사 화면을 검수하며 바닥 정리 설명의 줄 넘침을 수정했다. 구형 단계 검수의 첫 실패는 테스트 복제에서 null 귀환 기록을 빈 객체로 만든 오류였으며, 생산 저장 검증은 유지한 채 테스트의 null 보존을 고친 뒤 개별/통합 검수를 통과했다. 완료 후 Play Mode와 테스트 경로·선택 세션을 정리했다.

## 이전 구현과 검수 기록

처음에는 시작 체력 Max−1을 유지하고 두 사람이 잔해를 넘다 다쳤다는 대사와 휴식 필수 단계를 붙였다. 사용자가 그 인과관계를 거부해 **부상 설정·시작 피해·필수 휴식과 도입 체력 패널을 철회했다**. 아래는 철회 전 구현의 기술 검수 이력이며 현재 제작 방향이 아니다.

| v17→v18 저장 이행·유효성·디스크 왕복 | PASS | 기존 저장 보존 검증 이력. 이번 단계 3·4 연결은 별도 재검수 대상 |
