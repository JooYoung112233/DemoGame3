# 생활 물자 8종 적용 — 2026-09-25

사용자 요청: “만든 물품들 인게임에 넣어보자”. 기존 demo5에서 물품·수색·거래·제작·저장을 연결했다. 장비 장착/총기 개조 전체를 구현한 작업은 아니다.

## 실제 추가한 물건

| 물품 | 폐상가 수색 후보 | 현재 쓰임 |
|---|---|---|
| 연료통 | 복도 보관 상자 | 목재 대체 정수·조리, 교환 |
| 윤활유 | 오락기 정비판 | 공구 연구 후 못 가공, 교환 |
| 건전지 | 배전함 | 공구 연구 후 손전등 제작, 교환 |
| 담배 | 낡은 탁자 | 방문자 선호 교환품 |
| 커피 | 낡은 탁자 | 방문자 선호 교환품 |
| 소독 알코올 | 보관실 선반 | 붕대 대체 제작, 교환 |
| 전기 부품 | 배전함 | 공구 연구 후 손전등 제작, 교환 |
| 무기 부품 | 위험한 관리실 선반 | 가치 6의 교환품 |

새 물자는 수색 후보별 1개이며 기존 보상에 추가했다. 획득은 수색 방식·협력 보정과 기존 개별 확률을 따른다. 출발 자원에는 지급하지 않으며 첫 튜토리얼 물자 상자의 목재·고철·천은 바꾸지 않았다. 기존 완료 수색의 결과를 다시 뽑거나 이미 비운 상자를 채우지 않는다. 예전 캠페인에서도 방문자 거래로 구할 수 있다.

인벤토리 총 23종, 거래 대상 22종이다. 기존 탄약은 거래 대상으로 추가하지 않았다. 담배·커피·무기 부품은 현재 교환용이며 직접 먹기·회복·무기 개조 버튼은 없다. 기존 손전등은 계속 재사용 도구다.

## 새 제작법

| 제작법 | 재료 | 실제 결과 | 조건 |
|---|---|---|---|
| 연료 정수 | 미정수 물 2 + 연료 1 | 물 2 | 작업대 |
| 소독 붕대 | 천 1 + 소독 알코올 1 | 붕대 1 | 작업대 |
| 부품 손전등 | 전기 부품 1 + 건전지 1 | 손전등 1 | 공구 연구 |
| 윤활 못 | 고철 2 + 윤활유 1 | 못 3 | 공구 연구 |
| 연료 한 끼 | 기존 한 끼의 목재를 연료 1로 대체 | 기존 한 끼와 동일 | 조리대 |
| 연료 스튜 | 기존 스튜의 목재를 연료 1로 대체 | 기존 스튜와 동일 | 조리대 |

기존 제작법은 유지했다. 신규법은 관련 시설/연구 이전에 목록에서 숨기고 직접 등록도 차단한다. 제작법 ID와 실제 결과 물품 ID·수량을 분리해 물·붕대가 별도 아이템으로 중복 생성되지 않게 했다. 완료 기록은 실제 생산 물품과 수량을 표시한다. 부족한 재료 안내는 해금된 대체법도 찾으며 필요한 수량을 현재 재료로 만들 수 있는 방법을 우선 안내한다.

## 거래 UI와 가격

기존 종이·잉크 프레임 안에서 각 재고를 12칸 페이지로 표시한다. 이전/다음, 현재 쪽, 전체 품목 수가 보인다. 재고가 없는 물건은 숨기며 품절·빈 목록에서 선택과 페이지를 정리한다.

그림은 카드 중앙 76×62, 수량은 오른쪽 위, 이름은 아래 21px 한 줄로 분리했다. 긴 물품/제작법 이름은 짧게 다듬고 설명에 용도를 남겼다. 인벤토리 설명은 기존 26px·274×98 영역에 맞춰 두 줄로 정리했다.

방문 차수마다 담배/커피를 번갈아 선호한다. 해당 물건의 매입 가치는 +1이며 화면에 표시한다. 선호품 두 종류의 판매가는 기본 가치+1이므로 어느 방문에서도 매입가가 판매가보다 높지 않다. 방문일로 선호를 결정해 창을 다시 열거나 저장을 불러와도 바뀌지 않는다. 신규 방문 재고는 각 2개, 무기 부품은 1개다. 기존 방문 중 세이브를 이행할 때는 새 물건 재고를 0으로 보강해 그날 재고가 공짜로 늘어나지 않는다.

## 검수

최종 검수: 아래 검사 모두 통과(PASS). 검수 후 Play Mode를 종료하고 임시 캠페인 상태를 정리했다.

- `BuildEverydayGoods.Validate`: 그림·물품/재료/거래 목록·수색처·초기재고 0·ID 중복·튜토리얼 상자 보존 확인.
- `BuildEverydayTradeUI.Validate`: 인벤토리 23종, 거래 22종, 제작 24개·조리 6개의 행 이름 및 재료 이름 측정. 그림 중앙/수량/이름 비겹침 확인.
- `VerifyEverydayGoodsPersistence.Run`: 이전 저장 이행·잘못된 저장 거부·Temp 디스크 왕복·옛/새 제작법 실제 소모와 생산량·시설 조건·대체법 안내 확인.
- `VerifyEverydayGoodsPersistence.PlayMode`: 실제 제작·조리 화면의 버튼 listener로 예약/취소, 동시 작업 중 저장/재시작, 남은 시간과 한 번만 완료됨을 확인. 이 검사는 물리 포인터 검사를 주장하지 않는다.
- `VerifyEverydayTrade.Run`: 실제 Raycast와 클릭으로 전 품목 페이지 접근, 신규 8종 구매, 취소/중복 확정/품절/빈 목록/역거래/저장 복원 확인. 1920×1080·1280×800 캡처.
- `VerifyEverydayGoodsFlow.Run`: 실제 확률 계산과 재현 가능한 수색 결과로 담배·커피 획득→모두 담기→대원 전달→귀환→창고 보관, 모든 새 물건 상세와 제작·조리 UI를 두 해상도에서 확인한다. 인벤토리 전체 그림 검수 부분만 재고와 시설을 별도로 준비한 테스트 캠페인이다.

검수 기록: `아트/리소스검토/everyday-labels-static.json`, `everyday-trade-runtime.json`, `everyday-goods-flow.json`. 최종 결과는 각 JSON의 result와 실제 Unity 화면을 확인한다. 새 품목의 장기 캠페인 수급 밸런스를 완성했다고 해석하지 않는다.

## 재적용과 남은 범위

기존 inventory/loot 빌더를 다시 실행해야 하는 경우 최신 데이터가 지워질 수 있다. 최신 빌더 순서는 `BuildEverydayGoods.Run` → `BuildEverydayRecipes.Run` → `BuildEverydayTradeUI.Run`. 프리팹 YAML을 직접 수정하지 않는다.

무기 장착·개조, 발전기/현장 전원 이벤트, 기호품 생활 사건, 다른 탐험지 배치는 아직 도입안의 후속 범위다. 기존 가방 ‘재료 5개당 1칸’ 승인사항도 이번 물품 등록에서 변경하지 않았으며 현재는 종류당 한 칸 규칙이다.
