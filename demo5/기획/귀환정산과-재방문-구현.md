# 귀환 정산과 재방문

2026-09-23. 비전투 우선 제작 2단계와 재방문 연결.

## 플레이 흐름

1. 출발 때 원정대의 체력과 아이템별 휴대 수량을 기록한다.
2. 귀환하면 목적지·왕복 및 현장 경과 시간·대원별 체력·휴대품의 전후 수량을 표시한다.
3. `돌아가기`는 가방을 유지한다. `가방별 정리`는 첫 원정대원의 개인 가방을 연다. `휴대품 모두 보관`은 원정대 전원의 현재 가방 물품을 공용 창고로 옮긴다. 출발 때 챙긴 도구와 소모품도 포함된다고 안내한다.
4. 정착지 `기록`으로 최근 원정 결과를 다시 볼 수 있다. 결과 숫자는 귀환 시점 기록이며 이후 창고 정리에 따라 바뀌지 않는다. 보관 버튼과 안내는 현재 가방 상태를 반영한다.

물자는 수색에서 실제 가져올 때 이미 가방에 들어온다. 귀환 화면은 보상을 새로 생성하지 않는다. 보급품/탄약은 기존 총량에서 개인 소유분을 구분하는 구조이므로 입고 때 캠페인 총량을 다시 늘리지 않는다. 재료는 가방에서 줄이고 공용 재료에 더한다.

수량 변화는 **획득·사용·현장에 두기 합산**이다. 순증가량을 총 획득량이라고 표시하지 않는다. 획득/소비의 개별 사건 장부는 아직 없다.

## 재방문

기존 수색 상태와 남은 발견물은 원래 같은 세션 동안 유지되었지만 복도 방문/사물 조사 표시는 재출발 때 초기화되고 있었다. 이를 맞춰 방문 지식도 유지한다. 현재 방은 입구인 오락실로, 원정 턴/소음은 0으로 시작한다. 완료 수색은 재추첨되지 않는다.

현재 장소는 폐상가 한 곳이다. 장소별 ID를 분리한 다중 장소 저장과 실행 종료 후 복원은 다음 단계다. 이번 구현으로 디스크 저장까지 된 것은 아니다.

## 검증

- `VerifyExpeditionReturn.Preview`: 획득·탄약 사용·체력 감소를 결정적인 런타임 데이터로 구성하고 실제 귀환 버튼을 클릭한다. 확률 드롭/전투를 검증했다는 뜻은 아니다.
- `Flow`: 가방 화면 연결, 기록 재열람, 전체 입고, 재료 정확한 증가, 보급/탄약 중복 증가 방지, 재열람의 시간/보상 중복 방지, 빈손 두 번째 귀환 통과.
- `Revisit`: 실제 복도 왕복, 부분 수색 후 귀환/재방문, 방문 기록과 수색 진척 유지, 완료 후 재추첨 방지, 남긴 물건의 재방문 보존 통과.
- 실제 화면: `Assets/Screenshots/Settlement/return-summary.png`.

남은 순서: 도구가 필요한 수색 대상과 연결 방 확장, 다음 탐험 목적, 저장/복원. 전투 개선은 계속 보류한다.

## 가독성 개선 — 대원 카드와 물자 목록

사용자의 글 위주 구성 지적을 반영했다. 좌측은 초상·체력 숫자·막대·변화 표시 카드, 우측은 원정대 전체 물자를 합산한 아이콘 표다. 출발/귀환/증감의 열 기준선을 통일하고 증감은 부호와 색을 함께 사용한다. 경과 시간은 상단 별도 종이 표시로 분리했다.

`ReturnMemberRow.prefab`, `ReturnItemRow.prefab`을 개별 편집할 수 있으며 두 목록은 각각 독립 스크롤한다. 증가·감소·변화 없음은 색만으로 구분하지 않는다. 가방 정리 뒤에도 귀환 시점의 카드·수량을 유지한다.

`VerifyExpeditionReturn.Layout`로 2명/4종 표시, 초상과 체력 숫자, 수량 열 정렬과 글자 잘림을 검증했고 `Flow`의 가방 정리/기록 재열람/중복 방지 검증도 다시 통과했다. 실제 화면은 `Assets/Screenshots/Settlement/return-cards.png`다.
