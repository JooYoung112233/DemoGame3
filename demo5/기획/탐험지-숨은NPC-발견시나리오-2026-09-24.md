# 이웃 아닌 — 탐험지에 숨어 있는 NPC

사용자 요청: 탐험지에 숨어 있는 NPC도 만든다. 앞서 작성한 NPC와 탐험 사건에 **발견 과정과 첫 대화**를 추가한다.

상태: 플레이 가능한 흐름으로 구체화한 시나리오 초안. NPC 배치·단서 그림·행동 슬롯·진행 저장은 아직 Unity에 구현하지 않았다. 아래 은신처는 현재 그림에 이미 완성되어 있는 구조가 아니라 기존 방에 추가할 상호작용 지점의 제안이다. 탐험 담당의 코드와 프리팹은 변경하지 않는다.

## 발견의 기본 흐름

**생활 흔적을 본다 → 조사할 대원을 정한다 → 사람이 있다는 반응을 듣는다 → 거리를 정하고 대화한다 → 이름을 알게 된다 → 재회할 이유를 남긴다.**

- 입장 직후 NPC 말·이름표·느낌표를 띄우지 않는다. 처음 보이는 것은 사물과 흔적이다.
- 작은 픽셀을 우연히 누르는 방식은 피한다. 해당 영역에 접근하거나 포인터를 올리면 기존 사물과 같은 하이라이트와 중립적인 이름이 나타난다. 조사 전 이름 예: ‘밀린 오락기’, ‘선반 뒤 흔적’, ‘가려진 통로’.
- 소리만으로 찾게 하지 않는다. 바닥 자국·천의 움직임·작은 불빛 등 눈으로도 확인할 단서를 함께 둔다.
- 관찰에는 실제 행동 1칸과 턴을 사용하고 대화 읽기는 무료다. 정확한 소음은 구현 시 기존 행동 규칙과 맞춘다. ‘조용히 조사’가 전원 숨죽이기와 같다고 표시하지 않는다.
- 무작위 성공률로 사람의 존재를 지우지 않는다. 발견 조건을 충족하면 흔적은 반드시 보인다. 능력 있는 동료는 해석을 더해도 필수 열쇠가 되지는 않는다.
- 새 게임의 첫 수색 도입을 방해하지 않는다. 두 번째 방문의 장소 판 안내를 마친 이후부터 후보가 된다.
- 초반 폐상가의 새 인물 첫 만남은 한 방문에 최대 1건을 제안한다. 다음 인물은 다른 방문으로 미룬다. 모든 은신처에 NPC가 꽉 차 있는 모습은 피한다.

## 1. 오락기 뒤, 장도윤

사건 ID `mall.hidden_doyun`. 인물 ID `npc.jang_doyun`.

**장소:** 오락실 끝의 벽 쪽 기계 뒤. 사람이 웅크릴 수 있는 정비 틈으로 제안한다. 기존 오락기 수색과 구분할 단서 지점이 필요하다.

**왜 숨었나:** 상가 안쪽에서 돌아오다 ‘그것’의 기척을 피해 들어왔다. 낯선 원정대가 보이자 공구를 빼앗길까 봐 더 숨었다. 부상자를 흉내 내는 괴물 반전으로 쓰지 않는다.

### 발견 장면

1. 바닥에는 오락기 무게로 생긴 오래된 자국이 있다. 그 옆에 먼지가 덜 쌓인 짧은 밀림 자국이 한 줄 더 있다.
2. 조사하면 기계 아래로 말아 넣은 작업 장갑이 보인다. 안쪽에서 열쇠가 한 번 부딪히고 곧 멎는다.
3. 플레이어에게 ‘기계 뒤에 말을 건다 / 조금 떨어져 기다린다 / 지금은 지나간다’를 제시한다. 기계를 억지로 당기는 선택을 기본 상호작용으로 두지 않는다.

**말을 건넸을 때**

`?`: “기계는 밀지 마요.”

`서술`: 장갑이 안쪽으로 조금 당겨졌다.

선택: ‘거기서 나올 필요 없어요’ / ‘밖으로 나갈 길을 찾고 있어요’ / 대화 마무리.

`?`: “입구로 온 거죠? 복도 쪽 말고.”

`서술`: 어디로 들어왔는지 묻는 말이다. 현재 복도가 안전하다고 확인해 주는 정보는 아니다.

**이름 공개 장면**

한발 물러나자 그가 기계 뒤에서 몸을 편다. 가방 끈에 걸린 명찰이 돌아간다.

`서술`: 명찰에는 ‘장도윤’이라고 적혀 있다.

이 서술 확인 후 다음 대사부터 `장도윤` 표시.

`장도윤`: “저도 나가려던 참이에요. 두고 온 게 있어서.”

### 선택 결과

| 선택 | 즉시 결과 | 다음 사건 |
|---|---|---|
| 거리를 두고 대화 | 모습을 드러내기 전에도 짧게 응답한다. 공구와 짐을 두고 왔다는 사실을 안다. | 다음 방문의 ‘문을 잡고 있는 사람’에서 먼저 알아본다. |
| 입구까지 가는 길을 알려준다 | 이미 원정대가 확인한 경로만 이야기한다. 즉시 이동·구출 완료로 처리하지 않는다. | 철수 이후 밖에서 재회하는 분기 후보. |
| 지금은 지나간다 | 발견 이력과 은신처는 남는다. 다시 접근 가능하다. | 나중에 대화해도 처음부터 장갑 조사를 반복하지 않는다. |

`mall.held-door`를 먼저 겪었다면 새로 모르는 사람처럼 자기소개하지 않는다. ‘또 숨어 있는 이유’를 묻는 짧은 재회 장면으로 바꾸고 이름도 유지한다. 두 사건의 보상을 각각 구조 보상으로 중복 지급하지 않는다.

## 2. 보관실 선반 뒤, 배준

사건 ID `mall.hidden_jun`. 인물 ID `npc.bae_jun`.

**장소:** 보관실 끝 선반과 벽 사이. 사진 봉투를 눌러둔 얇은 판과 천 가림을 추가할 후보 위치다. 별도의 새 방을 이미 발견한 것처럼 취급하지 않는다.

**왜 숨었나:** 맞은편 점포에서 챙긴 사진을 말리고 있다. 이곳 물자를 훔치는 사람으로 오해받은 적이 있어 낯선 소리에 모습을 감춘다. 사진이 든 상자를 버리고 떠나기는 싫다.

### 발견 장면

1. 선반 밑 먼지에 무릎과 신발이 닿은 자국이 있다. 벽 틈에 끼운 사진 한 장만 깨끗하다.
2. 조사하면 안쪽의 작은 불빛이 가려진다. 천 뒤에서 “그건 밟지 마세요”라는 말이 들린다.
3. ‘사진을 건드리지 않고 말을 건다 / 사진을 제자리에 세워둔다 / 물러난다’를 제시한다. 실제 가방에 사진 아이템을 자동 지급하지 않는다.

**첫 대화**

`?`: “물건 찾으러 왔으면 저쪽이에요.”

`서술`: 천 뒤의 손이 물자 선반 쪽을 가리킨다.

선택: ‘이 사진은 누구 거예요?’ / ‘당신은 여기서 지내요?’ / ‘건드리지 않을게요’.

`?`: “누구 건지 아는 건 따로 놨어요. 저건 아직 몰라서.”

사진을 제자리에 두고 대화를 이어가면:

`?`: “배준이에요. 사진관에서 일했어요. 잠깐이지만.”

확인 후 `배준`으로 전환.

### 선택 결과

- **사진을 건드리지 않는다:** 다음 만남에는 먼저 가림천을 걷는다. 이 반응을 숨은 호감도 보너스 대신 구체적인 사건 기억으로 처리한다.
- **짐을 옮기는 일을 제안한다:** 사진을 옮길 장소와 수용 공간을 먼저 협의한다. ‘도움 제안’만으로 NPC 영입·창고 확장·가방 슬롯 점유를 발생시키지 않는다.
- **지금은 떠난다:** 첫 발견을 기록한다. 다음 방문에 말라 있는 사진으로 시간이 흘렀음을 보여준다. 지나갔다고 죽거나 물건을 전부 잃게 하지 않는다.

백소담이 실제 동행했다면 사진 뒤의 글과 앞면이 다른 시기에 작성되었다는 짧은 관찰을 추가할 수 있다. 백소담이 없어도 발견·대화·후속 진행은 가능하다.

**후속:** ‘사진을 가져갈 이유’ 사건. 실용 물자를 싣는 가방과 보관할 기억 사이의 선택으로 이어가되, 실제 이야기용 운반물 시스템이 준비되기 전에는 슬롯을 임의로 차감하지 않는다.

## 3. 복도 가림막 뒤, 남기호

사건 ID `mall.hidden_giho`. 인물 ID `npc.nam_giho`.

**장소:** 보관실이 보이는 복도 쪽 가림막/폐점 점포 앞. 관리실과 분리한 위치다. ‘그것’이 사는 관리실 안에 사람을 이유 없이 함께 숨겨 두지 않는다.

**왜 숨었나:** 누가 물자를 가져가는지 확인하고 있다. 도움을 기다리는 사람도, 즉시 공격할 적도 아니다. 원정대가 선반을 어떻게 다루는지 본 뒤 말을 걸 생각이다.

### 발견 장면

1. 가림막 밑에 놓인 작은 거울 조각이 보관실 문을 향한다. 바닥에는 최근 연필을 깎은 부스러기가 있다.
2. 조사하면 가림막 뒤에서 종이를 접는 소리가 난다. 시선을 느낀 순간 거울이 조금 돌아간다.
3. ‘누가 있는지 묻는다 / 물자 기록을 보여 주겠다고 한다 / 그냥 지나간다’를 제시한다. 두 번째 선택은 실제로 물자를 회수·남긴 기록이 있을 때만 표시한다.

**첫 대화**

`?`: “그 선반에서 몇 개 가져왔어요?”

선택: 수량을 확인해 준다 / 왜 보고 있었는지 묻는다 / 대화를 끝낸다.

`?`: “사라진 뒤에 세면 늦으니까요.”

이름을 묻거나 원장을 함께 확인하면:

`?`: “남기호. 저쪽 물건 정리하던 사람이에요.”

확인 후 `남기호` 표시. ‘관리하던 사람’이라는 주장을 물품의 정당한 소유권으로 확정하지 않는다.

### 선택 결과

- 실제 수량을 맞춰 보면 ‘다음 사람 몫’ 사건의 남긴 사람과 관리한 사람이 다르다는 단서가 나온다.
- 감시가 싫다고 말하면 거리를 두고 정산만 하는 관계가 가능하다. 대화 종료를 전투 개시로 바꾸지 않는다.
- 지나가면 관찰한 거울과 메모 흔적을 기록한다. 나중에 정식으로 마주쳤을 때 같은 원장·말투로 연결한다.
- `mall.next-person`이나 기호의 다른 사건에서 이미 만났으면 기존 선택에 맞는 재회 대사를 사용한다.

## 장소 판과 충돌하지 않는 처리

- NPC의 기척은 ‘생활 흔적’이다. 기존 적 위치·‘다음 턴 들어옴’·귀 대기 확정 정보의 표시를 대체하지 않는다.
- NPC 관찰 턴에도 기존 장소 시계와 적 이동은 진행된다. 수색을 겸하거나 같은 턴을 두 번 지불하지 않는다.
- 조우가 발생하면 실제 조우가 우선한다. 대화 진행 위치를 저장하고 안전한 시점에 이어 읽는다. 사건만 따로 적 움직임을 멈추지 않는다.
- NPC가 알려주는 안전 정보는 언제 직접 확인했는지 함께 말한다. 과거 목격을 현재 확정 안전으로 UI에 표시하지 않는다.
- 화면 가장자리·다른 가구 뒤에 완전히 가려진 작은 클릭 영역만으로 발견하게 하지 않는다. 포인터 단서와 읽을 수 있는 조사 문구가 필요하다.
- 이름 공개 전에는 목록·저장 설명·기록 제목에도 실명을 미리 노출하지 않는다. 제목은 ‘오락기 뒤의 사람’처럼 관찰된 정보만 쓴다.

## 진행 상태와 재방문

공통 상태 제안: 미발견 → 흔적 발견 → 사람 확인 → 대화 시작 → 이름 인지 → 후속 조건 충족.

별도로 보류/대화 중단/떠남/재회 위치를 저장한다. 발견 여부와 이름 인지를 같은 bool로 묶지 않는다. 장도윤을 먼저 다른 사건에서 만났을 때의 역순도 처리한다.

세 인물을 매 방문 무작위로 다시 배치하지 않는다. 첫 배치와 이후 이동은 이력으로 보존한다. 떠난 경우 비어 있는 자리와 남긴 흔적을 보여 주고, 이전 대화가 재생되어 물품이나 보상을 또 주지 않게 한다.

초기 연결 제안: 장도윤 1건으로 발견 → 대화 → 귀환 → 재회 흐름을 검증한 뒤 배준·기호를 추가한다. 이는 세 시나리오의 인게임 구현 완료를 뜻하지 않는다.
